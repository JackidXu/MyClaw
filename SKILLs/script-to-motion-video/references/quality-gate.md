# 出片前质量门禁（强制 · 跨风格适用）

本门禁是技能的**硬卡**，高于一切风格变体和模板。**无论选哪套皮肤（浅色 / 深色 / 霓虹 / 奶油…），以下指标必须逐条达标，任何一项不达标 → 禁止跑 `render.js`，先回去补满。**

门禁的设计目标：把"iWOD 那次为什么好"翻译成**可计数、不可偷懒**的指标，让换一次会话、换一个 AI 工具都不会掉回"只填骨架"的旧模版。

---

## 一、结构丰富度门禁（每条视频必过）

| # | 指标 | 下限 | 怎么数 | 不达标后果 |
|---|---|---|---|---|
| G1 | 设计系统 5 项 | 全齐 | `:root` 含 调色板 / ≥4 级字号 / 卡片系统 / 网格 / 纹理 | 退回旧模板 |
| G2 | 景深 | ≥4 层/场景 | L0 底板 + L1 纹理 + L2 实拍窗/内容卡 + L3 前景叠层 | 平面化，禁渲染 |
| G3 | 具象 UI mockup | ≥1 个/场景 | 手机界面/数据面板/流程图/文档卡/设备三连屏（HTML+CSS 搭，非截图） | PPT 感，禁渲染 |
| G4 | b-roll 实拍窗 | 实拍窗数 ÷ 场景数 ≥ 0.5（至少一半场景有真实 b-roll 窗口；iWOD 范例恰为 5/10=50%，即达标下限） | 每场景含 `<video>` 圆角窗口 或 已标 `bg_type:image`（注明搜过的关键词）；实拍窗数 ÷ 场景数 ≥0.5 | 0 条 b-roll 直接违规 |
| G5 | 动效组/节拍 | ≥3 组 | 每节拍 A主元素+B子元素级联+C辅助元素，入场后 D 持续动效 | 禁只 1 组 fade |
| G6 | 排版字号级 | ≥3 级/画面 | 主标题+导语+标签同框，级差 ≥1.3 倍 | 整屏 1 级字号禁 |
| G7 | 每场景图形数 | ≥5 | `graphic_plan.graphic_count` ≥5 且不为 0 | 画面单调 |
| G8 | 每场景文字数 | ≥5 | `graphic_plan.text_count` ≥5 且不为 0 | 失衡 |
| G9 | 紧凑化 | 必须跑 | 存在 tighten 记录，场景间隔 ≤0.65s，无 ≥1.0s 静默 | 判定未完成 |
| G10 | 时长三处同步 | 一致 | `data-duration` 累加 = JS `DUR` = `project.json.duration` = 音频实际时长 | 音画漂移 |

> **G7/G8 是规划阶段关卡**：`scene-plan.json` 没有 `graphic_plan`、或某场景 `graphic_count<5` / `text_count<5`，**禁止进入阶段 3 构建**。

## 二、场景密度门禁（已调为 6–8）

| # | 指标 | 口径 |
|---|---|---|
| G11 | 每 60 秒场景数 | **6–8 个**（平均 7.5–10 秒/场景）；少于 6 偏疏、多于 8 偏碎 |
| G12 | 不足 1 分钟 | `场景数 ≈ 时长秒 ÷ 9`，下限 3 个（极短 <20s 可 2–3 个） |

示例：30s → 3–4 个场景；45s → 5–6 个；80s → 8–10 个；120s → 12–16 个。

---

## 三、反模式黑名单（出现任一 = 退回旧模板，禁渲染）

1. `.bg img` 全屏背景图 + 多层 `rgba(0,0,0,0.6+)` 暗化 + vignette（画面发脏发灰）
2. 深色底 + `opacity:0.3-0.4` 背景图，可读全靠暗化层
3. 直接复制 `composition-template.html` 的 CSS 类名、没自建 `:root`
4. 把 `style-variants.md` 的色板变量当 `<style>` 直接用，没做 5 项设计决策
5. 全条视频 0 条 b-roll（跳过视频搜索直接用 CSS 渐变/静态图）

> **关键认知**：`style-variants.md` 37 种风格的「深色全盘 + 压暗类（scrim/dim/charge）」常被误用成上面第 1/2 条旧模版。换风格**只通过 `style-skins/` 皮肤包换 `:root` token + 底板光学**，绝不可用 `style-variants.md` 的全屏压暗类当 composition 底板。

---

## 四、门禁执行流程（阶段 5 渲染前必跑）

1. 逐场景过 G1–G8（可对照 `examples/iwod-light/` 范例的量级）。
2. 过 G9 紧凑化（渲染后必跑 `tighten-guide.md`）。
3. 过 G10 时长三处一致性。
4. 过 G11/G12 密度。
5. 扫反模式黑名单。
6. 跑 `checklist.md` 自检。
7. **以上全绿才允许 `node render.js`**。任何一项红 → 回去补，不补不许渲染。

---

## 五、风格与质量解耦原则

- **结构（决定质量）永远不变**：`composition-template.html` 脚手架（`.vframe/.card/.kicker/.h1` + 每场景 UI mockup + b-roll 窗口 + 逐元素动效 + 4 层景深 + 紧凑化）。
- **皮肤（决定观感）只换 token**：`style-skins/` 里的 `:root` 语义色 + `#paper`/`#grain` 底板光学 + 可选的 `.card` 表面/辉光。
- 任何皮肤都过本门禁。想加新皮肤：复制一个 `style-skins/` 子目录，只改 token 与底板，**不要**动结构，也不要引旧模版压暗类。
