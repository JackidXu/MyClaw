# 场景设计指南（文案 → 视觉映射）

收到一段视频文案后，怎么把每句文案变成画面上的视觉元素？本文档提供从文案到画面的完整思考流程。

---

## 一、文案 → 场景切分

### 该怎么做

1. 按语义把文案切分为场景（每句一个场景，或相近语义合并）
2. 根据原文案估算视频时长，通常时长每 60 秒切分为 6-8 个场景，把文案句归组：钩子 / 第一步 / 第二步 / … / 价值段 / CTA
   **密度基准：每 60 秒 6-8 个场景（平均 7.5-10 秒/场景）**——场景太长观众感知为幻灯片、太碎又显仓促，6-8 是「视频感」与「信息消化」的平衡点；不足 1 分钟按 `场景数 ≈ 时长秒 ÷ 9` 比例缩减（下限 3 个）
3. **为每个场景规划具象 UI mockup**——不是抽象图形。每个场景至少 1 个具体可辨认的产品界面元素（手机界面/数据面板/流程图/文档卡片/设备三连屏），在 `graphic_plan` 里新增 `ui_mockup` 字段描述具体界面类型和内容
3. 每个场景记录：id、标题、旁白文字、关键词、需要的视觉元素

### 切分原则

每个场景讲一个完整的意思。

每 60 秒**场景数量 6-8 个、每场景时长 7.5-10 秒**——这是硬性基准，偏离时要明确理由。

**新基准：每 60 秒 6-8 个场景、每场景 7.5-10 秒**——紧凑切换是「视频感」的第一要素。不足 1 分钟按 `场景数 ≈ 时长秒 ÷ 9` 比例缩减（下限 3 个，极短 <20s 可 2-3 个）。

## 二、从文案到画面

每句文案变成画面上的视觉元素。整个思考流程是连贯的：理解文案在说什么 → 找能讲这个故事的视觉元素 → 用构图表达概念 → 选动效让元素入场。

### 第一步：理解文案在传达什么

读每段文案时，先判断：

1. **这段文案的核心信息是什么？**（一句话概括）
2. **这个信息属于哪种类型？**（数据 / 对比 / 概念 / 关系 / 案例 / 转化 / 结论 / 情绪 / …，不限于这些）
3. **信息有几个层次？**（核心信息 + 辅助信息）

### 第二步：找能讲这个文案的视觉元素（强制）

**这是动效视频的核心环节，不是可选项。** 基于第一步判断的信息类型，必须为该场景推导出具体的图形元素以及文字元素——选最贴切的几个，把文案中的重点关键词进行提取，使用文字元素和图形元素进行表达。

**动笔写任何元素之前，必须先答完这三句话（缺一不可）：**

1. 这段文案在讲什么概念 / 信息类型？（数据 / 对比 / 概念 / 关系 / 案例 / 转化 / 结论 / 情绪……）
2. **用什么图形和文案最能讲这个故事？**（注意是"用什么图形"，不是"要不要图形"——默认答案永远是"要"）
3. 这个图形和文案放哪、为什么在这？（每个图形和文案都要能回答"它为什么在这"）

**思考方向**（根据文案语义判断）：

- 这段信息最关键的是什么？（用大元素 / 主图形突出）
- 还需要什么辅助图形和文案进行烘托？
- 什么元素不该出现？（跟本场景无关的坚决不放）

**自检锚点：** 若一个场景的元素清一色是文字元素或图形元素，即为违规，必须补元素后再继续。

元素就是 HTML + CSS + GSAP 的组合，可用 `composition-template.html` 的现成类，更要**根据文案语义自己写 CSS + inline SVG 创作**需要的图形（见下方「怎么创作图形」）。

### 第三步：用构图表达概念

每个场景的构图要能讲该场景文案的概念。不是随意摆元素，而是用画面结构表达文案含义。

**思考方向**：

1. **这段文案的核心概念是什么？**（对比？包含？流程？堆叠？强调？分散？…）
2. **哪种构图方式能表达这个概念？**（可能不止一种，选最直观的）
3. **画面中有几个主角，主元素放哪？辅助元素放哪？**（主元素占大区域，辅助元素烘托）
4. **画面结构是否能让观众一眼看出概念？**（如果不能，换构图方式）
5. **各元素是否都能回答"它为什么在这"？**（应该在哪个位置最合理）

具体布局规则（均匀分布、安全边距、防碰撞）见 `layout-rules.md`。

### 第四步：选动效让元素入场

每个元素选什么入场动效——从 `motion-patterns.md` 的基础原语里选，根据元素在画面里的角色和文案节奏决定。

**硬原则**：区域越大内容越多——大区域放核心元素（大字 / 数据 / 引言块），小区域放装饰元素（图标 / 光晕）。元素的视觉权重（大小 / 位置 / 动效强度）要跟它在文案里的重要性匹配。

动效选择没有标准答案，但要跟元素的性质匹配——冲击型信息用冲击型动效，铺垫型信息用平静型动效，具体选哪个由你根据文案节奏和情绪决定。

## 三、元素与画面

**每场景 5–6 个非文字图形元素 + 5–8 个文字元素（硬下限：图形不可低于 5、文字不可低于 5），均匀分布填满画面**（见 `layout-rules.md` 的均匀分布原则）。这是强制规则——两类都不可为 0，低于下限即视为画面单调 / 失衡、违规。**图形与文字必须同时出现、比例协调**：只有图形没有文字、或只有文字没有图形，都等于没把文案讲清楚（图形负责"看见概念"、文字负责"读清论点"，缺一不可）。图形 + 文字**总元素密度建议 10–14 个（两类合计），多于 14 个视觉过载。**

**怎么创作图形：** 每个场景的图形必须**根据文案语义现场创作** inline SVG / CSS 图形。库里没有的隐喻，就按文意自己画。**禁止因为库里没有就跳过图形、退回纯文字容器。**

### 图形精致度通用标准（强制）

图形的目标是"看起来像精心设计的资产"，不是"有就行"。精致与否**不取决于图形类型**——语义图标、数据图表、人形剪影、隐喻图形，每一种都要达到同样的精致基准。

**不要靠"禁止某类画法"（比如禁止单线条）来约束**：你能列举的画法永远列不完，列一种漏一种，下次照样出另一种糙图形。正确做法是把下面这套通用标准作为默认质量线，让任何类型的图形在创作这一步就做到位。

**精致四要素（任意类型通用）：**

1. **有光感——绝不平涂纯色**：填充一律用渐变（`linearGradient` / `radialGradient`），让元素有明暗过渡、像被光打过，而不是一张平贴纸。`fill="var(--teal-bright)"` 这种纯色实心、或 `fill="none" stroke="currentColor"` 这种单线描边，单独出现即不达标准。
2. **有层次——加投影 / 发光**：用 `filter: drop-shadow()` 或 `box-shadow` 给元素加一层柔和投影 / 光晕，让它从背景浮起来，而不是贴平在画面上。
3. **有细节——不是孤形 / 单线**：精致图形带"被设计过"的细节。放大镜不是圆 + 线两条 path，而是玻璃高光 + 手柄渐变 + 反光；柱状图不是纯色矩形，而是渐变 + 圆角顶 + 顶面高光 + 底部投影。细节是"设计资产"与"占位草图"的分水岭。
4. **有质感——渲染克制到位**：圆角端点（`stroke-linecap:round`）、统一线宽、平滑抗锯齿边缘；同一场景内的图形共享同一套视觉语言（相同描边粗细、相同阴影柔和度、相同渐变方向），画面才统一不杂乱。

**通用提升公式（每个图形落盘前过一遍）：**

1. 纯色填充 → 换成渐变（至少两档明暗）
2. 加一层投影 / 发光（`drop-shadow` 或 `box-shadow`），让元素离背景浮起
3. 加一处高光 / 内描边 / 小细节元件，制造"被打磨过"的观感
4. 圆角 + 统一线宽 + 圆头端点（别留尖角毛刺）
5. 用复合形状组合成有含义的结构，而非单个基本形孤零零摆着

**自检锚点（生成每个图形前问一句）：** 这个图形看起来像**精心设计的资产**（有光、有影、有细节），还是像**占位草图**（平涂、单线、无影）？只要像后者，就用上面的公式把它拉到前者再落盘——不要在渲染出来后才发现糙。

**跨类型示范（标准对一切类型通用，而非只针对某一类）：**

- 语义图标（如对话气泡）——糙版：单线条 `path`（`fill="none" stroke`）；精版：渐变填充 + `drop-shadow` + 高光点 + 圆角端点
- 数据柱状图——糙版：纯色 `rect` 加 `opacity`；精版：垂直渐变条 + 圆角顶 + 顶面高光 + 底部投影 + 基线
- 人形 / 隐喻图形——糙版：描边空心；精版：渐变实体 + 边缘 rim light（高光描边）+ 内部层次

> 具体 SVG 写法见 `composition-template.html` 的 `element-gallery`（已升级为精致范式）。复制后按本场景文意替换路径与配色，并保留渐变 + 投影 + 细节；同一页面内多个图形时，渐变 / 滤镜的 `id` 要改成各自唯一名，避免冲突。

**逐场景核验（强制 `graphic_plan`）：** 规划阶段就在 `scene-plan.json` 为每个场景产出完整的 `graphic_plan`——含 `graphic_count`（≥5）+ `graphic_elements` 数组（每项 `role`/`semantic`/`snippet`），以及 `text_count`（≥5）+ `text_elements` 数组（每项 `role`/`semantic`/`content`）。**`graphic_plan` 是强制字段——缺它、或某场景 graphic_count<5、或 text_count<5，禁止进入 composition 构建**，因为图形片段与文字容器都要在构建阶段原样落进 HTML，没有就既无图形可搬、也无文字可填。渲染前再逐场景核对实际画面图形数 = `graphic_plan.graphic_count`、文字元素数 = `graphic_plan.text_count`，且每个 snippet / content 都已落地

### 模板现成样式类

模板（`composition-template.html`）自带以下现成 CSS 类，可直接用，省写 CSS：

| CSS 类名         | 用途              |
| -------------- | --------------- |
| `.kicker`      | 场景顶部小标题，提示当前讲什么 |
| `.dchip`       | 数字 + 标签，展示统计数据  |
| `.quote-block` | 重要结论 / 案例描述     |
| `.ico-svg`     | 装饰图标 + 语义图标     |
| `.glow-orb`    | 填充留白 + 烘托氛围     |
| `.sil`         | 角色代表            |

**这些只是省事的现成样式，不是元素类型清单**——你可以用这些类，也可以自己写 CSS 创建任何你需要的元素类型。

## 四、场景过渡

场景之间的过渡，从 `motion-transitions.md` 的 13 种转场里选——根据场景之间的关系选合适的转场，没有默认值，每个过渡由你根据前后场景的关系判断。

### 验证过的规则

**场景时间轴必须锚定「切割时长」**：`gen_tts.py` 把整段录音按估算边界切成各 `segXX.mp3`，每段实际时长 = 切割长度、最后一段切到真实结尾，所以时间轴由**切割时长**推导，不手写、不二次估算（估算只用于定切割点，落盘后一律以真实切割时长为准）——

- 场景 N 的 `data-start` = 前 N-1 段切割时长之和
- 场景 N 的 `data-duration` = 第 N 段切割时长
- 视频总时长 = 各段切割时长之和 ≡ 整条音频真实时长（过渡由画面重叠实现，不额外占时）

由此推得转场节奏（画面转场与旁白自然咬合，不抢拍、不缩短）：

1. 旧场景在其音频尾音**结束时刻**开始退场（opacity / scale / y 变化），**不提前、不抢拍**
2. 新场景首元素在**切割边界（即旧场景结束时刻）**&#x81EA;然入场，与旧场景退场交叉溶解（cross-dissolve）
3. **最后一个场景不退场**（视频结尾停留在终画面）

> 说明：整段录音切割后各段首尾相接。旧场景播满尾音再退、新场景在边界接入，转场更从容自然。

```javascript
// 假设场景1切割时长 6.5s、场景2切割时长 5.8s
// 场景1 data-start=0, data-duration=6.5；场景2 data-start=6.5, data-duration=5.8
// 场景1在 6.5s（音频尾音结束时刻，非提前）开始退场，场景2首元素在 6.5s（切割边界）入场，自然交叉溶解
tl.to("#s1 .clip", { y: -60, opacity: 0, duration: 0.4, ease: "power2.in" }, 6.5);
tl.fromTo("#s2 .clip", { y: 60, opacity: 0 }, { y: 0, opacity: 1, duration: 0.5 }, 6.5);
```

### 思考方向

选转场时想：前后两个场景是什么关系？

- 连续叙述（A→B→C）→ 平滑过渡类转场
- 强对比（好→坏 / 旧→新）→ 强调变化类转场
- 时空转换（现在→过去）→ 回忆感转场
- 总结→CTA → 引向行动类转场

具体选哪个转场看 `motion-transitions.md` 的 13 种转场和它们的能量级别（Calm / Medium / High），根据场景情绪强度匹配。
