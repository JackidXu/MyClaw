# 声音

## 文案就是口播原话

本技能不做配音、不生成人声。**口播视频里的原声就是成片唯一的人声轨**，`script.json` 的 `lines` 是逐字转写出来的原话，不是写好的稿子。

- 先转写，再和用户核对每个字：数字人常读错字，语音识别也会听错；错字不修，后面的逐字对齐、字幕、卡点会一起错。
- 一句一个 `id`，`text` 写她实际说的那一句，字幕直接用这份。
- 插当事人原声的地方，口播里要有铺垫（"难怪某某总爱说这句："），剪口按波形定，见 `sourcing.md` 的「当事人原声」。

## 时间线：从口播原声逐字对齐

```bash
python scripts/host_timeline.py 口播.mp4 film/script.json film/timeline.json
```

用 faster-whisper 逐词识别口播原片，再逐字对齐到 `script.json` 的正文，产出 `timeline.json`（每个字的时刻、原声插段、片尾留白）。**片子的 t 就是口播的 t**：镜头表里写 `'@句id:词'`，不写秒数，画面全挂在字上。

- 对齐的键用完整句子编号。只截前几个字符当键的话，"b10b" 会覆盖 "b10"，字幕和卡点就全错了。
- 每改一次 `script.json` 的文案，就要重跑一次 `host_timeline.py`；`render.mjs` 会检查文案和时间线是否对得上。
- `new_film.mjs` 建片时生成的 `timeline.json` 只是占位（`timeline_stub.mjs` 按字数估的），**不能用来交片**：口播原片一到位就换成对齐出的正式时间线。
- 口播原声不要事后变速（不要用 atempo 加速），语速就是原片语速；片尾多留几秒用 `--tail`。

## 当事人原声插段

见 `sourcing.md` 的「当事人原声」一节。混音时，口播原声和插进来的当事人原声放在同一条人声总线上，这样配乐会自动给它让路；两段的响度差控制在 2dB 以内（`mix.py --check`）。

## 音效和配乐

音效只跟画面里的动作走，一个动作一声，同一时刻只留一个。实践中验证过的口味：
- 镜头沿桌面滑过去、摇去找下一个：很轻的 whoosh。
- 横推换人、画框甩进来、推近画框：电影感的快 whoosh。
- 巨字立起来、身后换背景：一声低沉的撞击。
- 累加滚数：滚的时候一条短的上升音，停在那个数上时一声电影感撞击。片名也用电影感撞击。
- 原文倒成桌面、两个世界之间的虚化过渡：低沉的 whoosh。
- 开头如果用关键词快闪：每张一声很轻的翻书。
- 资金流动的管子：很轻的 whoosh。
- **不用**：金币、收银机、筹码这类卡通化的"钱"音效；紧张的滴答配乐和放映机声，容易显得怪。

配乐用一条平稳的底乐，压在口播下面约 18dB，人声出来时 sidechain 自动压低，片名期间抬高。素材推荐从 Openverse 检索 CC0 的（`https://api.openverse.org/v1/audio/?q=…&license=cc0`），并把来源记进清单。

如果没法亲耳听（比如由 AI 代理混音）：
- 按峰值归一每个音效（`mix.py` 的 `peak` 参数），不靠猜音量；
- 混完量响度：开头、口播、每段原声插段都要量；
- 交付时请用户重点听口播剪口、插段接缝和语速。

`scripts/mix.py` 已经实现了上面这些：口播原声、原声插段、音效、配乐，最后到 -14 LUFS。
