# 原版处理素材的特效 · 开片必读，必须写进镜头表

**一句话**：荧光笔刷黄、拉近放大、快切实拍、画框推满屏、挂墙、圆窗这些特效，渲染代码一直都在
`kit/scenes.js`、`kit/scenes_plus.js`、`kit/kit.js`、`scripts/moves.js` 里，和原版逐行一致，一行都没删。
**它们靠镜头表里的参数触发，参数不写，成片里就一个都不会出现。**

用户认可的成片 `demo/host-demo/out/demo_720_host_mid.mp4` 里，10 镜有 6 镜是这类带真素材的镜头，
全部原技能原样（逐镜拆解见 `references/mid-film-breakdown.md）。其中：

- 第 5、9 镜是 `article` 的 **`hl` 荧光笔刷黄 + `zoom` 推近放大**（10 镜里只有 2 镜刷黄）
- 第 4 镜是 `footage` 的 **`push` 慢推近**
- 第 1、10 镜是 `host` 的 **`zoom` 景别跳**和 `enter:'grow'`，第 2、10 镜还挂了证据到墙上

也就是说，这条片子里的动作是**换着用**的：刷黄只占两镜，其余是慢推、挂墙、景别跳。

**这几镜一个像素都不许改。** 本技能后来加的东西只管「没有真素材、靠语义画」的那一屏，见
`references/semantic-thinking.md`；带真素材的镜头一律不碰。

---

## 开片必执行（不是可选参考）

1. 转写完口播、写 `film.js` 前，**先给每个带真素材的镜头写一句 `says`**：这一句要让观众看懂什么。
   是「给一个需要出处的数」、还是「指出这就是那个东西」、还是「把证据挂进她说话的画面」，
   决定这一镜用哪一种动效。
2. **一镜一个主动作，按语义分配，别全片只用荧光笔。** 荧光笔只是下面「动效配比」里的一族，
   而且只在「这句需要出处」时才对。参数最熟不等于每镜都该写 `hl`。
3. **每镜停够**：信息画面 ≥2.6 秒、元素多 ≥3.0 秒、带推近 / 刷黄动作 ≥3.4 秒；
   最后一个落点到切镜还要留 ≥0.7 秒（带动作 ≥1.2 秒）静止可读。见「停留时间」一节。
4. 交片前跑 `--check`。它既检查「一处刷黄、一处推近都没有」，也检查
   「连续三镜同族」「带素材 ≥5 镜却少于 3 族」「短镜」「末尾没留静止」；
   再用 `--sheet` / `--stills` 亲眼看动作走完没有。

**为什么以前会看不到**：上一版只把参数写进了参考文档和 HTML 菜单，没规定什么时候必须写、
也没进检查。别的 AI 工具写镜头表时按自己理解选了场景，没写 `hl` / `zoom`，代码再完整也不会动。
现在把它变成流程里的硬步骤。

**为什么后来又变成「一直只有荧光笔」**：上一版的开片必执行把 `article` 放在第 1 条、
`effects.html` 前三张卡都叫「荧光笔」、`--check` 只查「全片有没有至少一处 hl」。
于是最省事的写法是每镜都写 `article + hl + zoom`，一次就过检查。
现在检查改成按镜统计主动效族，重复就报错。

## 动效配比：一条片里别只有一种动作

`kit/kit.js` 按「观众看到的动作」把素材处理分成几族；`--check` 会统计每镜属于哪一族：

| 主动效族 | 场景 + 必写参数 | 这一句在讲什么 |
|---|---|---|
| 荧光笔刷黄 | `article`+`hl/zoom/hlAt`、`desk`+`read`、`headlines`+`pick` | 需要出处、要钉死某一句 |
| 实拍慢推 | `footage`+`push`（可加 `focus`） | 这就是那个东西，慢慢看清 |
| 界面框选推近 | `device`+`hl/zoom/label` | 界面里这一块最关键 |
| 画框推满屏 | `frames`+`fill` → 下一镜 `footage settle:true` | 并列几样，再细看其中一样 |
| 窗口撑开 | `popup`+`from/to/back` | 从上一镜拎出一份证据 |
| 快切实拍 | `montage`+`pin/items/step` | 这件事 = 这些画面 |
| 墙上挂证据 | `host`+`items[].at`、`swap` | 证据挂进她说话的画面 |
| 口播景别跳 | `host`+`zoom:[{at,s}]`、`enter:'grow'` | 给证据腾地方 / 说完收回 |

**怎么分**：带真素材的镜头 ≥3 镜时不能只有 1 族；≥5 镜时至少分散到 3 族；
同一族不连着用三镜。全片只要一两镜真的在「给出处」就够了，其余按语义换动作。
`--check` 报「动效重复」时，改法是把其中一镜换成上表里另一族并写齐它的参数，
不是把 `hl` 删掉让它变成静态截图。

**这是配比，不是镜头顺序模板。** 哪族用在哪一镜、用几次，全看这条口播在讲什么；
换一条口播、换一个 AI 工具，本来就该分得不一样。

## 什么时候用哪个：按这句话在讲什么选

不是按「手里恰好有什么素材」选，是按**这一句口播要观众看懂什么**选。同一个素材，说法不同，动效就不同。

| 这句口播在讲什么 | 该让观众看到什么 | 场景 + 必写参数 | mid 成片对应 |
|---|---|---|---|
| 给一个观众可能不信的数、一个需要出处的断言 | 「这句白纸黑字写着」 | `article` + `img` + `hl` + `zoom` + `hlAt` | 第 5 镜「永不关机 24 小时工作」、第 9 镜「第二大脑」 |
| 这就是那个东西、那个人、那个地方 | 慢慢看清、认得出 | `footage` + `img`/`clip` + `push` | 第 4 镜超级黑盒产品实拍 |
| 界面里这一块才是关键 | 视线被框到那一块 | `device` + `img` + `hl` + `zoom` + `label` | — |
| 好几家都在说，但要紧的只有一句 | 从一堆里挑出那一句 | `headlines` + `pick` + `mark`，或 `desk` + `read` | — |
| 钱 / 东西分到了这几样，再细看其中一样 | 并列 → 推满屏 | `frames` + `fill`，下一镜 `footage` 写 `settle:true` | — |
| 这件事 = 这些画面 | 很多画面连成一件事 | `montage` + `pin` + `items` + `step` | — |
| 证据要挂进她说话的画面 | 墙上多一样东西 | `host` + `items[].at`，或 `swap` | 第 2 镜挂官网工作台、第 10 镜挂回开头的卡 |
| 说到关键词要给证据腾地方 / 说完收回 | 景别变化 | `host` + `zoom:[{at,s}]`、`enter:'grow'` | 第 1、10 镜 |

**通用前提**：所有时刻写 `'@句id:词'`，挂在口播的字上，不写死秒数；真素材路径写自己的
`assets/img/…`、`assets/docs/…` 或 `clip` 帧序列名，别用 `assets/kit/ph/` 占位图交片。

## 一、给出处：荧光笔刷黄 + 推近放大（`article`）

### 什么时候用

只要这一镜在**给一个观众可能不信的数、一个需要出处的断言、一句官网原文**，就用它。
荧光笔的作用是把出处钉死，不是装饰：观众要同时看到「这是原文」和「就是这一句」。
不写 `hl` 只放一张截图，等于没做这个动作——`--check` 会提醒「有截图没给 hl：不知道刷哪一句」。

**没写它的后果**：成片里只剩一张静态截图，看不到黄色笔从左刷到右，也看不到镜头推近。
这正是之前反馈的「放大荧光笔刷黄这个动效没看到了」。

### 怎么运作（渲染器里实际发生的事，`kit/scenes.js` 的 `article.make`）

1. `prep` 先 `loadImg(p.img)` 拿到原图宽高 `iw/ih`。
2. 页面按 `PW=1560` 宽排进 1920×1080 世界坐标，顶部 `Y0=70`，整页按 `tilt`（默认 -1.2°）斜放。
3. **`hl` 坐标自动换算**：`k = PW / (cssW ?? (iw===3200 ? 1600 : iw))`，每个框乘 `k`。
   `snap_news.mjs` 截的图是 3200 宽、框按 1600 宽网页坐标给的，所以自动乘 `1560/1600`；
   别的截图按图片像素给，乘 `1560/iw`。折行的关键词给两个框，会分成两段分别刷。
4. 所有框 `unionBox` 成 `zb`，取中心 `(zx,zy)` 作为推近的目标点。
5. **时间轴**：`tz = max(t0+0.3, zoom 的时刻 ?? t0 + 镜长×0.3)` 开始推近；
   `th = hlAt 的时刻 ?? tz+0.6` 荧光笔开始刷。两个都挂在口播的字上。
6. **机位**：`camSeq` 三帧——开头看整页上半（约 0.92 倍），0.9 秒稳住，`tz` 起用 1.05 秒推到
   `camZ`（中心对着刷黄处，倍率 `zoomS` 默认 `clamp(1100/(刷黄宽度+300), 1.2, 1.8)`）。
7. **刷黄**：每帧 `hk = clamp((t-th)/0.45)`，在那一句上盖一层 `#ffd84a`、
   `mix-blend-mode:multiply` 的矩形，宽度 `(w+8)*hk` 从左往右长出来，0.45 秒刷完。
8. 推近时暗角随 `zk` 加深；刷完到切镜不足 1 秒会 warn「证据至少停 1 秒」。

所以 `zoom` 和 `hlAt` 不是两个孤立参数：`zoom` 定推近起点，`hlAt` 定笔落下的时刻，
`until` 必须留够刷完 + 停 1 秒。三者一起写，动作才完整。

### 参数

| 参数 | 作用 |
|---|---|
| `img` | 原文截图；`hl` 指定刷哪一块，折行写两个框 `[[…],[…]]` |
| `mock` | 截不到原文时用核实过的文字排一页：`{source,date,title,body:[…],mark}`；`mark` 必须原样出现在标题或正文里 |
| `hl` | `[x,y,w,h]` 或 `[[x,y,w,h],…]`，刷黄框 |
| `zoom` | 开始推向刷黄处的时刻（默认这一镜过了三成） |
| `hlAt` | 荧光笔刷过的时刻（默认 `zoom` 后 0.6 秒） |
| `zoomS` | 推近到几倍（默认按刷黄那句宽度算 1.2–1.8） |
| `tilt` | 截图斜几度（默认 -1.2，`0` 摆正） |
| `cssW` | `hl` 按多宽的网页坐标算；一般不用写 |

### 可复制片段

```js
// 有真截图：hl 直接抄 snap_news.mjs 打印的框
{scene:'article', until:'@b03', says:'这个数是报道里翻出来的，有出处',
 img:'assets/docs/report.png', hl:[783.6, 139, 139.9, 34], zoom:'@b02:两百亿', hlAt:'@b02:两百亿'},

// 截不到原文：用核实过的文字排一页，mark 刷黄
{scene:'article', until:'@d06:净烧', says:'亏损的数有出处',
 mock:{source:'报道', date:'2026-10-02', title:'预计未来几年累计投入约 2780 亿元',
  body:['报道称，算力上的投入还会继续增加，收入增长暂时追不上支出。'], mark:'2780 亿元'},
 zoom:'@d06:从今年', hlAt:'@d06:两千七百'},
```

### 荧光笔坐标怎么来

`scripts/snap_news.mjs` 截新闻页 / 财报页，并打印关键词所在的框；折行会给两个框。
用法见 `references/sourcing.md`「新闻截图」一节。

### 同类变体

| 场景 | 参数 | 说明 |
|---|---|---|
| `desk` | `items:[{img,at,hl,cssW}]` + `read:{i,at}` + `all` | 2–5 张截图摊桌面，抬平后推近第 i 张并刷黄它的 `hl`；`until` 比 `read.at` 晚 2 秒以上 |
| `headlines` | `items:[{src,title,date}]` + `pick:{i,at}` + `mark` | 6–12 条标题墙，只亮第 i 条并刷黄；`mark` 必须原样出现在那条 `title` 里 |

## 二、拉近放大素材

### 什么时候用

这一句在说「**这就是那个东西**」「界面里这一块才是关键」「先看这一样」的时候，
用推近把观众的视线收到一个点上。跟 `article` 的区别：`article` 推近是为了读那行字，
`footage` / `device` 推近是为了看清那样东西。

### `footage`：全屏实拍 + 慢推

**怎么运作**（`scenes.js` 的 `footage.make`）：
每帧算 `k=(t-t0)/镜长`，`s = lerp(s0,s1,k)`，`push:[1,1.06]` 就是整镜从 1 倍线性推到 1.06 倍；
`transform-origin` 取 `focus:[x,y]`（默认画面中心 960,540），`scale(s)` 作用在整个实拍层上。
`clip` 帧序列按 `from + (t-t0)*rate` 取帧。`settle:true` 会额外在开头 0.35 秒从 1.08 收回 1，
用来接上一镜 `frames.fill` 推满屏。`badge` 在其 `at` 时刻淡入一个圆盘钉在左上角。

| 参数 | 作用 |
|---|---|
| `img` / `clip` | 实拍图，或 `footage.py extract` 抽出的帧序列名 |
| `from` / `rate` | 从第几秒开始 / 播放速度（最慢 0.8） |
| `push:[1,1.06]` | 慢推起止倍数 |
| `focus:[x,y]` | 往哪一点推（1920×1080 坐标，默认中心） |
| `settle` | 接 `frames` 推满屏那一镜 |
| `badge:{name,color,at}` | 上一镜的圆盘缩成徽章钉在左上角 |

```js
{scene:'footage', until:'@d04', says:'这就是那批数据中心',
 clip:'site', from:0, rate:1, push:[1,1.06], focus:[960,540]},
```
实拍至少停 2.6 秒（旧文档写 1.5 秒，实测太短，观众认不出就切走了）；画面里要认得出是谁、是什么。原片烧进去的字幕台标，抽帧时放大裁掉。

**已验收样例（mid 成片第 4 镜）**：
```js
{scene:'footage',until:'@b06',host:'pip',says:'官网实物：超级黑盒，插电就一直在线',
 img:'assets/web/hw-box.jpg',push:[1,1.05],badge:{name:'HeyClaw',color:'gold',at:'@b05:第二步'}},
```

### `device`：界面框选 + 推近

截图铺满屏幕、顶对齐，`hl` 跟着自动换算，不用自己算比例；`zoom` 时刻推到框选处，
`label` 是 2–8 字短标签。**写了 `label` 就必须写 `hl`**。

```js
{scene:'device', until:'@e10', enter:'through', says:'看有没有人掏钱',
 img:'assets/img/app.png', hl:[48,1150,984,250], zoom:'@e09:愿不愿意', label:'付费入口'},
```

### 其它推近写法

```js
// frames：并列画框 → 其中一个推满屏，下一镜接同一素材的全屏实拍
{scene:'frames', until:'@d04', says:'钱的大头流向芯片和数据中心', pin:{value:'$7250亿'},
 items:[{img:'assets/img/chip.jpg', label:'芯片', at:'@d03:芯片'},
        {img:'assets/img/dc.jpg',   label:'数据中心', at:'@d03:数据中心'}],
 fill:{i:0, at:'@d03:END-0.1'}},
{scene:'footage', until:'@d05', says:'先看芯片这一头', img:'assets/img/chip.jpg', settle:true},

// popup：上一镜冻住压暗，从 from 撑开到 to，到 back 缩回（第一镜不能用）
{scene:'popup', until:'@d18', says:'连新闻台都在问',
 img:'assets/img/tv.jpg', from:[420,260,520,300], to:[400,220,1120,630], back:'@d17:END'},

// line（scenes_plus.js）：镜头推到出事那一段，线变红、旁边立大数
{scene:'line', until:'@g04', says:'十月这一跌最狠', data:'assets/data/gold.csv', unit:'$',
 draw:{at:'@g02:从年初', until:'@g02:一路'},
 focus:{at:'@g03:十月', from:'2026-10-01', value:'-6.9%', brow:'10月 · 金价'}},
```

```js

{scene:'montage', until:'@d19', says:'这七千多亿 = 这些楼和芯片',
 pin:{value:'$7250亿', brow:'一年'},

// title：实拍压暗退成底，片名压在上面
{scene:'title', until:'@d02', says:'先说结论', title:'这笔账到底怎么算',
```

`host` 的素材处理（挂墙 `items`、身后换世界 `swap`、`zoom` 景别跳、圆窗 / 竖窗、`enter:'grow'`）
见 `references/presenter.md`。完整场景参数以 `kit/README.md` 为准，`kit/scenes.js` 里每个场景的
`help` 字段是最终说明书。`kit/effects.html` 是同一批特效的纯 CSS 菜单（零图片），浏览器打开可对照。

模板对不上的那一镜写 `scene:'custom'`，复用 `scripts/moves.js` 的手法库；完整选型见
`references/motion.md`，`examples/ai-burn-money/moves_lib.json` 和 `film_lib.js` 是磨过的动作参数参考。

## 四、停留时间：一镜要停多久

量化基准是用户认可的 `demo_720_host_mid.mp4`：10 镜分别是
4.4 / 6.0 / 6.2 / 4.1 / 5.3 / 5.5 / 2.6 / 3.9 / 5.1 / 4.7 秒，**最短也有 2.6 秒**。

以前把「信息镜 ≥1.5 秒」写进文档，代码却只管纯图形场景（`flow` / `board` / `statement`…），
带真素材的 `article` / `footage` / `device` / `frames` 一秒下限都没有，也没检查
「最后一个落点到切镜还剩多久」——于是荧光笔刚落笔、镜头刚推近就切走，观众什么都没看清。

| 这一镜是什么 | 至少停 | 为什么 |
|---|---|---|
| 一般信息画面（卡片、大字、图表、实拍展示） | 2.6 s | 34–55 汉字要读完 / 要认得出是什么 |
| 元素多、信息量大、或按语义自己画的一屏 | 3.0 s | 视线要扫过不止一个焦点 |
| 带推近 + 刷黄动作（`article`、`device`、`desk`、`frames`） | 3.4 s | 起手 0.3 + 推近 1.05 + 刷 0.45 + 稳定停 1.0 + 余量 |
| `popup` 窗口撑开 | 2.6 s | 撑开 0.35 + 缩回 0.3 秒；硬凑 3.4 秒必然多出一段静止，静止段另见第七节 |
| 最后一个落点 → 切镜 | 0.7 s（带动作 1.2 s） | 动作走完要留一段静止可读的时间 |

`--check` 把这些做成硬错误。改法只有两种：**把 `until` 往后挪**，或**并进相邻镜**。
`short:true` 一条片最多一处，写多了也会被拦——别拿它当绕开检查的开关。

---

## 五、怎么确认这些特效真的画出来了

```bash
node scripts/render.mjs --dir <片子目录> --check                      # 参数写错 / 时刻没挂字 / 刷黄后停不够 / 全片没写动效，都会报
node scripts/render.mjs --dir <片子目录> --sheet                       # 每镜三帧（开头/中间/结尾）拼一张，看动作有没有走完
node scripts/render.mjs --dir <片子目录> --stills 3.2,4.8 --h 720    # 抽单帧看荧光笔 / 推近那一刻
```

看三件事：黄色笔从左往右刷完了；刷完到切镜停了 1 秒以上；实拍 / 界面确实推近到位了。

## 六、两条硬规矩

1. **带真素材的镜头一律由原技能场景渲染，一个像素都不改。** 不要在 `art.js` 里覆盖
   `host` / `footage` / `article` / `frames` / `desk` / `device` / `popup` / `montage` 的 `make`，
   也不要拿文字卡、网格、贴片去盖真素材。非素材镜头才由 `art.js` 自己画（见
   `references/semantic-thinking.md`）。
2. **这些是词汇，不是固定镜头顺序。** 每镜先写 `says`，再按这句话在讲什么挑一个特效，
   把参数写进镜头表；一镜一个主动作、同族不连用三镜、每条片至少分散到 3 族、每镜停够。
   不要照抄上面任何片段的文案和数字，也不要写 `semantic`（已废弃，
   技能不会自动替你画非素材画面）。

## 七、画面别抖、别死（v3.8.0）

用户验收 720p 成片时指出两类问题：2–3 秒「细微的放大缩小」、8–9 秒「画面静止」。
逐帧量过：2–3 秒有两次间隔 0.88 秒的反向景别跳；7.5–8.4 秒相邻帧差只有 0.06（等于静止），
8.6 秒之后是一张不动的真人照片。都不是渲染坏了，是镜头表写法 + 一处冻结逻辑叠出来的。
下面每一条都有 `--check` 兜底。

### 1. 景别跳别挤在一起（`host.zoom`）

`kit/host.js` 的 `zoomCam` 是**硬切档位**（原技能设计，源码注释写「换档是硬切，不推不拉」）：
到 `at` 那一刻 `s` 直接换成新值，没有缓动；档位之间还有每秒 0.4% 的慢漂。
一镜里写三档、后两档只隔 0.88 秒且一缩一放（1.15 → 1.0 → 1.06），
观众看到的就是「画面放大缩小抖了一下」，不是换景别。

- 相邻档位 ≥0.9 秒；方向要来回（推近再落回中景）就得 ≥1.2 秒。
- 收尾那一下「推近 → 落回中景」是原技能允许的（mid 片第 10 镜），只要离够 1.2 秒。
- 两档 `s` 差不到 0.04 等于白跳一次，`--check` 会提醒删掉。
- **`zoom` 仍由原技能渲染**：没有改成缓动、没有加模板，也没有写死档位。这里只管别写得太密。

### 2. popup 别留长段不动的画面

`popup` 原来是「上一镜冻住压暗 → 撑开窗口 → 看完缩回」，两层静止：

- `MV.popWindow` 把底层**永久冻在撑开前那一帧**（`still(o.under, o.t0-.01)`），
  窗口缩回去以后露出的是一张不动的真人照片；真实成片 8.6–9.8 秒就是这样。
- 窗口撑开只要 0.35 秒，`back` 却拖到句子末尾，中间 2.7 秒整屏一动不动。

v3.8.0 的改法（**窗口的大小、位置、压暗、虚化一个像素没动**）：

- `scripts/moves.js` 的 `popWindow` 底层默认**跟着片子的 t 继续走**，人还在动；
  要原技能的冻结帧写 `freeze:true`。`kit/scenes.js` 的 `popup.under` 不再忽略传进来的时间。
- `popup` 镜按 **2.6 秒**（不再按 3.4 秒的推近刷黄档硬凑；硬凑必然多出一段静止）。
- `back` 写在「看完」那一刻：撑开完 → 缩回前 ≤1.8 秒；缩回完 → 切镜 ≤0.9 秒，
  两条都由 `--check` 报成错误。窗口里要动就用 `clip` 帧序列，静态截图别单独撑 4 秒。
- 任何「只有一张静态图、中间没动作」且超过 3.2 秒的镜，`--check` 提醒加 `push` / 落点或缩短。

### 3. 25fps 源片抽 30fps 的重复帧

`footage.py host` 用 `fps=30` 抽帧；源片常见 25fps，ffmpeg 靠**重复帧**补，
约每 0.2 秒有一帧和上一帧一模一样，快动作会看着「顿一下」。这是帧率换算，不是渲染抖动，
也不是「画面静止」。默认保持原行为（不引入插帧伪影）；确实觉得顿，重抽一次：

```bash
python scripts/footage.py host 口播.mp4 <片子目录> --interp
```

`--interp` 用 `minterpolate` 运动补偿生成中间帧。代价：抽帧慢很多（1080p 整条几分钟），
快速挥手可能有拖影，抽完用 `--sheet` / `--stills` 看一眼再决定用不用。
`extract` 同样支持 `clips.json` 里写 `"interp": true` 或命令行 `--interp`。
