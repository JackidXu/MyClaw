# 真实素材口播剪辑（real-footage-presenter-cut）— 真人口播 + 真素材的解读短片

**讲一件事：真的人、真的画面、真的原文作证据；口播原声就是配音，图形只在该讲道理的地方把关系画清楚。每一镜都接住上一镜的东西往下走。**

## 输入只有一种

一条口播视频（真人或数字人，一个机位、中间不切）+ 这条片要用的真素材（产品/官网/新闻/实拍视频片段）。其它输入一律不接：不产出没有主持人的片子，也不用临时配音替代口播。

- 她是这条片的"地面"：观众每离开她一会儿就回到她身边。证据和图形不是盖掉她，而是挂进她的房间、或者把她带进图形的世界。
- 先读 `references/presenter.md`：真人怎么融进来、七种样子、怎么走、墙上挂东西放哪、景别、声音。
- 口播层 `kit/host.js`：`scene:'host'`（房间全屏 / `items` 挂墙 / `swap` 身后换世界 / `zoom` 景别跳），任何场景加 `host:'pip'`（角上圆窗）或 `host:'window'`（右侧竖窗 + 左侧图形板），`enter:'grow'` / `'drop'` 回到房间。

### 竖屏口播（9:16）怎么处理

**默认就是「中间放完整竖屏原片，两侧同源虚化」，绝不把人裁成大特写。** `footage.py host` 先用 ffprobe 量原片宽高，宽高比 < 1.45 自动走 blur 模式：抽出来的每一帧都是 1920×1080 的合成画面——中间是等比缩到 1080 高的完整竖屏原片（人、身体、手势、身后环境全在），两侧是同一帧放大铺满 + 高斯模糊 + 压暗 + 极淡网格。合成帧仍是 1920×1080，所以 `host` 的景别跳、挂墙 `items`、`pip` 圆窗、`window` 竖窗、`matte.py` 抠像全部照常工作，不用改模板。

- 别再用 `scale=1920:1080`（竖屏会被压扁），也别用 `crop` / `zoom` 去铺满（会把人脸放大裁成大特写，身体和环境都没了）。竖屏片段写了 `zoom` 时 blur 模式会忽略它，避免二次裁人。
- `fit` 选项：`auto`（默认，竖屏走 blur、横屏保持原来的等比铺法）/ `blur` / `cover`（确实要铺满时才用）/ `plain`（旧行为，只给横屏）。
- `faceY` 一律按**原片**里脸中心的 y 来量，`host.js` 读 `assets/clips/fit.json` 自动换算到合成帧；挂墙坐标、抠像坐标按合成帧 1920×1080 写。
- 两侧虚化是背景不是空位：还想放别的元素，用 `scene:'host', items:[...]` 把照片 / 价签挂进她的画面，或 `host:'window'` 让图形板占左边、她在右边竖窗；不要再铺一层大卡片把虚化盖掉。

### 开片流程

```
node scripts/new_film.mjs <片子目录>
python scripts/footage.py host 口播.mp4 <片子目录>   # 整条口播抽 30fps 帧、自动登记 counts.json；竖屏自动「中间完整 + 两侧虚化」
python scripts/matte.py <片子目录>/assets/clips/host <片子目录>/assets/cut/host   # 挂墙/换世界要抠像，再跑 matte_clean.py
（写 script.json：lines 写她实际说的话，一句一个 id；字幕就用这份）
python scripts/host_timeline.py <口播.mp4> <片子目录>/script.json <片子目录>/timeline.json [--tail 1.0]
（写 film.js：FB.init → KIT.use → await KIT_HOST.use(K,{faceY:她脸中心在原片里的 y}) → K.film([...])）
（带真素材的镜写足动效参数，一镜一个主动作、别全片刷黄，见 references/footage-effects.md 的「动效配比」；每镜停够 2.6 / 3.0 / 3.4 秒，见「停留时间」；host 的 zoom 档位别挤在一起，popup 看完就缩回，见「画面别抖、别死」）
（纯语义镜按 references/semantic-thinking.md 的四步在 art.js 里自己画，不写 semantic）
node scripts/render.mjs --dir <片子目录> --check / --sheet / --video --h 720
python scripts/sfx_synth.py library/sfx/synth
（写 sfx.json：音效卡在换样子的地方，见 references/presenter.md 的"声音"）
python scripts/mix.py <片子目录> --check
```

## 七条硬规矩

1. **真素材的镜头一个像素都不改，动效参数必须写足。** 场景清单：`host`（房间全屏 / 挂墙 / 换世界 / 景别跳）、`footage`（实拍全屏 + `push` 慢推）、`montage`（多段实拍快切）、`frames`（画框铺截图 + `fill` 推满屏）、`article`（原文 `hl` 荧光笔刷黄 + `zoom` 推近）、`headlines` / `desk`（标题墙 / 桌面刷黄）、`device`（界面框选推近）、`popup`（窗口撑开）、`person` / `title` 实拍压底——以及任何带 `img` / `clip` / `photo` 的场景，全部由原技能渲染。不要在 `art.js` 里覆盖这些场景的 `make`，也不要拿文字卡、网格、贴片去盖真素材。**渲染代码一行没删，但参数不写就看不到动效**：每镜按 `says` 选一个主动效族并写齐参数（刷黄 / 慢推 / 挂墙 / 推满屏 / 界面框选 / 窗口撑开 / 快切实拍），**一镜一个动作，同族不连用三镜，带素材 ≥5 镜至少分散到 3 族**；只挑一两镜真的需要出处的写 `hl`，别把荧光笔当默认动作。`--check` 既查覆盖也查重复。机制、配比、使用时机、可复制片段见 `references/footage-effects.md`，可视化菜单 `kit/effects.html`；逐镜验收基准见 `references/mid-film-breakdown.md`。
2. **非素材镜头按语义自己画，不给固定构图。** 没有真素材的那一屏，由写镜头表的人读这一句口播，按 `references/semantic-thinking.md` 的四步（信息结构 → 主焦点 → 只放重点信息 → 区域越大内容越多）自己决定画什么，写在片子目录的 `art.js` 里并挂到对应场景。**不写 `semantic`（已废弃）、不给 `kind` 映射、不给图标顺序、不给固定英文卡眉、不给占位文案**；换一条口播、换一个 AI 工具，画出来本来就该不一样。`kit/semantic_scenes.js` 现在是无内容的绘图工具箱，运行时不会自动替换任何画面。
3. **自己画的那一屏，配比参考这个**：每屏 34–55 个汉字（2–6 秒能读完）、1 个视觉主焦点、1 张短句卡、少量贴片，留白 30% 以上。这是配比不是版式模板：画什么、几个元素、怎么分层由语义决定。上屏内容全部来自这一镜口播原话或已核实的原文，不编数字、不写占位词；取不到内容就少画一个元素，绝不拿废话填空白。卡片内部内容垂直居中成簇，不许留大空白。
4. **底只有一张细斜纹深蓝织物**，配色只用深蓝 + 琥珀金 + 米白。不要满屏 3D 物体、紫色青色整屏底、大团彩色光、浮尘、彩色 emoji。
5. **每一镜写 `says`**，一镜一个主角；时刻挂在字上（`'@b05:英伟达'`），不写死秒数；开头 0.5 秒内开口，第一帧就有东西。
6. **一镜要停够，不许一闪而过**：量化基准是认可的 `demo_720_host_mid.mp4`，10 镜 2.6–6.2 秒。信息画面（图形、卡片、大字、图表、**实拍 / 原文截图**）≥2.6 秒，元素多或自己画的一屏 ≥3.0 秒，带推近 + 刷黄动作（`article` / `device` / `desk` / `frames`）≥3.4 秒；`popup` 按 2.6 秒（撑开 0.35 + 缩回 0.3 秒，硬凑 3.4 秒必然多出一段不动的画面）；最后一个落点到切镜还要留 ≥0.7 秒（带动作 ≥1.2 秒）静止可读。`--check` 把这些直接报成错误；改法是把 `until` 往后挪或并进相邻镜，`short:true` 一条片最多一处，别拿它绕开检查。cue 落点夹在镜内。**画面也别抖、别死**：`host.zoom` 相邻档位 ≥0.9 秒、方向来回 ≥1.2 秒（景别是硬切，挤在一起就是一缩一放）；`popup` 底层默认跟着时间走、人还在动，`back` 写在看完那一刻，撑开完→缩回前 ≤1.8 秒、缩回完→切镜 ≤0.9 秒；一张静态图撑过 3.2 秒要有 `push` 或落点。机制见 `references/footage-effects.md` 第七节。
7. **交片前**：`render.mjs --check` 没有错误（含素材动效覆盖、**动效重复**、停留时长、末尾静止、**景别跳间隔 / popup 静止段**检查）；`--sheet` 自己看过，确认刷黄刷完、推近到位、刷完停够 1 秒，且没有连着几镜都是同一个动作；720p 抽帧逐镜比对；带真素材的镜头要能确认与上一版完全一致。

## 这份技能是什么

- **是**：一套设计思路（每一镜放什么、为什么、凭什么接下一镜）、一套动效原理（为什么不像 PPT、不像 AI，手法清单和量化目标）、一套风格语言（舞台、巨字、抠像、圆盘、数字、图表、原文高亮、开头钩子菜单）、一套工具；原技能处理素材的动效原样保留，非素材画面给方法不给模板。
- **两档做法，画风是同一个：**
  - **模板档（默认，先用这个）**：`kit/` 里 33 个场景。一条片 = 一张镜头表：每一镜选一个场景，填这一镜的字、数、图和"念到哪个字"。镜头怎么走、东西怎么出现、前后层、运动模糊、字号颜色，都由模板管。
  - **手写档（模板对不上的时候）**：底座 `film_base.js` + 手法库 `moves.js` + 2.5D 小工具 `stage25d.js`，逐镜手写。只有一镜对不上时写 `scene:'custom'`。
- **模板是词汇，不是镜头顺序**。每条片的画面都从它自己的文案和素材里现想：每一镜先写 `says`（这一镜让观众多懂了什么），再找意思对得上的场景；只是差不多就换一个，或者手写。
- **慢推、数字滚动、实拍上压字都能用**。廉价的不是手法，是做法。判断用三句话：删掉它观众少懂了什么？是镜头在动、东西在换状态，还是元素自己在演入场？这一层是真的、具体的吗？
- 动手前先读 `references/thinking.md`、`references/motion.md`、`references/rules.md`；做模板档再读 `kit/README.md`、`references/footage-effects.md`（素材动效什么时候用、怎么运作、可复制片段）和 `references/semantic-thinking.md`（非素材画面怎么按语义自己设计）。`kit/effects.html` 是同一批特效的可视化菜单，纯 HTML/CSS、零图片，每张卡都有「什么时候用」和「怎么运作」两段，源码里带可复制片段。

## 流程：每一站停下来给用户看

审美由用户把关。不要一口气出成片；每站给出具体的东西，等他点头再往下走。

| 站 | 做什么 | 给用户看什么 |
|---|---|---|
| 0 选题 | 题目要同时满足"现在热"和"看完能带走点什么"；事实先查清、留链接 | 两三个题目，每个附一句钩子 |
| 1 文案 | 文案就是她的口播。先转写，和用户核对每个字（数字人常有读错、识别也会听错）；事实照样查清、留链接 | 转写全文 + 核对后的定稿 |
| 2 导演表 | 每一镜多一列"她在哪"：房间 / 挂墙 / 换世界 / 竖窗 / 圆窗 / 不在。先按 `presenter.md` 判断用哪几句，再填画面 | 要点：开头怎么抓人、每处怎么接、哪几处用真素材 |
| 3 素材 | 官方高清片 → 新闻/官网原文 → 产品实拍 → 原声。先拼联系表看过，再定入点，逐帧查切点；单段只截要用的几秒（`references/sourcing.md`） | 3–4 张关键样帧（真素材 + 版式），方向对了再做整片 |
| 4 时间线 | `host_timeline.py` 从口播逐字对齐，片子的 t 就是口播的 t；不用临时配音 | — |
| 5 开头 | 先挑 3 个机制不同的钩子，各做 5–8 秒粗剪给用户选（`references/opening.md`）；选中的再做 15–20 秒带声音的小样 | 3 个钩子粗剪 → 选中后的开头小样 |
| 6 全片 720p | 按导演表铺完。模板档：镜头表 → `--check` → `--sheet` → 720p；手写档：每写两三镜截静帧看，关键动作看连续帧（`strip.py`）。交片前跑 `motion_check.py` | 720p 全片、抽帧图，再点出两三处请他重点看 |
| 7 成片 | 改到满意；`mix.py` 混音；出 1080p，只渲一次 | 1080p |

每次交付都要做到：
- 用 `ffprobe` 验证文件能打开。
- 自己逐镜看过静帧和联系表，关键动作看过连续帧。
- 放进一个固定的审阅文件夹，用编号加中文名命名，旧版本加 `旧_` 前缀。
- 说清楚这版改了什么、哪些量过、哪些要用户自己听或看。
- 版权素材标出来，每条片写出处清单。

## 导演表

全片只有这一份计划。用户拿它核对画面，做的时候照它做，审片时拿它对照。每一镜写这几列：

| 镜 | 时间 | 口播原话 | 屏上是什么，在干什么 → 停下来时留下什么 | 观众多懂了什么 | 承担 | 她在哪 | 读懂时刻 + 停留 | 承接 | 手法 |
|---|---|---|---|---|---|---|---|---|---|

- **观众多懂了什么**：一句具体的话，和上一镜的不一样。写不出来，这一镜就该删或者重想。模板档里这一列就是 `says`。
- **承担**：这一镜靠什么让人看懂。人物 / 实证（真素材、原文）/ 构造（短句卡、贴片、图表）/ 文字（大字、结论）/ 混合。
- **她在哪**：房间 / 挂墙 / 换世界 / 竖窗 / 圆窗 / 不在。
- **承接**：上一镜留下的哪样东西被这一镜接住，接法写成 `续 / 切 / 带过 / 推近 / 展开 / 换章` 加上那样东西。第一镜写 `—`。
- **手法**：模板档写场景名；手写档写 `moves.js` 里的手法名。先填前面几列，最后才填这一列。
- 每一镜的素材从哪来（哪段实拍、哪篇原文、哪张照片）也记下来，交片时就是出处清单。
- 口播原话一字不改；一镜可以覆盖好几句话；时刻挂在词上。
- 写完做一次"读表"检查：遮住文案和"多懂了什么"两列，只读"屏上"一列，看还讲不讲得通。

## 模板档：一条片怎么做

```
node scripts/new_film.mjs <片子目录>                  # 建片子：lib/、assets/kit/、fonts/、script.json、film.js 起点
（抽口播帧、写 script.json、跑 host_timeline.py 出 timeline.json）
（写 film.js：await K.film([ {scene, host, until, says, enter, …场景参数}, … ])）
node scripts/render.mjs --dir <片子目录> --check        # 几秒：镜头表错误 + 提醒，改到没有错误
node scripts/render.mjs --dir <片子目录> --sheet        # 每镜开头/中间/末尾三帧拼成 out/sheet.png
node scripts/render.mjs --dir <片子目录> --video --h 720
```

- 场景怎么选、每个场景的参数和例子：`kit/README.md`（30+ 场景，优先看带真素材的那些）；非素材镜头怎么按语义自己画：`references/semantic-thinking.md` + `starter/art.js`。
- 场景写法参考（纯代码，不能建片）：`kit/demo/film.js`（前 22 个场景各用一次）、`kit/demo2/film.js`（后 11 个）。这两份文件没有口播层，只用来查某个场景的参数怎么写；成片一律从 `starter/` 起，接真人口播帧。
- `--check` 的提醒都要处理：要么改，要么能说出为什么不改。
- 一镜对不上任何场景：`scene:'custom'` 手写这一镜，也要写 `says`。
- 真素材镜头改完，用原版入口和新版入口各抽一帧做 SHA256 比对，确认零改动；非素材镜头确认是自己按语义画的，没有套固定版式。

## 手写档：片子怎么搭（骨架）

- 底座 `film_base.js` 暴露 `window.ready` 和 `window.seek(t)`。`seek` 找到 t 所在的镜头（`shot(t0, t1, fn)`），调用 `fn(t)` 返回这一帧的 HTML，并等图片解码和字体加载完。同一个 t 永远画出同一帧，不依赖 CSS 动画和播放时钟。
- `index.html` 已经引好底座、手法库、2.5D 小工具、模板库、无内容的绘图工具箱和 `art.js`。字体和素材都要在片子目录里：`render.mjs` 的服务器根目录就是片子目录，`../` 引用会 404。
- 时刻一律写成 `cue(句id, '词')`，从时间线里取，不写死秒数。
- 实拍抽成帧序列，按 t 取帧，不用 `<video>`。帧数要登记，漏了会取到不存在的帧，出现黑屏或空框。
- 一镜 = 一个机位函数 + 几层画面：机位用 `camPath(t, 起点, 移动表)`，每层用 `L(机位, 上一帧机位, z, html)` 包起来，远的层 z 小，运动模糊自动算。
- 镜头之间要承接时，把上一镜的函数在它最后一刻的画面拿来做下一镜的开场。手法库里的转场（`pushSwap`、`pushThrough`、`blurToBase`、`frameFill`）就是这样接的。
- 720p 看效果，1080p 只在定稿后渲一次。

## 视频素材怎么用

技能不直接吃 `.mp4`：先 `footage.py extract clips.json` 抽成 30fps / 1920×1080 的 `assets/clips/<名>/0001.jpg…`，帧数会自动登记进 `counts.json`；镜头表里把 `img:'assets/…jpg'` 换成 `clip:'<名字>'` 即可，支持 `from`（入点）、`rate`（速度）。`footage` / `montage` / `frames` / host 的 `items` 都能放视频，口播层本身就是帧序列。

注意：帧率统一 30fps；**竖屏 / 方屏片段 `extract` 会自动走 blur 填充（中间完整 + 两侧虚化），既不压扁也不把人裁成大特写**，确实要铺满才显式写 `fit:'cover'`；帧数漏登记会直接报错；**视频原声不会自动进成片**，渲染器只画画面，声音走 `mix.py` 单独混；5 秒帧序列约 18MB，长视频只截要用的几秒。
