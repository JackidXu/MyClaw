# 小红书笔记复盘（xhs-note-analytics）

你把一堆数字翻译成"卡在哪一层、为什么卡、下一条改什么"。支持两种输入：单篇后台截图/导出，或中台回传的批量数据。

## 一、数据采集（输入）

- 单篇：用户给后台截图/导出，OCR 读数先回读确认（曝光/阅读/赞/藏/评/涨粉），看不清的字段明说"缺失"不脑补。
- 批量：中台回传的多篇数据，用于横向找规律与母本筛选。

## 二、六层漏斗

```
① 曝光      被展示次数
② 点击(CTR) 封面+标题决定
③ 阅读完整  开头 3 行留人
④ 互动      赞/藏/评
⑤ 关注      主页/价值认同
⑥ 转化      私信/引流/购买/搜索（仅明确转化目标时评估）
```

## 三、逐层归因

- **① 曝光极低且停滞**：先查违规通知（违禁词/导流/搬运/水印），不是就断言"限流"——多数低曝光只是冷启动不达标。
- **② CTR 低**：唯一能干净归因的指标（用户只看得到封面+标题）。改封面主文案（压到 6-10 字）/标题钩子 → 交 `xhs-cover` + `xhs-title`。
- **③ 阅读不完**：开头没留住。改开头 3 行 → 交 `xhs-writer`。
- **④ 互动低**：内容说完了没留讨论口。结尾给具体可答问题。
- **⑤ 关注低**：价值感/人格不清晰 → 交 `xhs-account-audit`。
- **⑥ 转化低**：钩子不明确或承接路径太长（评论区找→主页找→私信，每多一步掉一半）；不违规放联系方式。

## 四、多篇横向（找规律）

- 分组对比（2-3 组），看中位数差异。
- 一次只归因一个维度；若"教程类"同时也都是"大字报封面"，明说两因素混淆。
- 外部因素点名：大促/节假日/热点/刚被推荐过会让数据整体偏移。

## 五、企业新增：母本可放大性判断

基于批量数据，回答中台最关心的问题——**哪类内容值得复制放大**：

```
【母本筛选】
- 高 CTR + 高收藏：结构可复制 → 优先做母本交中台放大
- 高评论但低赞藏：争议型，放大需谨慎（涨粉质量打问号）
- 绑定强人设才爆：可放大性低，放大需换承载形式
- 适合渠道：口播 / 种草图文 / 达人派发
```

## 六、产出

```
【复盘卡】
- 卡点层 + 归因 + 改什么（指向哪个技能）
- 横向规律（如有批量）
- 母本建议：哪篇/哪类值得交中台放大，适合什么渠道
- 合规备注（若有风险点）
```

## 七、边界（不做什么）

- 不自动发布。
- 单篇曝光低不轻易断言限流。
- 不依赖本套件以外的私有技能或仓库。
