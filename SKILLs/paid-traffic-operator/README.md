# 投流操盘手（paid-traffic-operator）Skill 包

> 一条**独立**的内容生产链路，专门制作「信息流投放 / 投流视频」文案。
> 不在 IP 内容生产体系内、零上游依赖；可按需借用 IP 包的成熟模块（只借产品/服务相关部分）。

---

## 1. 这个 Skill 是什么

把「一个要投流的产品/服务」变成「一条能投、能转化、合规无风险的旁白视频式脚本」。

**6 步同创流程**：

1. 定核心客户群体 / 核心痛点 / 核心卖点 → 产出 `投流Brief`
2. 建爆款开头库（按产品持久化，冷启动联网搜索（`browser` / `web-search`））→ 出 3-5 条 tailored 开头
3. 多版痛点描述（同创选优，过转化三刀）
4. 多版客户独有解决方案（挖客户方法论，必须客户确认）
5. 案例信任状（现场级还原，作证据画面）
6. 合规引流结尾（先问目的 + 钩子，必须共创）

→ 按「选择结论 + 理由链 + 证据画面」组装成旁白视频式脚本，过合规 + 去 AI 味。

## 2. 包结构

```
paid-traffic-operator/
├── SKILL.md                          # 主 Skill：触发词/定位/借用边界/6步流程/模板/边界
├── README.md                         # 本文件
└── references/
    ├── 爆款开头库模板.md              # Step2：开头方法论+5类钩子模板+持久化规则
    ├── 解决方案方法论库模板.md        # Step4：捕获客户独有方法论（per-client 库）
    ├── 投流合规清单.md                # Step6：广告法/平台雷区/行业禁词/风险审查（自包含）
    ├── 钩子类型库.md                  # Step6：引流钩子类型+共创流程（无钩子不交付）
    └── 投流脚本格式.md               # 组装：旁白视频式规则+理由链映射+校验红线
```

> 运行时还会在 `references/` 下生成**持久化数据文件**（非随包分发）：
> - `爆款开头库_{产品标识}.md`（Step2 产物，一款产品一个库）
> - `解决方案方法论库_{客户}.md`（Step4 产物，per-client 库）

## 3. 与 IP 包的关系（借用边界）

| 处理 | 借什么 | 怎么借 |
|------|--------|--------|
| ✅ 借（产品相关） | content-ip-manager：业务资料库 / 三层靶子 / 业务性感 / 产品相关案例 | 有 IP 档案则预填 Brief；无则轻量产品采集 |
| ⚠️ 默认不借 | 故事弹药库 / 精神内核 / 人物感性 | 投流是产品导向，人物稀缺性不进脚本 |
| ✅ 借（方法论） | content-script-writer/references/旁白视频-methodology.md | 组装脚本套用 |
| ✅ 借（润色） | qu-ai-wei | 终稿去 AI 味 |
| ✅ 借（合规·蒸馏） | content-quality-guard → 投流合规清单.md | 已内嵌，自包含 |

**零依赖**：IP 包未安装也能跑——产品字段走轻量采集，组装用内置 `投流脚本格式.md`，润色降级为通用口语化（建议装 qu-ai-wei 效果更佳）。

## 4. 安装 / 使用

1. 把 `paid-traffic-operator/` 整个目录放到 HeyClaw Skill 目录（`~/Library/Application Support/HeyClaw/SKILLs/`）。
2. 触发：说「帮我写个投流视频 / 投流文案 / 信息流投放脚本」即可调用。
3. 首次对某产品投流：Skill 会自动通过联网搜索（`browser` / `web-search`）冷启动建开头库；之后同类产品复用，不重复搜。

---

## 5. 与 IP 流程的本质区别（一图速记）

| 维度 | IP 流程 | 投流操盘手 |
|------|---------|-----------|
| 核心资产 | 人物稀缺性 | 产品/服务卖点·痛点·方案 |
| 目标 | 立信任、长期资产 | 接流量、转化、ROI |
| 结尾 | 关注/私信/立人设 | 引流钩子（无钩子=浪费） |
| 合规 | 内容合规 | 广告合规（更严） |
