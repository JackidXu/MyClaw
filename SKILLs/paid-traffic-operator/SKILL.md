# 投流操盘手（paid-traffic-operator）

> 独立的内容生产 Skill，专门制作「信息流投放 / 投流视频」文案。6 步同创流程，产出旁白视频式投流脚本。可借 IP 包能力，但不挂在 IP 流程里。

---

## 1. 触发词

- `投流视频` / `投流文案` / `信息流投放脚本`
- `帮我写个投流视频` / `做个投放脚本`
- `投流开头` / `投流钩子` / `投流结尾怎么写`
- `这个产品投流怎么打` / `投流卖点文案`
- `引流视频脚本` / `广告视频文案`

---

## 2. 核心定位

**不是 IP 内容生产的延伸，而是一条独立的产品/服务导向投放链路。**

IP 流程的核心是「人」——立人、立信、立言，靠人物的稀缺性做信任。投流视频的核心是「产品/服务」——靠卖点、痛点、解决方案、案例、引流钩子把流量接住并转化。两者逻辑不同，所以本 Skill **不依赖 IP 档案**，只在「客户已有 IP 档案且产品相关字段可用」时**可选借**。

**本 Skill 解决一件事**：把「一个要投流的产品/服务」变成「一条能投、能转化、合规无风险的旁白视频脚本」。

**核心公式**：

```
投流脚本 = 开头库(Step2) + 痛点(Step3) + 解决方案(Step4) + 案例信任状(Step5) + 引流结尾(Step6)
         → 按「选择结论 + 理由链 + 证据画面」组装成旁白视频式脚本
```

**与 IP 流程的本质区别**：

| 维度 | IP 流程（内容生产Skill包） | 投流操盘手 |
|------|--------------------------|-----------|
| 核心资产 | 人物的稀缺性（经历/精神/故事） | 产品/服务的卖点·痛点·方案 |
| 目标 | 立信任、养粉丝、长期资产 | 接流量、转化、短期 ROI |
| 人群 | 三层靶子（主/副/种草）偏人设共鸣 | 加定语到「一个会买单的人」 |
| 结尾 | 关注/私信/立人设 | 引流钩子（1元/9.9元），无钩子=流量浪费 |
| 合规 | 内容合规（红线/限流） | 广告合规（广告法/平台审核/引流风险）更严 |

---

## 3. 与 IP 包的借用边界（重要）

本 Skill 独立运行，但可按需借用同 skill 包里的其他模块（如 content-ip-manager、content-material-library 等）里的成熟模块。**借用时必须过滤——只借产品/服务相关字段，不借人物稀缺性素材。**

| 处理 | 借什么（来自 IP 包） | 怎么借 |
|------|---------------------|--------|
| ✅ **借（产品相关）** | `content-ip-manager`：业务资料库（产品清单/卖点/服务流程/差异化）、三层靶子（人群）、业务性感（痛点拆解/方案拆解/结果承诺）、客户案例（**仅产品相关案**） | 若工作区已有该客户 IP 档案 → 自动读「产品相关」字段做预填草稿；无则走轻量产品采集（§5 Step1） |
| ⚠️ **默认不借** | 故事弹药库（偏人经历）、精神内核、置顶定调、人物感性 | 投流是产品/服务导向，人的稀缺性素材**不进投流脚本** |
| ✅ **借（方法论）** | `content-script-writer/references/旁白视频-methodology.md`：选择结论+理由链+证据画面 | 组装成品脚本时套用（见 references/投流脚本格式.md） |
| ✅ **借（润色）** | `qu-ai-wei`：51 条 AI 腔模式 + 口播强化层 | 终稿去 AI 味（见 §5 组装步骤） |
| ✅ **借（合规，蒸馏版）** | `content-quality-guard`：广告法/平台规则/风险 | 已蒸馏为 `references/投流合规清单.md`，本 Skill 自带，不依赖 quality-guard 是否安装 |

> **借用纪律**：凡从 IP 档案读取的内容，标注「来源：IP档案·业务资料库」等；凡本 Skill 自行采集的，标注「来源：本次对话」。产品相关案例才进投流，人物故事案例默认排除（除非客户明确说这个人的故事就是产品信任状）。

## 4. 输入

### 必需

| 输入 | 说明 | 工作模式 |
|------|------|---------|
| **产品/服务** | 要投流的是什么（名称+解决什么问题+怎么收费） | Step1 采集或借 IP 档案 |
| **目标人群** | 这条投流打谁（有 IP 档案则借三层靶子，无则现采） | Step1 |
| **投流目的** | 加私域 / 成交 / 其他（影响 Step6 结尾设计） | Step6 前置确认 |

### 可选（增强质量）

| 输入 | 来源 | 用途 |
|------|------|------|
| IP 档案（该产品客户） | content-ip-manager | Step1 预填产品相关字段 |
| 爆款开头种子 | 客户给 / 联网搜索工具（`browser` / `web-search`） | Step2 开头库冷启动 |
| 客户案例素材 | 客户 / IP 档案产品相关案 | Step5 信任状 |
| 引流钩子商品 | 客户给（1元/9.9元什么） | Step6 |
| 已投数据/反馈 | 客户后台 | 复盘优化（可选） |

## 5. 六步工作流

> **交互总原则**：编导模式为主。每步先出多版候选 → 客户选/改/合并 → 定稿。关键决策（Step4 方法论正确性、Step6 引流钩子）**必须客户明确确认**，不替客户拍板。

### Step1：定核心客户群体 / 核心痛点 / 核心卖点

**目标**：锁定「一个会买单的人」+ 他最痛的点 + 你最硬的卖点，产出 `投流Brief`。

**流程**：

1. **读 IP 档案（若有）**：检查工作区是否已有该客户 IP 档案。有 → 读「业务资料库 + 三层靶子 + 业务性感（痛点拆解/方案拆解）」做预填草稿，标注来源。
2. **无 IP 档案 → 轻量产品采集**（product-centric，不建人物档案）：
   - 要产品资料（手册/官网/链接/报价），提取产品清单+卖点+服务流程+定价。
   - 每条卖点必须配可验证证据（借 content-ip-manager 策略18 最硬证据追问：「有没有同行拿不出的数据？零投诉/零事故/XX国验证/XX专利？」）。
   - 挖产品侧痛点：从「痛点拆解」+ 原厂/竞品痛点（策略20：客户用原装/竞品时最受不了什么）。
3. **人群加定语做窄**（借三层靶子逻辑）：不是「企业老板」，是「年营收5000万+、团队50人+、正在转型的制造业老板」。窄到能一句话描述一个活人。
4. **产出 `投流Brief_{客户}_{产品}.md`**（模板见 §7）。

**输出**：投流Brief（人群 + 痛点 + 卖点三件套，每条卖点带证据）。

---

### Step2：建立爆款开头库（蒸馏方法论 → tailored 开头）

**目标**：建一个「按产品持久化」的爆款开头参考库，并产出 3-5 条适配本产品卖点×痛点的 tailored 开头。

**流程**：

1. **判断库是否已存在**：检查 `references/爆款开头库_{产品标识}.md`（产品标识用产品名/品类，同类产品可共用）。
2. **首次冷启动（库不存在）**：
   - 用 联网搜索工具（`browser` / `web-search`） 搜「该产品/服务 + 目标人群 + 平台（抖音/小红书/视频号）」的爆款视频开头，整理 N 条真实参考（标题/开头句/为什么抓人）。
   - 蒸馏成「开头方法论 + 分类模板」（悬念/数字/反差/提问/场景，见 `references/爆款开头库模板.md`）。
   - 写入 `references/爆款开头库_{产品标识}.md`，标注来源 URL + 日期。
3. **复用（库已存在）**：同产品/同人群直接复用；**仅当产品/人群变更时**才重新通过 联网搜索工具（`browser` / `web-search`） 扩充。一款产品一个库，同类可共用。
4. **产出 tailored 开头**：按 Step1 的卖点×痛点，从库里检索+改写，出 **3-5 条** 不同钩子类型的开头句（每句完整口播句，不是「用XX开头」）。
5. **与客户同创**：客户选/改/合并，定稿 1 个主开头（投流前 3 秒决定划走率）。

**输出**：爆款开头库（持久）+ 本次 3-5 条 tailored 开头 → 定稿 1 个。

> ⚠️ **不靠 AI 实时扒 300 条**：库是「方法论+分类模板+种子案例」的蒸馏体，300 是目标体量不是一次性硬采。每项目累积，越用越厚。

---

### Step3：输出多版痛点描述（同创选优）

**目标**：把 Step1 的核心痛点，写成多版不同角度的口播文案，与客户同创出最准的那版。

**流程**：

1. **基于 Step1 痛点**，出 **3+ 版** 不同角度文案：
   - 情绪型（"你有没有那种……"戳焦虑）
   - 场景型（"半夜三点，客户站在你门口……"画面感）
   - 算账型（"一天多花 11 万，一年白扔几千万"绝对值冲击）
2. **与客户同创**：客户选最像目标人群真实状态的、或合并几版优点，定稿痛点描述。
3. **过转化三刀**（借 content-script-writer）：追问「所以呢」把痛点追到客户能感知的损失；换主语「我→你」；配可感知结果。确保痛点是从客户视角讲，不是自嗨。

**输出**：痛点描述定稿（写入 Brief 或独立片段）。

---

### Step4：输出多版客户解决方案（用户独有方法论，必须确认）

**目标**：把客户「自己独有的解决方法论」挖清楚，再针对核心痛点出多版方案文案，必须确认方法论正确、细节清楚。

**这是最关键的一步——方案必须是客户独有，不是通用套路。**

**流程**：

1. **先挖方法论（借 content-ip-manager 挖独门方法逻辑）**：
   - 多轮追问：「你给客户解决 XX 问题时，你的具体步骤跟别人有什么不同？」「你的独门心法是什么？」「客户在你这和别家体验的最大不同？」
   - 挖到步骤/心法/差异化/适用条件，存 `references/解决方案方法论库_{客户}.md`（模板见 references）。
   - **不挖清楚不写方案**——通用方案没有转化力。
2. **出多版方案文案**：针对 Step1 核心痛点 + 挖到的独有方法论，出 **3+ 版** 解决方案口播（角度/详略/语气不同）。
3. **必须与客户确认**：
   - 「这个方法论我理解对不对？步骤是 A→B→C 吗？」
   - 「细节有没有遗漏？客户实际操作时最关键的那一下是什么？」
   - 客户确认无误后，同创定稿。方法论错了/细节不清 → 退回追问，不将就。
4. **过转化三刀**：方案段落到「客户能得到什么」买点。

**输出**：解决方案方法论库（持久）+ 方案文案定稿。

> ⚠️ **红线**：方案文案不得编造客户没有的方法论。挖不到独有方法 → 如实问客户，不从通用模板编。

---

### Step5：挑选客户案例作信任状

**目标**：用 1-3 个最硬的案例，把「方案有效」变成可验证证据。

**流程**：

1. **选案例来源**：
   - 优先：IP 档案里「产品相关」客户案例（过滤掉纯人物故事）。
   - 无则：客户现给 / 新建投流案例库（本次对话采集）。
2. **还原成交现场级**（借 content-ip-manager 策略11）：每个案例还原到「触发事件→客户情绪反应→关键转折→结果」，不是一句概括。
3. **挑 1-3 个最硬**：选证据最强（有数据/有原话/有前后对比）的，作理由链里的「证据画面」。
4. **事实标注**：案例数据标 🟢事实（有出处）/ 🔴需验证（发布前核实）。

**输出**：案例信任状定稿（1-3 个，现场级）。

---

### Step6：合规引流结尾（目的 + 钩子，必须共创）

**目标**：设计符合平台规则、能承接流量的结尾 + 引流钩子。无钩子=流量无承接。

**流程**：

1. **先问目的**（前置确认）：这条投流想达到什么？
   - 加私域（引流加微信/企微）
   - 成交（直接卖/留资等销售跟进）
   - 其他（品牌/活动）
   - 目的不同 → 结尾 CTA 与钩子设计不同。
2. **设计引流钩子（必须共创）**：
   - 钩子商品**由客户给**（1 元资料包 / 9.9 元体验装 / 免费诊断表…）。
   - 用 `references/钩子类型库.md` 辅助共创：列可选钩子类型，客户选/定具体商品。
   - **无钩子不交付结尾**——流量再大没东西接住就浪费。若客户没有现成钩子商品，引导客户想一个低门槛承接品（资料包/体验装/诊断），不替客户虚构。
3. **写合规结尾**：结尾文案 + CTA + 钩子呈现，过 `references/投流合规清单.md`：
   - 广告法禁用词（最/第一/绝对/根治/100%…）→ 替换
   - 平台引流雷区（外链/二维码/硬导流措辞）→ 合规表达
   - 风险审查（虚假承诺/绝对化保证/行业特殊禁词）
4. **客户确认结尾 + 钩子** → 定稿。

**输出**：引流结尾 + 钩子定稿 + 合规自检通过。

---

### 组装：旁白视频式投流脚本

**目标**：把 6 步产物组装成一条可拍摄的旁白视频脚本。

**组装规则**（借 `content-script-writer/references/旁白视频-methodology.md`，详见 `references/投流脚本格式.md`）：

```
选择结论（一句话：看完这条视频客户该信什么）
  = Step4 解决方案的核心论点 / Step1 卖点转化后的买点
理由链（5-7 个，服务于同一结论）：
  ① 开头钩子（Step2 定稿）
  ② 痛点描述（Step3 定稿）
  ③~⑤ 解决方案（Step4 定稿，含独有方法论）
  ⑥ 案例信任状（Step5 定稿，证据画面）
  ⑦ 引流结尾（Step6 定稿，钩子）
证据画面：每句旁白配「客户看到什么」（产品/案例/数据画面）
```

**段落过渡（硬规则）**：6 步产物是「递进链」不是「拼盘」。每段末尾必须埋一个「启下钩子」自然引出下一段，每段开头用口语化连接词接住上一段（连接词库与四组桥接范式见 `references/投流脚本格式.md` §5 段落过渡规则）。组装后必过「过渡自检」：删掉连接词，上一句仍能引出下一句，否则补过渡。

**终稿去 AI 味**：口播文本过 `qu-ai-wei`（语体=内容/自媒体，口播强化层），附打磨报告。

**输出**：`投流脚本_{客户}_{产品}_{日期}.md`（见 §7 模板），含事实标注 + 合规自检 + 去AI味报告。

## 6. 交互模式

### 编导模式（默认·投流）
- 每步出多版候选，客户选/改/合并，关键决策必确认。
- Step4 方法论、Step6 钩子必须客户明确拍板，不替客户决定。
- 追问可到 3 轮，不一次性抛 20 问（借 content-ip-manager 打字减负：拆问题+给选项）。

### 老板模式（快速）
- 客户说「快点出」→ 每步直接推 1 个推荐版，客户微调。
- 仍保留 Step4 方法论确认、Step6 钩子确认（这两条不可跳）。

### 模式切换
- 「仔细打磨」→ 编导模式；「快速出」→ 老板模式。

## 9. 边界与禁止

### 做什么
- 把「一个产品/服务」变成「一条可投的旁白视频脚本」
- 每步多版同创，关键决策（方法论/钩子）必确认
- 借 IP 包产品相关能力，过滤人物素材
- 结尾合规 + 引流钩子承接

### 不做什么
- 不建 IP 档案（无则轻量产品采集，不强制建档）
- 不写人物故事型内容（投流偏产品，人物稀缺性不进脚本）
- 不进选题/规划/拍摄体系（独立链路）
- 不虚构客户方法论/案例/钩子商品

### 禁止
- 不替客户拍板方法论正确性（Step4 必须客户确认）
- 不交付无引流钩子的结尾（Step6 无钩子不交付）
- 不写广告法禁用词 / 平台违规引流表达
- 不把产品卖点写成自嗨（必须过转化三刀到买点）
- 不编造客户没有的案例数据（标🔴需验证，发布前核实）

## 10. 示例对话

**用户**：帮我给「超会AI 数字人获客」写个投流视频。

**AI**：好。先建投流Brief——你们这款产品核心打谁、最痛的点、最硬的卖点是什么？（有 IP 档案我先读产品相关字段）

**用户**：打实体店老板，痛点是不知道怎么用 AI 日更获客，卖点是数字人+AI脚本+全平台分发。

**AI**：（轻量采集，卖点配证据追问）「数字人+全平台分发」有没有可验证数据？比如做过哪个客户、涨了多少？
→ 读/采完，出 Brief。然后 Step2：这款产品有开头库吗？没有我先用 联网搜索工具（`browser` / `web-search`） 冷启动建一个，出 3-5 条 tailored 开头你选。
→ Step3 出 3 版痛点文案同创。Step4 挖你「独有解决方法论」——你帮客户做 AI 获客的具体步骤跟别家哪不同？挖清楚存方案库，出 3 版方案你确认。
→ Step5 挑案例作信任状。Step6 问目的+钩子：想加私域还是成交？钩子商品你给个（1元资料包/9.9体验装）？
→ 组装旁白视频脚本，过合规+去AI味，交付。
