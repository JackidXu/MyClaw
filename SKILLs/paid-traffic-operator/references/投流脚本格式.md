# 投流脚本格式（投流操盘手 · 组装支撑文件）

> 用途：把 6 步产物组装成一条可拍摄的「旁白视频式」投流脚本。
> 借用关系：组装骨架借 `content-script-writer/references/旁白视频-methodology.md`（选择结论+理由链 5-7+证据画面 1:1）。本文件说明「投流专用」怎么套。
> 配套使用：SKILL.md §5「组装：旁白视频式投流脚本」、§7 脚本模板。
> 若 IP 包未安装：本文件即内置组装规则，可直接用，不依赖旁白视频-methodology 是否可读。

---

## 1. 底层公式（同源旁白视频）

```
投流脚本 = 选择结论 + 理由链(5-7) + 证据画面(1:1)
```

- **选择结论**：看完这条视频，客户该信「一个」结论（通常是 Step4 方案的核心论点 / Step1 卖点转化后的买点）。
- **理由链**：5-7 个按次第排列的理由，全部服务于同一个结论。
- **证据画面**：每一句旁白都有对应画面作证（句画合一）。

> 与旁白视频-methodology 一致：**不是句句卖货，而是句句都为选择服务。**

---

## 2. 投流专用：理由链 = 6 步产物的映射

投流的理由链不是抽象编排，而是直接来自本次 6 步工作流：

| 链序号 | 来源 | 内容 | 时长 |
|--------|------|------|------|
| ① | Step2 定稿 | 开头钩子（最有冲击力理由句） | 0-3s |
| ② | Step3 定稿 | 痛点描述（客户视角，过转化三刀） | 3-15s |
| ③~⑤ | Step4 定稿 | 解决方案（含独有方法论，过转化三刀） | 15-50s |
| ⑥ | Step5 定稿 | 案例信任状（证据画面，现场级还原） | 50-55s |
| ⑦ | Step6 定稿 | 引流结尾（钩子 + CTA） | 55-60s |

> ⑦ 是投流相对纯旁白视频的「增量」：纯旁白视频结尾留记忆/行动入口即可，投流必须有**承接钩子**把流量接住。

---

## 3. 开头钩子的特殊判定

旁白视频-methodology 说：钩子=理由链里「最有冲击力」的那一句（数字冲击/反差对比/反直觉/场景画面感）。

投流开头（Step2 定稿）先按「5 类钩子」（悬念/数字/反差/提问/场景，见 `爆款开头库模板.md`）接住人；同时它必须也是理由链①——即开头那句本身要带一个真实理由（不是纯悬念标题党），正文才能兑现它。

> 不满足"钩子承诺正文能兑现" → 退回 Step2 重写（不标题党红线）。

---

## 4. 时长与段落组织

- 总时长建议 30-60s（信息流短、完播率优先）。
- 段落规则（借旁白视频-methodology §6）：
  1. 开头先放最有吸引力的理由（即钩子）。
  2. 多用数字、动作、场景、结果、选择——避免抽象形容词（"专业/领先/优质/靠谱"必须有证据）。
  3. 理由间自然推进，不跳跃。
  4. 每句只承担一个主要任务，不堆砌。
  5. 结尾留行动入口（钩子 CTA）。
- 证据画面占比：每句旁白 1:1 配对，无"无画面句"。

---

## 5. 段落过渡规则（投流加强）

> 投流脚本的流畅感不在单段写多好，而在段与段"接得顺"。6 步产物是递进链不是拼盘——每段接住上一段、引出下一段。

### 5.1 过渡三原则
1. **每段末埋启下钩子**：段落①~⑦ 结尾那句，自然抛"然后呢/怎么办/你看"的钩子，把观众推向下一段。
2. **每段首用口语连接词接上**：不用硬切，用"所以呢/其实/说白了/关键就在这/那问题来了"接住上一段情绪。
3. **递进不跳跃**：7 段全服务同一选择结论，一层推一层（痛点→方案→证据→行动）；删掉连接词上句仍能引出下句。

### 5.2 四组桥接范式（可填空）

| 过渡 | 桥接句范式 | 示例 |
|------|-----------|------|
| 开头→痛点 | 钩子抛反常 → "你有没有{同款困境}？/ 问题就出在{痛点}" | "…上个月到店多了40个新客。你有没有算过，你店里那个拍视频的活，一个月烧掉你多少？" |
| 痛点→方案 | 痛点戳完 → "那怎么办？/ 其实不用你{痛点动作}" | "…账号躺那不动，客人被同行截走。其实不用你出面——" |
| 方案→案例 | 方法讲完 → "这不是空话，{某客户}就是这么做的" | "…一天几条轻轻松松。像开头那家店，之前半年就发几条——" |
| 案例→结尾 | 证据亮完 → "你想不想也这样？/ 现在有个低门槛办法" | "…周边三公里刷到就是它。想知道你的店怎么起号？点主页——" |

### 5.3 过渡连接词库（口语化，避免书面硬转）
- 承接痛点：说白了 / 其实 / 说穿了 / 你品品
- 引出方案：那怎么办 / 关键就在这 / 我们拆开看 / 真正的做法是
- 引出证据：我不是空说 / 给你看个真的 / 就像{客户}
- 引出行动：想不想也这样 / 现在有个办法 / 你只需要一步

### 5.4 过渡自检（组装后必过）
- [ ] 删掉每段首句连接词，上一句能否自然引出下一句？不能→补启下钩子
- [ ] 每段是否接住上段+引出下段？有硬切→补过渡
- [ ] 7 段是否层层递进服务同一结论？跳脱段→重排或删

## 6. 事实标注（借 content-script-writer 四色）

每段落标事实状态，写入 §7 模板：

| 标记 | 含义 | 处理 |
|------|------|------|
| 🟢 事实 | 有证据的数据/事件 | 正常使用，画面展示证据 |
| 🟡 判断 | 客户主观观点 | 正常使用，是价值所在 |
| 🟠 推测 | 合理推断无直接证据 | 加"我判断"等限定 |
| 🔴 需验证 | 待核实 | 列事实核验清单，发布前必核 |

**纪律**：宁严勿松；客户观点不标 🟢；含数字/结论的开头标 🟢或🔴。

## 7. 校验规则（借旁白视频-methodology §9，投流加强）

| # | 检查 | 通过标准 |
|---|------|----------|
| 1 | 只证一个结论？ | 7 个理由都服务同一结论 |
| 2 | 产品信任还是人物信任？ | 投流=产品/服务信任，人物稀缺性不进 |
| 3 | 每理由与选择有关？ | 砍无关理由 |
| 4 | 理由有无重复？ | 本质同则合并 |
| 5 | 有真实证据？ | ≥3 理由配具体证据 |
| 6 | 每句有画面？ | 1:1，无无画面句 |
| 7 | 高冲击有可核实证据？ | 红线：无证据不夸张 |
| 8 | 结尾有钩子承接？ | 投流增量：无钩子不交付 |
| 9 | 过合规清单？ | `投流合规清单.md` 四项全 ✅ |
| 10 | 去过 AI 味？ | qu-ai-wei 口播强化层通过 |
| 11 | 段落过渡顺滑？ | 删连接词上句仍能引出下句（§5） |

---

## 8. 红线（汇总）

- 高冲击表达无证据 → 禁（借旁白视频红线）。
- 标题党（钩子正文不兑现）→ 禁。
- 人物故事进投流脚本 → 禁（产品/服务导向）。
- 无引流钩子交付结尾 → 禁。
- 广告法禁用词 / 平台违规引流 → 禁（过 `投流合规清单.md`）。
- 编造客户方法论/案例/钩子 → 禁。
- 段落硬切、无过渡拼盘 → 禁（过 §5 过渡自检）。
