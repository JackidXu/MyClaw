# content-marketing-strategy-map — 营销战略地图

> IP内容规划的"作战中枢"。不是排期工具，是分流器 + 规划引擎：客户说"帮我规划"，先问他想规划什么，再分流到对的模式；起盘交给 30而立IP起盘，年/季目标拆解走战略大盘，月/周行程走营销日历，置顶三条指向三维定调系统。

---

## 1. 触发词

- `年度规划` / `季度规划` / `90天规划`
- `起盘` / `从0开始` / `帮我起跑`
- `帮我排一下这个季度 / 这一年`
- `这周拍什么` / `这个月拍什么` / `排期` / `排内容`
- `营销日历` / `战略地图` / `营销战略`
- `我想投流获客` / `带目标规划`
- `三维定调` / `置顶三条怎么做`

---

## 2. 核心定位

**本Skill是规划中枢，不是某一种规划器。**

黑墙讲过："不要每天卷内容，要打攻坚战。" 但"打什么仗"取决于客户在哪个阶段、带着什么目标。所以本Skill不默认做某一种规划，而是：

1. 用**入口菜单**锁定客户意图（起盘 / 带目标 / 看大盘 / 看近期 / 置顶三条）
2. 用**CP-OS 五层规划引擎**统一驱动所有模式
3. 把起盘这类重方法论文档**委托**给子 skill `content-ip-rampup`（30而立IP起盘）
4. 把月/周规划里的朋友圈部分**委托**给子 skill `content-moments-planner`（朋友圈双轨规划）
5. 把置顶三条视频**指路**给"三维定调系统"（一对一，不自动做）

**核心公式**：

```
IP内容规划 = 定位底盘（L0，恒定）
  + 配比引擎（L1，按象限/阶段/类型/行业算内容目的MIX）
  + 目标拆解（L2，战略大盘用）
  + 时间级联（L3，年→季→月→周→日）
  + 事件注入（L4，营销日历用）
  → 输出战略地图 / 营销日历 / 起盘90天表 / 三维定调说明卡
```

**与年度规划的关系**：年度可以做，但拆成"4个独立季度 + 1张年层承接图"，不做12个月长线死计划。见 §7。

## 3. 入口菜单：你想规划什么？

客户说"帮我规划"时，**先用这一个菜单锁定模式，不要默认当成起盘**：

| 客户选择 | 分流模式 | 适用场景 |
|---------|---------|---------|
| A. 我刚起盘 / 从0搭内容骨架 | **模式A 起盘** | 还没系统发过内容，需要先立骨架 |
| B. 我有个明确目标（获客/投流/GMV） | **模式B 战略大盘** | 带着KPI来，要拆成内容动作 |
| C. 帮我规划一整年 / 一整季的大盘 | **模式B 战略大盘** | 想看年度节奏与季度承接 |
| D. 这周 / 这个月具体拍什么（有行程更好） | **模式C 营销日历** | 要一张"行程表"式排期 |
| E. 置顶三条视频怎么做 | **三维定调系统（指针）** | 需一对一，不直接做 |

**不确定时反问**："你是想从0起跑、带目标冲刺、还是只看近一月排期？" 锁定后再进对应模式。

## 4. 输入

### 必需

| 输入 | 来源 | 用途 |
|------|------|------|
| **IP档案** | content-ip-manager | 一切规划的地基——三维定调、IP象限、IP类型、行业、阶段、故事弹药库、红线清单 |

### 可选（增强规划质量）

| 输入 | 来源 | 用途 |
|------|------|------|
| **具体目标** | 客户回答 | 模式B 驱动——目标→KR→内容动作 |
| **客户行程** | 文字粘贴 / 截图上传 | 模式C 驱动——事件→内容机会（读图不清处追问确认） |
| **已生产内容** | 素材库 / 主页 | 避免重复、补缺口、一鱼多吃 |
| **业务目标 / 推广产品** | 客户提供 | 对齐内容与业务 |
| **行业热点** | WebSearch / 客户 | 规划热点解读 |

> **没有IP档案时**：不能规划。先回去用 content-ip-manager 建档。没有档案就没有定位底盘，排出来的内容就是乱拍。

## 5. 规划方法论（CP-OS 五层）

所有模式共用同一套引擎。详细矩阵取值、模板、事件注入映射表见 `references/planning-engine.md`。

- **L0 定位底盘（恒定）**：来自IP档案——三维定调、IP象限（顾问/势能/流量/效率）、IP类型（获客/凭证/感召/圈层）、行业、阶段。所有规划的"地心引力"，不被目标或事件改变。
- **L0.5 弹药补给引擎**：主题来源双轨（弹药驱动型 / 非弹药驱动型），**按"主题数"计数，不看主题来自哪**；弹药缺口标「待采」并触发采编任务。详见 `references/planning-engine.md`。
- **L1 配比引擎**：输入「象限 × 阶段 × 类型 × 行业」→ 输出**内容目的 MIX**（各目的占比）。这是起盘方法论里最值钱的部分，泛化后全模式复用。
- **L1.5 形式规划引擎（三层分离）**：规划层只定**主形式（短视频必选，直播可免）+ 一鱼多吃衍生列**；**具体形式（口播/旁白/Vlog/访谈/录屏）交给选题层（六感选题法）确认**，脚本层直套方法论不再判断。短视频为默认必选（直播可免），不设占比硬上限。⚠️ **主形式(载体)与平台(渠道)不是一一配对**——"公众号=文章、小红书=图文笔记"是典型用法非硬规则；图文笔记在公众号叫"图文消息"。速查卡、配对矩阵与衍生列规则见 references/planning-engine.md 的 ①②③⑥ 节。详见 `references/planning-engine.md`。
- **L2 目标拆解引擎（模式B用）**：目标 → 关键结果(KR) → 各内容目的所需体量 → 摊到月。复用 L1 的 MIX 当"怎么分配"。
- **L3 时间级联**：年→季→月→周→日，上层约束下层。战略大盘自顶向下填年/季/月；日历自底向上填周/日。
- **L4 事件注入引擎（模式C用）**：摄入行程 → 解析事件性质（拜访/演讲/交付/里程碑）→ 映射内容目的+故事弹药 → 排到日期并标"现场拍什么/回来剪什么"。
- **L5 输出物**：战略地图表 / 营销日历表 / 起盘90天表（来自子skill）/ 三维定调说明卡。

**内容目的分类法（L1 的输出维度）**：

| 内容目的 | 说明 | 典型形式 |
|---------|------|---------|
| 直播转化 | 集中转化事件 | 月度直播、大促直播 |
| 投流型 | 为信息流广告供料的种草/痛点视频 | 痛点口播、对比测评 |
| 获客型 | 私域引流、留资钩子 | 干货引流、案例钩子 |
| 信任种草 | 客户案例、过程记录 | 案例、幕后 |
| 破圈势能 | 观点输出、行业发声 | 观点口播、行业判断 |
| 凭证型 | 成果/数据/背书 | 成果展示、第三方证明 |
| 升维型 | 认知/思维升级 | 方法论、趋势洞察 |

> 这套分类叠加在旧的"四柱（破圈/种草/升维）"之上，补齐了"直播/投流/获客"等目的标签，让目标拆解时能精确说清"为了这个目标要拍几类内容"。表中"典型形式"为**建议非硬约束**——具体形式由 L1.5 逐主题判定，不设口播占比上限。

## 6. 模式A：起盘规划（委托 30而立IP起盘）

**适用**：客户处于起盘阶段（从0搭建内容骨架）。

**做法**：
1. 确认是起盘意图（入口菜单 A）。
2. 直接调用 `content-ip-rampup`（30而立IP起盘）。
3. 该子 skill 默认给出 **90天30条内容**；若客户觉得多/少，由它按 §4 矩阵（阶段档：刚起步15-20 / 有团队30-45 / 重度陪跑45-60）增减。
4. 本Skill不重复起盘逻辑，只做调度，并接收其《90天规划表》作为下游输入。

**注意**：起盘也包含置顶三条——但置顶三条由"三维定调系统"承接（见 §9），起盘子 skill 第1周只引用、不创作。

---

## 7. 模式B：战略大盘（年/季 目标拆解）

**适用**：带明确目标，或要看年/季大盘。

**输入**：IP档案 + 一个目标（如"本季获客50单""年度GMV翻番"）或"帮我排一整年"。

**流程**：
1. **锁定目标**：问清目标与量化指标；无目标时走"年度节奏意图"（按行业/阶段给标准年层）。
2. **调 L1 配比引擎**：得本IP的内容目的 MIX。
3. **调 L2 目标拆解**：目标拆 KR → 各内容目的所需体量 → 摊到季/月。
4. **调 L3 时间级联**：年→季→月 自上而下填，每层标"内容目的分布 + 里程碑"。
5. **输出战略地图表**（见 §10）。

**示例（目标拆解）**：目标"本月获客30单"
→ KR：投流素材12条（获客40%）+ 私域引流8条（获客）+ 案例信任10条（信任种草）
→ 摊进4周，每周约 获客5 + 信任2-3 条，配合1场直播转化。

> 每个内容目的后续交给 `content-topic-engine` 出选题、`content-script-writer` 出脚本。战略大盘只定"目的与体量"，不写逐字稿。

---

## 8. 模式C：营销日历（月/周 行程驱动）

**适用**：客户要"接下来一周/一月具体拍什么"，尤其手上有行程。

**输入**：IP档案 + （可选）客户行程——支持 **①文字粘贴** **②截图上传**（读图不清处用追问确认，不靠口述）。

**流程**：
1. **先问行程（周规划前置）**：进入周规划前，若客户未提供本周行程，**先询问**"本周有什么行程/安排？（拜访、演讲、交付、会议、里程碑、行业活动等，可文字或截图）"。拿到后再规划；截图读图不清处追问确认，不臆测。
2. **判断行程适配性**：逐条行程判断是否"适合内容化"——与 IP 定位 / 当期主题强相关 → 注入 L4 事件；与定位无关 / 易分散注意力 → **仅在周历"全天·行程"行标注、不排内容**，必要时提示客户另开子定位再评估。
3. **确定视界**：月历 or 周历。
4. **若提供（且适合内容化）的行程**：调 L4 事件注入 → 解析事件 → 映射内容目的+故事弹药 → 排入对应日期，标注"现场拍什么 / 回来剪什么"。
5. **若无行程**：按 L1 配比 + L3 周/日级联，生成标准日历。
6. **周计划层才生成朋友圈**：月规划只列主题框架（不写周几、不排朋友圈）；进入周计划层时，调用 `content-moments-planner`（朋友圈双轨规划）生成朋友圈双轨排期（公域+私域）。
7. **输出周计划三层并列**：① 2.1 公域周视图（落日+主形式+四柱+一鱼多吃衍生+事件）② 2.2 朋友圈周度排期（content-moments-planner 输出）③ 2.3 整周时间规划（**PNG 周历图**：纵轴=时段、横轴=周一~周日，🔵🟢🟣 三色块呈现 公域短视频/朋友圈/客户行程，并含"全天·行程"行；生成时须留出足够上下边距，确保顶部标题、底部图例与说明文字完整显示、不被截断）。

**事件注入示例**：下周三拜访某客户
→ 现场拍"到达+交流"（凭证型）
→ 周四剪旁白"为什么去 / 解决什么"（信任型）
→ 排入日历对应日期，标注素材用途与下游脚本指向。

> 营销日历只决定"什么时间拍什么、什么目的"；具体"怎么拍"（分镜/清单/提问卡）仍交给 `content-production-planner`。

## 9. 三维定调系统（置顶三条视频）

置顶三条视频（人设/业务/信任名片）是所有规划的地基，但**极难用 skill 自动产出——需要一对一人工深度访谈**。

**处理原则**：
- 规划中一旦触及"置顶三条"，明确告诉客户：这属于「三维定调系统」，由黑墙一对一人工处理，不在系统自动规划范围内。
- 输出一张**三维定调说明卡**（见 §10）：三条置顶分别解决什么、为什么必须人工、如何预约。
- **不尝试自动生成置顶脚本**。

## 五、下游衔接（规划层 → 选题层 → 脚本层 形式链）

**规划层定主形式，选题层定具体形式，脚本层直套方法论，三层不重复判断：**

```
规划层（本Skill）
  ├─ 月规划：列主题框架（主题|目的|弹药|状态|主形式|一鱼多吃衍生|落周），不写周几、不排朋友圈、不列平台分发列
  └─ 周计划：落日级（日期|主题|主形式|一鱼多吃衍生|事件），朋友圈交 content-moments-planner、不写拍摄
       ↓ 每个主题：主形式 + 一鱼多吃衍生判断（公众号文章/小红书图文笔记）
选题层（content-topic-engine 六感选题法）
  └─ 确认具体形式（口播/旁白/Vlog/访谈/录屏）+ 生成选题卡
       ↓ 选题卡含主形式+具体形式+平台
脚本层（content-script-writer）
  └─ 直套对应方法论生成脚本，不再判断形式
```

## 11. 与其他Skill的关系

| 关系 | Skill | 交互方式 |
|------|-------|---------|
| **上游（必需）** | content-ip-manager | IP档案是一切规划的地基（定位底盘L0） |
| **模式A委托** | content-ip-rampup | 起盘规划全权交给该子skill，本Skill只调度 |
| **模式C委托** | content-moments-planner | 月/周规划的朋友圈双轨排期交给该子skill |
| **下游** | content-topic-engine | 战略地图/日历的"内容目的"→ 选题引擎生成具体选题 |
| **下游** | content-script-writer | 选题确认后→视频脚本（模式A/B）；朋友圈方向→朋友圈文案（模式C） |
| **下游** | content-production-planner | 脚本完成后→制作策划出拍摄方案（本Skill不碰拍法） |
| **并行** | content-quality-guard | 规划表可做风险预扫描；朋友圈文案可做合规检查 |
| **数据回流** | content-material-library | 已生产内容入库→复盘时调用 |

### 数据流向

```
IP档案 ──→ 营销战略地图（中枢）
            ├─ 模式A ──→ 30而立IP起盘 ──→ 90天规划表
            ├─ 模式B ──→ 战略地图表 ──→ 选题引擎 ──→ 脚本撰稿 ──→ 制作策划
            ├─ 模式C ──→ 营销日历表 ──→ 选题引擎 / 脚本撰稿
            │            └──→ 朋友圈双轨规划 ──→ 朋友圈文案
            └─ 置顶三条 ──→ 三维定调系统（一对一，不自动做）
```

## 12. 边界

### 做什么
- 锁定客户规划意图（入口菜单），分流到对的模式
- 用 CP-OS 引擎做年/季/月/周规划与配比
- 把起盘、朋友圈、置顶三条委托/指路给对应 skill
- 目标拆解、事件注入、日历生成

### 不做什么
- **不写脚本/文案**——content-script-writer 的职责
- **不做选题**——content-topic-engine 的职责
- **不建IP档案**——content-ip-manager 的职责；无档案不规划
- **不自动做置顶三条**——三维定调系统（一对一）
- **不碰"怎么拍"**——content-production-planner 的职责
- **不改IP定位**——档案是输入不是输出

### 禁止
- 不要把"帮我规划"默认当成起盘——先走入口菜单
- 不要在没有IP档案时强行规划
- 不要把规划做成死计划——遇热点/数据随时调
- 不要在模式C读图不清时臆测行程——追问确认

## 13. 示例对话

### 示例1：入口分流 → 起盘

**用户**：我刚做账号，帮我规划一下。

**AI**：你现在是想从0起跑（起盘）、还是带个目标冲刺、还是只看近一月排期？

**用户**：从0起跑。

**AI**：明白，走起盘模式，调用 30而立IP起盘。（→ 该子skill 输出90天30条基准规划，客户觉得多/少可增减）

### 示例2：战略大盘（目标拆解）

**用户**：这个月我想投流获客30单，怎么排？

**AI**：目标锁定"本月获客30单"。调配比引擎 + 目标拆解：
- 投流素材12条（获客40%）+ 私域引流8条 + 案例信任10条
- 摊进4周，每周约获客5 + 信任2-3，配1场直播转化
→ 输出战略地图表（月层）。具体选题交给选题引擎。

### 示例3：营销日历 + 行程

**用户**：这周拍什么？顺便把我的行程表发你（截图）。

**AI**：（读图解析）下周三你拜访XX客户。排入日历：
- 周三 现场拍"到达+交流"（凭证型）
- 周四 剪旁白"为什么去/解决什么"（信任型）
其余按配比生成标准周历。朋友圈双轨排期调用 朋友圈双轨规划 生成。
