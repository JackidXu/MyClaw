# content-performance-review — 数据复盘官

> 内容发布后的效果闭环。把平台数据回收进来，验证三维定调 / 六感 / 一鱼多吃 / 配比这套方法论到底灵不灵，再把结论反哺回选题、脚本和战略地图。

---

## 1. 触发词

- `复盘一下`
- `看看数据`
- `效果复盘`
- `这个月数据怎么样`
- `月度复盘`
- `数据怎么样了`
- `帮我复盘这个月`

---

## 2. 核心定位

**不是"数据看板"，而是"方法论验证 + 上游反哺器"。**

内容生产全流程（建档 → 规划 → 选题 → 脚本 → 拍摄 → 素材）跑完之后，发布的数据一直没有回流——哪根子枝留人、哪种钩子有效、配比对不对，全凭感觉。本 Skill 补上这个闭环：

1. **回收数据**：从平台后台把已发布视频的表现拉进来（CSV 导入 / 手动录入双入口）
2. **回填标签**：把每条视频关联到三维定调的子枝、六感、钩子类型、视频类型、信息/信任型
3. **验证方法论**：用真实数据看哪套打法有效、哪套失灵
4. **反哺上游**：把结论变成选题引擎的加权、脚本的钩子模板、战略地图的战役配比

**横切定位**：本 Skill 不生产内容，只消费数据 + 指挥上游。当前以用户主动触发为主（独立运行任意周期复盘）；规划上预留由 `content-marketing-strategy-map`「月底复盘·战役效果评估」步骤调用的接口（待接入）。

---

## 3. 输入与输出

**输入**
- 平台数据（双入口，见 `references/data-import.md`）：CSV 文件 或 手动逐条录入
- IP 档案（`IP档案_{客户}_V1.md`，必需）：用于映射子枝/六感与信任·信息配比基准
- 当月战役卡 + 已发布选题卡（`选题卡_{客户}_{选题}.md`）：用于回填方法论标签
- 常备选题库（`常备选题库_{业务}.md`，来自 `content-topic-engine` §8）：用于把已发布视频**回链到常备条目**，回填「状态 / 上次打的内容任务 + 日期」，并校验"重复打换任务"铁律

**输出**
- `数据档案_{客户}.md`：跨月累积的视频表现记录（含回填标签），下次复盘自动追加
- `复盘报告_{客户}_{YYYYMM}.md`：当月复盘结论（仪表盘 + 归因 + 反哺清单）
- 反哺清单（内嵌于报告，同时可作为选题/脚本/战略地图的下次输入）

## 4. 与营销战略地图的衔接

`content-marketing-strategy-map` 的「月底复盘·战役效果评估」步骤（待接入）→ 调用本 Skill：

```
战略地图（月底复盘）
  → 读取当月战役卡 + 数据档案 + 常备选题库
  → 调用 content-performance-review
  → 生成 复盘报告_{客户}_{YYYYMM}.md
  → 反哺清单回写战略地图下月战役卡
  → 常备条目回填建议回写 常备选题库（状态/上次打的任务+日期）
```

本 Skill 不重复做规划，只负责「数据 → 分析 → 反哺」。战略地图保留规划职责。

## 5. 执行流程

```
读取: references/data-import.md
```

按 `data-import.md` 完成 **步骤① 数据导入** 与 **步骤② 回填关联**，得到标准化的 `数据档案_{客户}.md`。

```
读取: references/analysis-framework.md
```

按 `analysis-framework.md` 完成 **步骤③ 效果分析**（仪表盘 + 最优 TOP3 归因 + 最差归因 + 跨维度对比 + 战役卡目标达成度）。

```
读取: references/feedback-rules.md
```

按 `feedback-rules.md` 完成 **步骤④ 反哺建议**（选题引擎 / 脚本撰稿 / 战略地图三端），并 **步骤⑤ 输出复盘报告 + 更新数据档案**。

**步骤④补充 · 常备选题库回填闭环**（仅当输入含 `常备选题库_{业务}.md` 时执行）：
1. **回链**：把每条已发布视频按其「常备条目回链」字段，对应到常备库条目，在 `数据档案` 中标注。
2. **回填建议**：在反哺清单里输出「常备条目回填建议」——该条目已发布，建议状态改为 `已拍第 N 版`、填写 `上次打的内容任务 + 日期`，由上游（用户 / topic-engine / script-writer）回填进常备选题库。
3. **重复打铁律校验**：扫描同一常备条目是否出现「重复打标记=同任务重复⚠️」（同内容任务被打 2 次且无新案例）。若出现 → 在报告标红警告，反哺 script-writer 模式E（下次同条目必须换任务或换支撑案例，否则等于白拍，见 topic-engine §8「重复打」定义）；若该条历史数据表现好，注明"同题型可继续复用"供上游判断。

**五步总览**

| 步骤 | 名称 | 关键产出 |
|------|------|---------|
| ① | 数据导入 | 标准化单条视频记录 |
| ② | 回填关联 | 带方法论标签的数据档案 |
| ③ | 效果分析 | 仪表盘 + 归因 + 跨维度对比 |
| ④ | 反哺建议 | 三端加权/调整清单 |
| ⑤ | 输出报告 | 复盘报告 + 档案更新（闭环） |

## 6. 数据档案结构

`数据档案_{客户}.md` 每条记录格式：

```markdown
## 记录 · {发布日期} · {标题}
- 平台：抖音 / 视频号 / 小红书
- 指标：播放 {n} · 完播率 {x%} · 点赞 {n} · 评论 {n} · 转发 {n} · 收藏 {n} · 涨粉 {n}
- 关联选题卡：{文件名 或 无}
- 方法论标签：
  - 主枝：人物感性 / 业务性感 / 信任背书
  - 子枝：{18子枝之一}
  - 六感：{痛/手/温/证/鲜/悟}
  - 钩子类型：{悬念/结果前置/反差/提问/共鸣/…}
  - 视频类型：{11种之一}
  - 内容型：信息型 / 信任型
  - 内容任务：{看得准 / 有解法 / 做得到 / 信得过 之一}（来自常备条目「内容任务」，无对应常备条目则"待标注"；与子枝互补——子枝是三维定调细粒度，内容任务是业务选题四组粗粒度）
  - 常备条目回链：{常备#X / 无}（回链到 `常备选题库_{业务}.md` 的条目，用于回填状态）
  - 重复打标记：{首打 / 换任务重打(上次任务：XXX·日期：XXX) / 同任务重复⚠️（未换任务也未换案例）}
- 数据来源：CSV导入 / 手动录入 / 待标注
```

跨月累积，新记录追加在文末，不覆盖历史。

## 7. 前置与注意事项

1. **无 IP 档案则降级**：没找到 `IP档案_{客户}_V1.md` 时，先提示用户建档案（或最小补档），否则子枝/六感映射会失真。
2. **选题卡缺失可 fallback**：无对应选题卡时，按标题模糊匹配；都失败则引导用户从 18 子枝中选 1 个，其余标"待标注"，不卡流程。
3. **数据真实性**：所有指标以用户导入的后台数据为准，不估算、不美化。完播率缺项则跳过该指标，不拿播放量冒充。
4. **归因要落方法论**：最优/最差归因必须落到 ≥2 个方法论维度（子枝/六感/钩子/类型/平台/内容型），不许只说"播放高所以好"。
5. **反哺要可执行**：给上游的必须是加权/调整清单，不是"建议多拍好内容"这类空话。
6. **CSV 模板字段**：见 `references/data-import.md`，用户从抖音/视频号/小红书创作者后台复制数据填入。
7. **内容任务标签映射**：有常备条目回链的视频，其「内容任务」取常备条目字段（看得准/有解法/做得到/信得过），与「子枝」并行不冲突——子枝是三维定调细粒度，内容任务是业务选题四组粗粒度；无回链标"待标注"，不卡流程。
8. **常备回链回填是软建议**：本 Skill 不直接改写 `常备选题库_{业务}.md`，只输出「回填建议」清单交给上游执行；标记「同任务重复⚠️」时给警告而非拒绝。
