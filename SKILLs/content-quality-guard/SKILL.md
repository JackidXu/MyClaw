# content-quality-guard — 质量守门员

> 内容发布前的最后一道关。合规拦截、事实核验、信任配比、方法论校验、风险扫描、信任完整度——六维审查，只抓真问题，不搞形式主义。

---

## 1. 触发词

- `审查一下`
- `检查一下这个脚本`
- `合规检查`
- `看看能不能发`
- `这个内容有没有风险`
- `看看信任感够不够`
- `帮我过一遍`
- `质量审查`
- `发布前检查`
- `朋友圈能发吗`
- `检查一下这条朋友圈`
- `这篇公众号能发吗`
- `检查一下这篇文章`
- `这篇长文有没有问题`

---

## 2. 核心定位

**不是"打分工具"，而是"发布前拦雷器"。**

内容生产流程中，每个环节都有内置的质量检查（脚本撰稿有事实标注+去AI味+方法论自检，IP建档有信任审计10问）。本Skill不重复这些内置检查，而是做它们覆盖不到的**横向审查**：

1. **合规拦截**——广告法/平台规则/行业特殊规定/隐私/版权，这些是法律和平台硬规则，违反了会被罚款或下架
2. **事实复核**——不是重新标注事实状态，而是抽查脚本中标注为🟢事实的声明是否真有证据支撑
3. **信任配比**——信息型vs信任型内容的比例是否合理，IP象限不同配比不同
4. **方法论校验**——内容是否违反了对应视频类型的校验规则
5. **风险扫描**——争议话题/敏感表述/公关风险/IP红线，这些是"发了可能翻车"的风险
6. **信任完整度**——这条内容传递了IP的哪些信任维度，有没有明显的信任缺口

**核心原则：只说真问题。**

- P0（必须修改）= 不改会被罚款/下架/翻车
- P1（建议修改）= 改了效果更好，不改也能发
- P2（可选优化）= 锦上添花

不搞形式主义的扣分项，不为了"显得专业"而制造噪音。

## 3. 输入

### 必需（至少1种）

| 输入类型 | 说明 | 典型来源 |
|---------|------|---------|
| **脚本/文案** | 完整的脚本或口播文案 | content-script-writer / 用户自己写的 |
| **选题卡** | 选题引擎输出的选题卡 | content-topic-engine |
| **成片描述** | 已拍完的视频的文字描述/转录 | 用户口述 / 视频转录 |

### 可选（增强审查质量）

| 输入 | 来源 | 用途 |
|------|------|------|
| **IP档案** | content-ip-manager | 红线检查+信任配比判断+IP风格一致性 |
| **视频类型** | 用户指定 / 选题卡推荐 | 加载对应方法论校验规则 |
| **目标平台** | 用户指定 | 平台规则差异化检查（抖音/小红书/视频号） |
| **行业** | 用户指定 / IP档案 | 行业特殊合规规定 |

> **如果没有IP档案**：信任配比和信任完整度检查使用默认规则，红线检查跳过。
>
> **如果没有视频类型**：方法论校验跳过，只做通用审查。
>
> **如果没有目标平台**：默认按"全平台通用规则"审查，不做平台差异化检查。

## 4. 两种工作模式

### 模式一：独立审查（主模式）

用户拿着内容来找你审查。完整执行6大维度审查，输出审查报告。

**典型场景**：
- "脚本写好了，帮我审查一下"
- "这个文案看看有没有合规问题"
- "这条内容发出去会不会有风险"

### 模式二：嵌入式审查（被其他Skill调用）

其他Skill在流程末尾调用质量守门的检查维度做自检。不输出完整报告，只列出P0/P1项。

**典型场景**：
- content-script-writer 在脚本生成后自动执行合规+风险扫描
- content-topic-engine 在选题卡输出前检查选题风险

> **嵌入式调用方式**：其他Skill引用本Skill的§5（审查维度）作为检查清单，在自身流程的末尾按维度逐项检查。不需要显式调用本Skill——引用规则即可。详见§10。

## 5. 审查维度

### 5.1 合规检查

**目标**：拦截法律和平台硬规则违规——这些是"发了真会出事"的问题。

**检查清单**（详细规则见 `references/compliance-rules.md`）：

#### A. 广告法违规

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 最高级用语 | 最、第一、唯一、独家、首个、首选、最佳、最好、最大、顶级、极品 | P0 |
| 绝对化用语 | 100%、绝对、永远、必然、肯定、确保、保证、包治 | P0 |
| 虚假承诺 | 效果保证、收益保证、升学保证、胜诉保证 | P0 |
| 贬低他人 | 直接贬低竞争对手的表述 | P0 |

**处理方式**：
- P0：标记违规词 + 给出替换建议
- 替换原则：用"之一"替代"第一"，用"较多/较高"替代"最"，用"我们追求"替代"保证"

#### B. 平台规则

| 平台 | 重点检查 |
|------|---------|
| 抖音 | 导流词（加微信/私信我→主页/评论区）、医疗健康限制、金融投资限制 |
| 小红书 | 导流限制更严（不能提微信号/手机号）、医美限制、夸大功效限制 |
| 视频号 | 相对宽松，但金融/医疗类同样限制 |

**处理方式**：
- P0：标记平台违规词 + 给出合规替代
- 导流类：将"加微信"改为"主页有联系方式"或"评论区见"

#### C. 行业特殊规定

| 行业 | 重点检查 |
|------|---------|
| 金融/保险 | 不得承诺收益、不得推荐具体产品、需有风险提示 |
| 医疗/健康 | 不得承诺疗效、不得推荐具体药物、需有"遵医嘱"提示 |
| 教育 | 不得承诺升学率、不得制造焦虑、不得引用具体学生成绩 |
| 法律 | 不得承诺胜诉率、不得对具体案件做判断 |
| 食品 | 不得宣称治疗功效、需有"不能代替药物"提示（如适用） |

> **行业识别**：从IP档案的业务描述中自动识别行业，或从内容关键词判断。如果涉及多个行业，按最严格的行业规则检查。

#### D. 隐私保护

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 客户姓名 | 除非已获授权，否则不得出现真实姓名 | P0 |
| 联系方式 | 电话/微信号/地址不得出现 | P0 |
| 聊天截图 | 需脱敏（打码姓名/头像/手机号） | P0 |
| 客户案例 | 负面案例需特别确认授权 | P1 |
| 未成年人 | 未成年人信息需特别保护 | P0 |

#### E. 版权

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 引用他人内容 | 引用他人观点/数据/案例需标注来源 | P1 |
| 使用他人素材 | 他人视频/图片/音乐需确认授权 | P0 |
| 商标/品牌 | 使用他人商标/品牌名称需规范 | P1 |

### 5.2 事实复核

**目标**：不重新标注事实状态，而是抽查已标注为🟢事实的声明是否有证据支撑。

**检查逻辑**：

1. **提取所有🟢事实声明**：从脚本中提取所有标注为🟢事实的段落/句子
2. **逐条检查证据**：
   - 有具体数据 → 是否标注了来源？（"46%的人没续签" → 来源是什么？）
   - 有事件声明 → 是否可验证？（"XX上热搜了" → 搜索确认）
   - 有因果声明 → 因果关系是否成立？（"因为X所以Y" → 是否真的是因果关系）
3. **检查🔴需验证项**：脚本中的🔴需验证项是否已列入事实核验清单？是否有明确的验证方式？
4. **检查🟡判断**：是否有主观判断被错误标注为🟢事实？

**处理方式**：

| 问题 | 严重度 | 处理 |
|------|--------|------|
| 🟢事实但无来源 | P1 | 建议补充来源或降级为🟠推测 |
| 🟢事实但可验证为假 | P0 | 必须修改或删除 |
| 🟡判断误标为🟢事实 | P1 | 改标为🟡判断 |
| 🔴需验证但无验证方式 | P1 | 补充验证方式或降级为🟠推测 |

> **不重复标注**：脚本撰稿已有完整的事实标注体系。本维度只做"抽查+复核"，不重新标注每一段。

### 5.3 信息vs信任配比判别

**目标**：判断内容的信息型/信任型配比是否合理。

**配比标准**（根据IP四象限）：

| IP象限 | 推荐配比（信任:信息） | 说明 |
|--------|---------------------|------|
| 顾问型（TO C高客单） | 70:30 | 信任是核心，信息是辅助 |
| 势能型（TO B高客单） | 60:40 | 原创方法论是信任+信息 |
| 流量型（TO C低客单） | 30:70 | 信息驱动转化，信任靠规模 |
| 效率型（TO B低客单） | 40:60 | 信息为主，信任提效 |
| 无IP档案 | 50:50 | 默认均衡 |

**判断方法**：

1. **逐段标注**：将脚本每段标注为"信息型"或"信任型"
   - 信息型：传递知识/方法/数据/行业信息
   - 信任型：展示人物/经历/价值观/案例/客户反馈
   - 混合型：既有信息也有信任（按主要倾向标注）
2. **计算配比**：按时长或字数计算信任型vs信息型的实际配比
3. **对比推荐配比**：实际配比与推荐配比偏差超过20% → P1建议

**处理方式**：

| 情况 | 严重度 | 处理 |
|------|--------|------|
| 信任型严重不足（<推荐-20%） | P1 | 建议增加信任型段落（人物故事/案例/客户反馈） |
| 信息型严重不足（<推荐-20%） | P1 | 建议增加信息型段落（方法/数据/行业信息） |
| 配比合理 | — | 通过 |

> **特殊规则**：如果视频类型方法论中有明确的配比建议（如旁白视频偏信任型），以方法论的配比建议为准。

### 5.4 类型方法论校验

**目标**：检查内容是否违反了对应视频类型的校验规则。

**加载流程**：

1. 确认视频类型（从脚本头部/选题卡/用户输入）
2. 查找方法论文件：`content-script-writer/references/{类型名}-methodology.md`
3. 读取方法论文件中的"方法论校验规则"部分
4. 逐条检查

**已加载方法论的校验**：

| 类型 | 校验规则来源 | 校验内容 |
|------|------------|---------|
| 旁白视频 | 旁白视频-methodology.md §8项自检清单 | 选择结论+理由链+证据画面+钩子4标准+无画面句检查 |
| VLOG视频 | VLOG视频-methodology.md §校验规则 | 不得只有行程流水账/不得用"今天我来到了"开头/口述不伪装同期声/一次一个任务/避免信息当信任 |
| 其他类型 | 待用户提供方法论 | 文件不存在时跳过此项 |

**无方法论文件时**：跳过此项，不做方法论校验。不凭空编造校验规则。

**处理方式**：

| 问题 | 严重度 | 处理 |
|------|--------|------|
| 违反方法论硬规则 | P1 | 列出违反了哪条规则 + 修改建议 |
| 方法论文件不存在 | — | 跳过，提示"该类型方法论未提供，无法做类型校验" |

### 5.5 风险扫描

**目标**：发现"发了可能翻车"的风险——不是法律问题，是口碑/公关/平台限流问题。

#### A. 争议性话题

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 政治敏感 | 涉及政治人物/政策/两岸/领土/民族 | P0 |
| 性别对立 | 可能引发男女对立的表述 | P1 |
| 地域歧视 | 地域黑/刻板印象 | P1 |
| 收入/阶层 | 炫富/仇富/阶层固化 | P1 |
| 宗教信仰 | 涉及宗教评价/对比 | P0 |

#### B. 潜在公关风险

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 断章取义风险 | 某句话单独拿出来会被误读 | P1 |
| 负面解读风险 | 表述可能被解读为傲慢/冷漠/歧视 | P1 |
| 竞争对手提及 | 是否涉及对竞争对手的直接/间接评价 | P1 |
| 客户负面信息 | 是否暴露了客户的负面情况 | P0 |

#### C. IP红线检查

**前提**：需有IP档案。从IP档案中读取"红线清单"字段。

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 红线触碰 | 内容涉及IP明确表示不做的方向 | P0 |
| 价值观冲突 | 内容的价值观与IP精神内核冲突 | P1 |
| 风格不一致 | 内容的语言风格与IP档案风格定位明显不符 | P2 |

> **无IP档案时**：红线检查跳过。

#### D. 敏感词扫描

扫描内容中是否包含各平台已知的限流词/违禁词。详细词表见 `references/compliance-rules.md`。

**处理方式**：标记敏感词 + 给出替代建议。

#### E. 账号标签偏移风险

**目标**：检查内容是否会导致平台算法给账号打上与IP核心定位无关的标签——标签一旦偏移，精准客户将刷不到你的内容，即使后续内容质量再高也触达不到目标受众。

**前提**：需有IP档案（用于读取定位句和目标客户画像）。无IP档案时跳过此项。

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 选题与IP定位相关性 | 内容选题是否与IP核心定位直接相关，或通过"观点"有效桥接到定位 | P1 |
| 泛流量内容风险 | 内容是否可能吸引大量非目标用户（泛娱乐/泛知识），导致算法重新判定账号标签 | P1 |
| 蹭热点受众匹配度 | 蹭的热点是否为目标客户群体关心的——如果客户不关心，即使能爆也不要发 | P1 |
| 标签一致性 | 连续发布的内容方向是否一致——偶尔一条偏离不影响，但如果近期多条偏离需预警 | P1 |

**判断逻辑**：
1. 从IP档案读取定位句和三层靶子（目标客户画像）
2. 检查内容选题是否在定位范围内，或通过"观点"桥接到定位
3. 如果内容选题完全偏离定位（如金融IP蹭娱乐热点），标记P1风险
4. 如果内容可能爆量但吸引的是非目标用户，标记P1风险并说明标签偏移后果

> **⚠️ 真实案例警示**：某IP蹭了一个跟自身业务无关的泛娱乐热点，视频爆了**600万播放**，但算法给账号打上了"泛娱乐"标签，后续所有内容被推给非目标用户——流量看起来很大，但精准客户刷不到，转化归零。花了**整整三个月**通过持续发垂直内容才把标签拉回来。
>
> **判断标准**：不是"这个热点火不火"，而是"这个热点的受众跟你的目标客户重不重合"。如果不重合，即使预测播放量再高也要放弃——爆了反而会做偏账号标签。

**处理方式**：

| 情况 | 严重度 | 处理 |
|------|--------|------|
| 内容完全偏离IP定位且无法通过观点桥接 | P1 | 建议放弃或调整角度 |
| 内容蹭的热点客户不关心但有爆量潜力 | P1 | 警示标签偏移风险，建议放弃 |
| 内容在定位范围内或通过观点有效桥接 | — | 通过 |
| 近期多条内容方向偏离IP定位 | P1 | 预警账号标签偏移趋势，建议回归核心定位 |

### 5.6 信任完整度检查

**目标**：判断这条内容在"让人信人"和"让人信产品"两个维度上传递了什么，有没有明显缺口。

> **与IP档案信任审计的关系**：IP档案的信任审计10问是针对"档案本身够不够全"做的检查。本维度是针对"这条具体内容传递了哪些信任信息"做的检查。一个检查档案完整度，一个检查内容覆盖度。

**检查框架**（基于IP档案信任审计10问）：

#### 信人维度（5问）

| 问题 | 内容中的体现 | 检查标准 |
|------|------------|---------|
| 1. 什么样的人 | 人物形象/价值观/性格 | 内容是否展现了IP是一个什么样的人 |
| 2. 凭什么懂 | 专业能力/经历/资质 | 内容是否体现了IP的专业性 |
| 3. 说的是真话吗 | 真实性/脆弱面/失败经历 | 内容是否有真实感（不是纯包装） |
| 4. 别人怎么看你 | 客户证言/第三方评价 | 内容是否引用了他人对IP的评价 |
| 5. 平时什么样 | 日常真实/工作状态 | 内容是否展示了IP的日常一面 |

#### 信产品维度（5问）

| 问题 | 内容中的体现 | 检查标准 |
|------|------------|---------|
| 6. 卖什么 | 产品/服务清晰度 | 内容是否让受众知道IP做什么业务 |
| 7. 为什么选你 | 购买理由/差异化 | 内容是否传递了选择IP的理由 |
| 8. 做过什么结果 | 案例/成果/数据 | 内容是否展示了IP的业务成果 |
| 9. 客户用后怎样 | 客户结果/反馈 | 内容是否展示了客户使用后的效果 |
| 10. 出问题怎么办 | 风险逆转/售后保障 | 内容是否传达了出问题的兜底机制 |

**判断逻辑**：

1. 逐问检查这条内容是否覆盖了该问题（覆盖/部分覆盖/未覆盖）
2. 不要求一条内容覆盖全部10问——不同内容类型覆盖不同的维度
3. 但要检查"内容目的"与"覆盖维度"是否匹配：
   - 信任型内容（如旁白视频"凭什么信任你"）→ 应覆盖信人维度≥3问
   - 业务型内容（如痛点拆解）→ 应覆盖信产品维度≥2问
   - 转化型内容（如CTA前的卖点段）→ 应覆盖信产品维度≥3问

**处理方式**：

| 情况 | 严重度 | 处理 |
|------|--------|------|
| 信任型内容信人维度覆盖<2问 | P1 | 建议补充人物/经历/价值观内容 |
| 转化型内容信产品维度覆盖<2问 | P1 | 建议补充购买理由/案例/结果 |
| 内容目的与覆盖维度完全不匹配 | P1 | 提示内容方向与目的不一致 |
| 覆盖合理 | — | 通过 |

#### 买点vs卖点检查

**目标**：检查脚本中的"卖点"段落是否已转化为客户能感知的"买点"——卖点是"我提供什么"（自嗨），买点是"你得到什么"（客户视角）。没有转化的卖点段落读起来像广告，转化效果差。

**检查范围**：脚本中标注为"方法论/卖点"或涉及业务展示的段落。

**检查规则**：

| 检查项 | 自问句 | 通过标准 | 不通过则 |
|--------|--------|---------|---------|
| 主语检查 | 这段话的主语是"我/我们"还是"你"？ | 主语为"你"或主语平衡 | 如果全是"我们提供/我们擅长"，标P1 |
| "所以呢"检查 | 客户听完这段会问"所以呢？跟我有什么关系？" | 已追到客户能感知的利益 | 如果停在概念层面（"专业靠谱""经验丰富"），标P1 |
| 结果可感知检查 | 卖点是否配了客户能直接感知/验证的结果？ | 有具体可感知的结果 | 如果只有抽象形容词没有具体结果，标P1 |

**示例**：

| 类型 | 表达 | 判定 |
|------|------|------|
| ❌ 卖点思维 | "我们有10年行业经验，专业团队一对一服务" | 主语全是"我们"，客户听完会问"所以呢？" |
| ✅ 买点思维 | "你踩过的坑我都踩过，咨询完你能拿到一份踩坑清单，每条都标了出处" | 主语是"你"，结果可感知（拿到清单+标了出处） |
| ❌ 卖点思维 | "我们提供全面的资产配置方案" | 概念化，客户无法感知具体得到什么 |
| ✅ 买点思维 | "你的钱不会因为不懂规则而缩水，方案里每一步都有替代选项" | 客户能感知"不缩水"和"有替代选项" |

**处理方式**：

| 情况 | 严重度 | 处理 |
|------|--------|------|
| 卖点段落全部是"我/我们"主语，无客户视角 | P1 | 建议使用"转化三刀"（追问"所以呢"+换主语"我"→"你"+配可感知结果）重写 |
| 卖点段落停在概念层面，无具体可感知结果 | P1 | 建议补充客户能直接验证的具体结果 |
| 卖点段落已转化为买点表达 | — | 通过 |

> **与content-script-writer的协同**：脚本撰稿已集成"转化三刀"技巧（§5第四步），用于在脚本生成时将卖点转化为买点。质量守门在这里做的是"验证"——检查转化是否到位，不是重新转化。

> **无IP档案时**：信任完整度检查降级为简化版——只检查"这条内容有没有传递IP是一个什么样的人"和"有没有提到IP做什么业务"，不做10问逐项检查，也不做买点vs卖点检查。

### 5.7 朋友圈文案专项检查

**目标**：对朋友圈文案执行专属合规检查——朋友圈有不同于短视频的折叠/频率/查重/导流规则，违反这些规则不会被罚款但会被限流/折叠/ shadowban。

**触发条件**：当审查对象是朋友圈文案时（从内容类型标识或用户声明判断），执行本维度检查。

**参考文件**：`content-script-writer/references/moments-compliance-checklist.md`

#### A. 折叠检查（防折叠）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 文字长度 | 纯文字≤5行（约100字），超过6行会被折叠 | P1 | 建议精简，溢出内容放图片说明 |
| 图片数量 | 1-3张最佳；9宫格容易被标记为营销 | P2 | 提醒用户9宫格有营销标记风险 |
| 段落格式 | 是否有自然段落分隔（不能挤成一团） | P1 | 建议分2-5段，每段1-2句 |

#### B. 频率检查（防刷屏限流）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 日发布量 | 当天不超过5条 | P1 | 提醒用户今日已发X条 |
| 密集发布 | 30分钟内不超过3条 | P1 | 建议间隔≥15分钟 |
| 模板复用 | 不连续3条使用同一文案模板结构 | P1 | 建议换模板 |

#### C. 查重检查（防去重）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 文字查重 | 与上一条朋友圈文字差异>30% | P1 | 建议修改表述 |
| 图片复用 | 不连续2条使用同一张图片 | P2 | 建议换图 |

#### D. 朋友圈禁用词检查

在§5.1A通用广告法禁用词基础上，朋友圈还有额外的禁用词：

| 类别 | 禁用词 | 安全替代 | 严重度 |
|------|--------|---------|--------|
| 诱导互动 | 转发、集赞、截图发我、不转不是XX | 评论区聊聊、收藏起来 | P0 |
| 导流用语 | 加微信、加好友、扫码加我、立刻下单 | 私信我、想了解的聊聊 | P0 |
| 绝对化（朋友圈特有） | 全网最低、爆款、抢疯了 | 口碑款、很多客户选 | P1 |

#### E. 行为风险检查（隐形限流触发）

| 行为 | 风险 | 严重度 | 处理 |
|------|------|--------|------|
| 文字+logo+价格的图片 | 图片识别标记为广告 | P1 | 建议用生活照，减少文字贴纸 |
| 外部链接 | 导流检测 | P0 | 建议改为"私信我" |
| 朋友圈中出现微信号/二维码 | 导流检测 | P0 | 建议改为"私信我" |
| @很多人（>3人） | 营销bot行为 | P1 | 建议@不超过3人 |

#### F. 高危行业合规声明检查

| 行业 | 必须声明 | 严重度 | 处理 |
|------|---------|--------|------|
| 医疗健康 | "请及时就医"/"以上为健康科普" | P0 | 必须在文案中出现 |
| 财经 | "不构成投资建议" | P0 | 必须在文案中出现 |
| 法律 | "不构成具体法律意见" | P0 | 必须在文案中出现 |
| 教育 | 不得出现"保过/包录取" | P0 | 删除或替换 |
| 美业 | 不得出现"永久/一次祛斑/永不反弹" | P0 | 删除或替换 |

#### G. 六条铁律检查

| 检查项 | 自问句 | 通过标准 | 严重度 |
|--------|--------|---------|--------|
| 真实感 | 像跟朋友聊天还是像念广告词？ | 口语化、有细节、有温度 | P1 |
| 价值感 | 这条提供了有用/有趣/有共鸣/有福利哪种价值？ | 至少提供一种 | P1 |
| 场景化 | 是抽象概念还是具体画面？ | 有具体场景描写 | P2 |
| 互动钩子 | 前两行有没有让人想评论的冲动？ | 有提问/悬念/选择 | P2 |
| 简洁度 | 在5行以内吗？ | ≤5行 | P1 |
| CTA | 是给路径还是给命令？ | 软性CTA | P2 |

**处理方式汇总**：

| 情况 | 严重度 | 处理 |
|------|--------|------|
| 出现导流用语/诱导互动/高危行业缺声明 | P0 | 必须修改 |
| 文字超6行/模板复用/无价值/纯广告感 | P1 | 建议修改 |
| 段落格式/互动钩子/CTA风格 | P2 | 可选优化 |

> **与content-script-writer的关系**：content-script-writer模式C已内置6步合规检查（§5C第六步）。质量守门在这里做的是"独立复核"——特别是当用户自己写的朋友圈文案（未经script-writer生成）需要审查时。

### 5.8 公众号文章编辑质量检查

**目标**：对公众号长文（模式D产出或用户自写）执行专属编辑质量审查——长文的风险不是限流而是"权威崩塌"：编造经历、论点无证据、凑字数空转，会让 IP 的专业形象一次翻车。

**触发条件**：当审查对象是公众号文章（从内容类型标识、明显长文结构或用户声明判断）时，执行本维度检查。

**参考文件**：`content-script-writer/references/wechat-article-methodology.md` §5（编辑质量五维）

#### A. 准确检查（事实边界）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 核心事实来源 | 🟢事实标注的声明是否有来源支撑（IP档案业务资料/公开数据/用户本次提供） | P0 | 无来源→标🔴或删除 |
| 事实/推断/意见分离 | 是否把🟠推测或🟡判断写成🟢事实 | P0 | 改回正确标注 |
| 结论超界 | 结论是否超出证据能支持的边界 | P1 | 补边界限定词或缩小主张 |
| unsupported 主张 | 是否混入 claims 中 status=unsupported 的主张 | P0 | 删除或补来源 |

#### B. 观点检查（核心判断）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 核心判断明确 | 文章是否给出清晰的核心判断（thesis.statement） | P0 | 补明确结论 |
| 新增价值 | 是否说明相较常见说法的新增价值（novelty），而非重复常识 | P1 | 补差异化角度或缩小问题 |
| 反方与边界 | 是否给出最强反方（counterpoint）与适用边界（boundary） | P1 | 补反方+边界 |

#### C. 有用检查（读者收益）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 回答读者问题 | 是否真正回答 audience.question | P0 | 答非所问→重写或删除无关节 |
| 可执行交付 | 是否给出行动/决策条件/可迁移框架（goal.action） | P1 | 补可执行内容 |

#### D. 合声检查（IP一致性）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 个人材料来源 | 所有第一人称事件/对话/感官细节是否来自 IP 档案故事弹药库或本次用户提供 | P0 | 超范围编造→删除或改非亲历论述 |
| 语气一致 | 是否符合 IP 档案风格定位+精神内核，未被模板绑架 | P1 | 调回 IP 语体 |
| 挪用范文 | 是否直接复用第三方范文的观点/句子/经历 | P0 | 删除 |

#### E. 好读检查（结构与表达）

| 检查项 | 规则 | 严重度 | 处理 |
|--------|------|--------|------|
| 开头进问题 | 开头是否迅速进入读者问题或核心判断（非万能开头） | P1 | 改具体场景/判断开头 |
| 各节有任务 | 每节是否服务指定 claim，无答非所问的漂亮结构 | P1 | 删无关节 |
| 论证连贯 | 节间过渡是否自然，无跳跃/重复 | P2 | 补过渡 |
| 标题准确 | 标题是否准确概括核心判断，无标题党 | P1 | 改标题 |
| 节奏过齐/空转 | 是否存在段落同长同构、论证空转凑字数 | P1 | 打乱节奏/补具体 |

**阻断问题（任一出现不得通过）**：
- 编造 IP 亲历/朋友/采访/对话/场景（超故事弹药库范围）
- 核心具体事实无来源或来源不支持
- 核心论点与证据脱节，或把推断写成确定事实
- 文章未给读者明确结论/行动/判断方法

**处理方式汇总**：

| 情况 | 严重度 | 处理 |
|------|--------|------|
| 编造经历/核心事实无来源/论点脱节/无结论 | P0 | 必须修改 |
| 无新增价值/不合声/标题党/空转凑字数 | P1 | 建议修改 |
| 过渡/节奏细节 | P2 | 可选优化 |

> **与content-script-writer的关系**：content-script-writer模式D已内置编辑质量五维自检（§5D第六步）。质量守门在这里做"独立复核"——特别是用户自己写的公众号文章（未经script-writer生成）需要审查时，以及模式D自检后仍要横向把关（如标签偏移、高危行业合规声明是否到位）。

## 6. 审查工作流

### 独立审查模式

```
第一步：接收内容 + 确认审查范围
  → 内容类型（脚本/选题卡/文案）
  → 视频类型（如有）
  → 目标平台（如有）
  → IP档案（如有）
  → 行业（如有）

第二步：合规检查（§5.1）
  → 广告法违规扫描
  → 平台规则检查
  → 行业特殊规定检查
  → 隐私保护检查
  → 版权检查
  → 标记P0项

第三步：事实复核（§5.2）
  → 提取🟢事实声明
  → 抽查证据支撑
  → 检查🔴需验证项
  → 标记P0/P1项

第四步：信息vs信任配比（§5.3）
  → 逐段标注信息型/信任型
  → 计算配比
  → 对比推荐配比
  → 标记P1项

第五步：方法论校验（§5.4）
  → 加载方法论文件
  → 逐条检查校验规则
  → 标记P1项
  → （方法论不存在则跳过）

第六步：风险扫描（§5.5）
  → 争议性话题扫描
  → 公关风险扫描
  → IP红线检查
  → 敏感词扫描
  → 账号标签偏移风险检查
  → 标记P0/P1项

第七步：信任完整度检查（§5.6）
  → 10问逐项检查覆盖度
  → 内容目的与覆盖匹配度
  → 买点vs卖点检查
  → 标记P1项

第七步B：朋友圈专项检查（§5.7）— 仅朋友圈文案
  → 折叠检查
  → 频率检查
  → 查重检查
  → 朋友圈禁用词检查
  → 行为风险检查
  → 高危行业合规声明检查
  → 六条铁律检查
  → 标记P0/P1/P2项

第七步C：公众号文章编辑质量检查（§5.8）— 仅公众号文章
  → 准确检查（事实边界/unsupported主张）
  → 观点检查（核心判断/新增价值/反方边界）
  → 有用检查（回答读者问题/可执行交付）
  → 合声检查（个人材料来源/语气一致/挪用范文）
  → 好读检查（开头/各节任务/标题/节奏空转）
  → 标记P0/P1/P2项

第八步：输出审查报告（§7）
```

### 快速审查模式

当用户只需要快速检查能不能发时，只执行：
- 合规检查（§5.1）——法律和平台硬规则
- 风险扫描中的P0项（§5.5 A/D）——争议话题和敏感词
- 事实复核中的P0项（§5.2）——可验证为假的声明

跳过配比、方法论、信任完整度检查。输出简化报告。

## 问题清单

### ❌ P0 必须修改（不修改不能发布）

**1. [合规检查] 广告法最高级用语**
- 原文：「我们是行业第一的品牌咨询公司」
- 问题：「第一」是广告法禁止的最高级用语
- 修改建议：改为「行业领先的品牌咨询公司之一」
- 位置：段落3

**2. [风险扫描] 客户负面信息暴露**
- 原文：「XX公司的张总去年亏了300万」
- 问题：暴露了客户真实姓名和财务状况，可能面临法律风险
- 修改建议：脱敏为「我接触过一个客户，去年在这个领域亏了不少」
- 位置：段落4

### ⚠️ P1 建议修改（修改后效果更好）

- 原文：「行业数据显示，90%的影楼都面临获客难题」

- 建议：段落2-4全是方法论输出，缺少人物故事/案例/客户反馈。建议段落3改为客户案例

### 💡 P2 可选优化

**1. [风格一致性] 表达风格偏离IP**
- 原文使用「赋能」「闭环」等互联网黑话

## 8. 严重度分级

| 级别 | 含义 | 处理 | 示例 |
|------|------|------|------|
| **P0** | 必须修改 | 不改不能发布 | 广告法违规、隐私泄露、政治敏感、事实造假 |
| **P1** | 建议修改 | 改了效果更好，不改也能发 | 信任配比失衡、事实无来源、方法论违规、公关风险 |
| **P2** | 可选优化 | 锦上添花 | 风格微调、表达优化 |

**总评规则**：
- 有任何P0 → ❌不通过
- 无P0有P1 → ⚠️需修改
- 只有P2或无问题 → ✅通过

### 与脚本撰稿内置检查的关系

脚本撰稿已有三层内置检查：
1. 事实标注（🟢🟡🟠🔴）——质量守门做"复核抽查"，不重新标注

**原则**：内置检查做过的，质量守门不重复做，只做"验证+补充"。

## 11. 边界

### 做什么
- 审查已有内容，发现问题+给修改建议
- 合规拦截（法律+平台硬规则）
- 风险预警（可能翻车的表述）
- 信任配比分析（信息型vs信任型）
- 方法论校验验证
- 信任完整度覆盖度检查

### 不做什么
- **不改写内容**——只发现问题+给建议，不替用户改
- **不重新标注事实**——脚本撰稿的职责，质量守门只做复核
- **不去AI味**——qu-ai-wei的职责
- **不做创意建议**——不评价"这个选题好不好"，只审查"这个内容能不能发"
- **不凭空编造校验规则**——方法论文件不存在时，不做方法论校验，不猜规则
- **不做法律定性判断**——只标记"可能违规"，不判断"是否违法"。涉及法律风险的，建议用户咨询专业律师

### 禁止
- 不要为了"显得专业"而制造无意义的扣分项——只说真问题
- 不要把P1当P0报——不夸大问题的严重性来制造焦虑
- 不要审查内容中没有的部分——如果内容没有客户案例，不报"缺少客户证言"为P0
- 不要在没有IP档案时编造IP红线——明确说"无IP档案，红线检查跳过"

## 13. 实施建议

1. **先做合规再做其他**——合规检查是硬规则，优先级最高。合规不通过，其他检查做了也白做
2. **P0是底线**——P0问题必须修改，没有商量余地。不要因为用户说"没事吧"就放过P0
3. **P1是建议不是要求**——给建议但不强制。尊重用户对自己内容的判断
4. **给具体修改建议**——不是"这里有问题"，而是"这里有问题，建议改成XX"。用户能直接用
5. **信任配比是参考不是标准**——不同内容有不同的配比需求，不要机械套用推荐配比
6. **方法论校验依赖方法论文件**——文件不存在时诚实说跳过，不编造规则
7. **无IP档案时降级检查**——不编造IP红线和信任维度，只做通用检查
8. **审查报告要可执行**——用户看完报告知道"改哪几处、怎么改、改完能不能发"
9. **不替代专业法律意见**——合规检查只做"可能违规"的预警，涉及法律定性问题建议用户咨询律师
