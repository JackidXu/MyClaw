# content-material-library — 素材库管理

> 帮客户建立和管理结构化素材库。素材分类、标注、入库、增量更新。
> 这是素材处理的基础skill，被 content-video-cutter（切片入库）和 content-material-matcher（选题匹配读取）调用。

---

## 1. 触发词

- `素材整理`
- `素材分类`
- `素材入库`
- `帮我整理这些素材`
- `我的素材库`
- `这些素材帮我归个类`
- `我每次拍完素材都扔进来`

---

## 2. 核心定位

**客户的素材库管家。**

客户把所有拍摄的内容放在一个文件夹里扔进来，AI帮忙分类、标注、入库。客户逐渐积累出一个结构化的素材库——知道手里有什么素材、什么场景的素材、什么类型的素材。

**素材库是长期资产**：客户每次拍完素材都可以入库，逐渐积累。素材库越丰富，选题匹配越精准。

---

## 3. 输入

### 必需（至少1种）
- **原始素材**（至少1种）：
  - 视频片段（用户上传 / 用户提供文字描述）
  - 照片（用户上传 / 用户提供描述）
  - 录音（用户上传 / 用户提供内容摘要）
  - 聊天截图（用户上传 / 用户提供文字）
  - 文档/数据截图（用户上传 / 用户提供文字）
  - 现场笔记/口述回忆（用户直接输入文字）

### 可选（增强输出质量）
- **IP档案**（来自 content-ip-manager）— 用于三维定调标注和故事弹药入库
- **已有素材库**（之前整理过的素材库文件）— 用于增量更新

> **如果没有IP档案**：素材标注的维度参考用通用框架。

## 4. 素材分类体系

**核心分类逻辑**：按素材的"内容属性"分类，不按文件类型分类。

### 一级分类（6大类）

| 分类 | 说明 | 典型内容 |
|------|------|---------|
| **人物形象** | IP本人的个人形象素材 | 穿搭展示/工作状态/生活场景/口播画面/个人特写 |
| **场景环境** | 不同场景的环境素材 | 工厂/办公室/客户现场/街拍/门店/仓库/其他 |
| **产品服务** | 产品展示和服务过程素材 | 产品特写/工艺细节/服务流程/方案演示/前后对比 |
| **客户相关** | 客户相关的素材 | 客户证言/客户案例/客户互动/客户反馈截图 |
| **事件记录** | 特定事件相关的素材 | 行业活动/出差记录/会议/直播/合作签约 |
| **数据证据** | 数据和凭证类素材 | 数据截图/合同/资质证书/奖项/媒体报道 |

### 二级分类（按具体内容细分）

**人物形象** → 穿搭展示 / 工作状态 / 生活场景 / 口播画面 / 个人特写
**场景环境** → 工厂 / 办公室 / 客户现场 / 门店 / 街拍 / 仓库 / 其他
**产品服务** → 产品特写 / 工艺细节 / 服务流程 / 方案演示 / 前后对比
**客户相关** → 客户证言 / 客户案例 / 客户互动 / 客户反馈
**事件记录** → 行业活动 / 出差 / 会议 / 直播 / 签约
**数据证据** → 数据截图 / 合同凭证 / 资质荣誉 / 媒体报道

### 特殊标签

| 标签 | 说明 |
|------|------|
| **口述回忆** | 不是现场实拍，是口述回忆的内容——标注"口述，需补拍" |
| **通用画面** | 可以用于多种场景的过渡/空镜画面 |
| **新故事弹药** | 素材中包含IP档案没有的新故事，标注"可入库" |
| **切片来源** | 由 content-video-cutter 切片产生的素材，标注源视频+时间段 |

## 5. 素材库位置管理

> **核心原则**：AI不能自行决定素材库保存路径，必须先问用户。

### 首次使用时

当用户第一次使用素材库相关功能（入库/切片/匹配）时，**必须先确认素材库位置**：

**确认逻辑**：
1. 问用户："你的素材库放在哪个文件夹？给我一个路径就行。"
2. 如果用户说没有素材库："那我帮你新建一个素材库文件夹，你希望放在哪个目录下？比如桌面、Documents、或者项目文件夹里？"
3. 用户指定路径后，创建目录结构（如果不存在的话）
4. 在素材库报告中记录素材库的物理路径，后续使用时直接引用

**目录结构**：
```
[用户指定路径]/
└── [IP名称]_素材库/
    ├── _索引表.csv          ← 素材库核心索引（AI读这个文件做检索和匹配）
    ├── _索引报告.md          ← 人类可读的整理报告（每次入库后更新）
    ├── 01_人物形象/
    ├── 02_场景环境/
    ├── 03_产品服务/
    ├── 04_客户相关/
    ├── 05_事件记录/
    ├── 06_数据证据/
    ├── 99_损坏废弃/
    └── ⚠️ 待补拍/
```

### 非首次使用时

如果之前的索引表中已记录了素材库路径，直接使用该路径，但向用户确认一次：
- "切片将保存到你的素材库 `[路径]`，对吗？"
- 如果用户说要换路径，按新路径走

> ⚠️ **禁止行为**：不要自行默认保存到项目目录、桌面、Downloads等任何路径。路径必须由用户指定或确认。

## 5.5 素材库索引表

> **核心原则**：索引表是素材库的"数据库"。AI通过读取索引表来检索和匹配素材，而不是逐个扫描文件。索引表必须做到：AI可读可查、可增量更新、字段完整。

### 索引表文件

- **文件名**：`_索引表.csv`
- **位置**：素材库根目录（与分类文件夹同级）
- **格式**：CSV（UTF-8编码，逗号分隔，首行为表头）
- **用途**：
  - `content-material-matcher`（选题匹配）：读索引表按标签检索匹配素材
  - `content-video-cutter`（切片入库）：切片完成后追加行到索引表
  - `content-material-library`（入库管理）：入库时创建/更新索引表

### 索引表字段定义

| 列序 | 列名 | 说明 | 示例 | 必填 |
|------|------|------|------|------|
| 1 | 编号 | 素材唯一编号，接续编号不回收 | R-01 | ✅ |
| 2 | 文件名 | 含扩展名 | 原视频.mp4 | ✅ |
| 3 | 文件路径 | 相对于素材库根目录的路径 | 01_人物形象/原视频.mp4 | ✅ |
| 4 | 一级分类 | 6大类之一 | 人物形象 | ✅ |
| 5 | 二级分类 | 子分类 | 口播画面 | ✅ |
| 6 | 素材类型 | 视频/照片/录音/截图/文档 | 视频 | ✅ |
| 7 | 时长 | 视频/录音时长，照片填"-" | 0:30 | ✅ |
| 8 | 文件大小 | 文件大小 | 27.5M | ✅ |
| 9 | 内容描述 | 1-2句内容描述 | 戴眼镜男士在办公桌前出镜讲解 | ✅ |
| 10 | 六感标签 | 主感/次感，多个用竖线\|分隔 | 手感\|证据 | ✅ |
| 11 | 三维定调 | 维度·子枝，多个用竖线\|分隔 | 人物感性·独立观点 | ✅ |
| 12 | 证据强度 | 强/中/弱/不可用 | 强 | ✅ |
| 13 | 可用片段 | 黄金片段时间+摘要，无则填"整段可用" | 00:30-01:15(面料对比演示) | ✅ |
| 14 | 合规风险 | 无/需打码/需授权/商业机密/场地权限 | 无 | ✅ |
| 15 | 事件标签 | 事件背景（路径A）或"杂拍"（路径B） | 杂拍 | ✅ |
| 16 | 来源场景 | 拍摄场景 | 办公室 | ✅ |
| 17 | 拍摄日期 | 日期，未知填"未知" | 2026-07-28 | ✅ |
| 18 | 可用性 | 强/中/弱 | 强 | ✅ |
| 19 | 切片来源 | 源视频+时间段，非切片填"-" | 7月30日.mp4 00:00-00:15 | ✅ |
| 20 | 状态 | active/损坏/缺失 | active | ✅ |
| 21 | 入库日期 | 入库日期 | 2026-07-30 | ✅ |
| 22 | 备注 | 特殊说明，无则留空 | IP本人出镜 | ❌ |

### 索引表创建规则

1. **首次入库时创建**：第一次使用素材库入库时，在素材库根目录创建 `_索引表.csv`
2. **UTF-8编码**：必须用UTF-8编码，确保中文不乱码
3. **首行为表头**：列名按上表定义，顺序固定不可调整
4. **一行一素材**：每个素材一行，不合并

### 索引表更新规则

**必须更新索引表的场景**：

| 场景 | 触发方 | 操作 |
|------|--------|------|
| 新素材入库 | content-material-library（本skill） | 在CSV末尾追加行 |
| 切片入库 | content-video-cutter → 调用本skill | 在CSV末尾追加行 |
| 文件重命名 | content-material-library（本skill） | 更新对应行的文件名+文件路径列 |
| 文件移动/重新分类 | content-material-library（本skill） | 更新对应行的一级分类+二级分类+文件路径列 |
| 文件损坏标记 | content-material-library（本skill） | 更新对应行状态列为"损坏" |
| 文件缺失发现 | content-material-matcher（推荐时发现文件不存在）| 更新对应行状态列为"缺失" |
| 文件恢复/重新入库 | content-material-library（本skill） | 更新对应行状态列为"active" |

### 索引表维护原则

1. **追加优先**：新素材入库时在CSV末尾追加行，不修改已有行（除非是更新状态/重命名/重新分类）
2. **状态管理不删行**：文件损坏或缺失时不删除行，只改状态列——保留记录方便追溯
3. **编号不回收**：已入库的编号永久占用，即使文件损坏/缺失也不回收再分配
4. **入库后同步检查**：每次入库操作完成后，AI应扫描素材库目录与索引表做一次比对：
   - 索引表有记录但目录中不存在的文件 → 状态改为"缺失"
   - 目录中有但索引表没有的文件 → 提示用户"发现未入库文件：[文件名]，是否需要入库？"
5. **索引表与索引报告的关系**：
   - `_索引表.csv` = 机器可读的结构化数据（AI检索用）
   - `_索引报告.md` = 人类可读的整理报告（用户审阅用）
   - 每次入库后两个文件都要更新

## 6. 素材入库工作流

### 第一步：素材来源预问

**目标**：在接收素材前，先了解这批素材的来源背景，决定后续处理路径——避免AI盲目全盘识别导致分类不准、耗时过长。

> ⚠️ **核心原则**：用户在提供素材时，通常已经知道这批素材是什么背景。AI应该先问、再整理，而不是自己猜。

**必须问用户的问题**（一轮问完，不逐个追问）：

1. **这批素材是什么来源？**
   - A：同一事件/场景下拍的（如"某次活动""某次出差""某次客户服务"）
   - B：日常积累的杂拍（多次不同场景拍的混在一起，但大致知道每段是什么）
   - C：纯杂乱，需要AI全盘识别区分

2. **如果是事件/场景，是什么事件？**（一句话说明即可）
   - 例如："7月30日广州AI商业策略演讲""上周客户跟拍""工厂参观"

3. **有没有需要特别注意的素材？**（可选）
   - 例如："第3个视频很重要""那几张照片是客户提供的""有个文件可能损坏了"

**根据回答走不同路径**：

| 路径 | 触发条件 | 处理方式 | 速度 |
|------|---------|---------|------|
| **路径A：事件批量处理** | 用户说明了事件/场景背景 | AI用事件信息作为统一"事件标签"，快速扫描每个素材验证内容是否匹配说明，匹配的直接标注入库，不匹配的标注"异常"单独列出 | ⚡快 |
| **路径B：逐个识别分类** | 用户说杂乱/需AI区分 | 走完整AI识别流程（逐个提取关键帧→识别内容→分类标注） | 慢 |
| **路径C：混合处理** | 用户说"大致知道但有部分不确定" | 用户说明的部分走路径A，不确定的部分走路径B | 中 |

**路径A（事件批量处理）的具体操作**：
1. 用户说明事件背景后，AI把事件信息作为这批素材的统一"事件标签"（如`事件：7月30日广州AI商业策略演讲`）
2. 快速扫描每个素材（视频提取1帧关键帧/直接看图片），验证内容是否与用户说明的事件相关
3. **匹配的**：直接标注入库——事件标签 + 内容描述 + 分类建议，不需要逐个深度识别
4. **不匹配的**：标注"⚠️ 异常——内容与说明不符"，单独列出让用户确认（可能是用户说错了，也可能是混入了其他素材）
5. **AI不猜内容**：用户说了背景，AI只需验证不需要猜——如果一帧画面就能确认是演讲场景，直接标注入库

**路径A的优势**：
- 准确率高——用户说的事件背景比AI从一帧画面猜的准
- 速度快——同源素材批量处理，不需要逐个深度识别
- 索引清晰——每个文件都带事件/场景来源标签
- 异常可发现——AI验证时发现内容与说明不符会单独标注

---

### 第二步：素材接收与清点

**目标**：把客户扔进来的所有素材过一遍，建立素材清单。

**素材清点维度**：

| 维度 | 记录内容 |
|------|---------|
| 序号 | S-01, S-02, ...（如果是增量入库，接续已有编号） |
| 事件标签 | 如果走路径A，标注用户说明的事件背景（如`7月30日广州AI商业策略演讲`）；走路径B标注"杂拍" |
| 素材类型 | 视频/照片/录音/截图/文档/口述 |
| 内容描述 | 这个素材讲了什么/展示了什么（1-2句话） |
| 时长/数量 | 视频/录音标注时长，照片/截图标注数量 |
| 来源场景 | 在哪拍的/什么场景下记录的 |
| 拍摄日期 | 什么时候拍的（如能确认） |

**素材接收规则**：
1. 用户可能是口述描述，也可能是上传文件
2. 如果是口述描述，AI需要追问关键信息缺口
3. 如果是文件上传，AI直接读取理解
4. **路径A（事件批量处理）时**：AI用第一步确认的事件标签作为统一来源标注，只需快速扫描每个素材验证内容是否匹配，不需要逐个深度识别——匹配的直接进第三步分类，不匹配的标注"异常"
5. **路径B（逐个识别分类）时**：AI逐个提取关键帧/读取图片，深度识别内容后再进第三步分类
6. 如果素材数量超过20个，先分大类归组再逐个标注
7. 如果已有素材库，增量入库——只整理新素材，不重复已有素材

**⚠️ 视频素材质量预检**（在标注之前快速筛一遍）：
- 用 ffmpeg 提取每视频第5帧（如 `ffmpeg -i x.mp4 -vf "select=eq(n\,5)" -vframes 1 /tmp/preview.jpg`）作为快速预览
- 如果预览帧是纯灰色/纯黑/纯白/只有水印 → 标记为"损坏/低质量"，归入`99_损坏废弃`子文件夹，不入库
- 损坏文件不删除，保留原文件名+损坏原因，等待用户重新录制或删除决定

**追问规则**：
- 最多追问1轮（老板模式）/ 3轮（编导模式）
- 优先追问"分类关键信息"——这段素材主要拍的是什么场景/什么内容

---

### 第三步：素材分类

**目标**：把每个素材归入对应的一级分类和二级分类。

**分类规则**：
1. 一个素材可能跨多个分类，取最主要的作为主分类，次要的标注为副分类
2. 如果素材纯粹是环境空镜，归入"场景环境·通用画面"
3. 如果素材是口述回忆，归入对应内容分类，但标注"口述，需补拍"
4. 分类标准以素材的**主要内容**为准

**⚠️ 多版本素材处理**（同一类内容多版本，如成本上升.mp4/2/3/4）：
- 全部归入同一主分类
- 在索引中标注"主版本/推荐版本"——基于时长、画质、内容完整度综合判断
- 提示用户确认主版本，让以后选题匹配默认调用主版本

**⚠️ 文件名误导识别**（实测常见问题）：
- 实际内容可能跟文件名不符（如文件名"播放量低"实际是高播放量案例）
- 分类时如发现名字与内容矛盾，在索引的"处理建议"列明确写出**重命名建议**
- 例如：`播放量低2.mp4` → 实际是美食探店高互动案例 → 建议重命名 `播放量高_探店美食案例.mp4`

---

### 第四步：素材标注

**目标**：为每个素材打上标签，让它能被检索和匹配。

**标注维度**（5个标签）：

#### 标签1：六感标签
| 标签 | 识别信号 |
|------|---------|
| 痛感 | 素材中有客户抱怨/质疑/提出痛点 |
| 手感 | 素材中展示了一个有效的方法/技巧/操作 |
| 温度 | 素材中有人际互动/情绪波动/感动或愤怒 |
| 证据 | 素材中有好评/数据/结果/认可 |
| 鲜度 | 素材中有行业新闻/趋势/新变化 |
| 悟感 | 素材中有突然想通/领悟/认知迭代 |
| 过程 | 纯过程记录，无明确情绪触发 |

#### 标签2：三维定调标签
| 维度 | 子枝 |
|------|------|
| 人物感性 | 成长经历/亲身事件/内心感悟/独立观点/世界观与准则/好恶立场 |
| 业务性感 | 购买理由/客户案例/痛点拆解/销售QA/方案拆解/结果承诺 |
| 信任背书 | 客户证言/实绩成果/资质荣誉/第三方佐证/履约实拍/长期口碑 |
| 通用 | 通用画面，不特定挂某个子枝 |

#### 标签3：证据强度
| 强度 | 标准 |
|------|------|
| 强 | 有具体数据/客户原话/现场实拍/可验证事实 |
| 中 | 有过程展示/场景佐证/间接证据 |
| 弱 | 只有环境画面/泛泛描述/无具体信息 |
| 不可用 | 画面模糊/声音不清/内容与IP无关 |

#### 标签4：可用片段
- 视频/音频：标注黄金片段（起止时间+内容摘要）、可用片段、废片
- 照片/截图/文档：标注"整张可用"或"局部可用"
- 口述回忆：标注"需补拍"

#### 标签5：合规风险
| 风险类型 | 检查 |
|---------|------|
| 客户隐私 | 客户姓名/联系方式/面部是否需要打码 |
| 客户授权 | 客户是否知道在拍摄/是否同意公开使用 |
| 商业机密 | 是否涉及未公开的商业信息/价格/合同 |
| 场地权限 | 拍摄场地是否允许公开使用画面 |
| 无风险 | 以上都不涉及 |

**标注输出格式**：
```
素材标注：
S-01 [视频·3分20秒] → 人物形象·口播画面
- 内容描述：江总在衣品空间里拿起一件基础款衬衫，讲解面料工艺差异
- 六感标签：手感（主）/ 证据（次）
- 三维标签：业务性感·方案拆解（主）/ 信任背书·履约实拍（次）
- 证据强度：强 — 有具体面料工艺对比演示
- 可用片段：00:30-01:15（黄金片段：面料对比演示）/ 02:00-02:45（可用片段：客户案例讲述）
- 合规风险：无风险
- 拍摄日期：2026-07-28
```

**入库规则**：
1. 每个素材按主分类归入对应分类
2. 口述回忆类素材归入"⚠️ 待补拍"分类，不能和实拍素材混在一起
3. 如果已有素材库，新素材增量添加，标注"新增"标记
4. 如果素材库中没有的二级分类首次出现，新建分类

6. **入库后必须更新索引表**（见下方"索引表更新操作"）

**索引表更新操作**（入库时的强制步骤）：

> ⚠️ **入库不更新索引表 = 素材等于没入库**。索引表是AI检索素材的唯一入口，不入索引表的素材在选题匹配时无法被发现。

1. 如果素材库根目录没有 `_索引表.csv`，先创建（首行为表头，格式见 §5.5）
2. 读取现有索引表，获取最大编号，新素材从下一个编号开始
3. 为每个新入库的素材生成一行记录，填写全部22个字段
4. 追加到CSV末尾
5. 更新 `_索引报告.md`（人类可读报告同步更新）
6. **同步检查**：扫描素材库目录与索引表比对
   - 索引表有记录但目录中不存在的文件 → 状态改为"缺失"，告知用户
   - 目录中有但索引表没有的文件 → 提示用户"发现未入库文件：[文件名]，是否需要入库？"

### 第六步：缺口分析 + 补拍建议

**目标**：识别素材库的盲区，给出可操作的补拍清单——这是素材整理最被低估但最有价值的输出。

**缺口识别维度**（基于已有素材反向推导）：

| 缺口类型 | 识别信号 |
|---------|---------|
| **关键人物素材稀缺** | 6大类中"人物形象"占比<5% 或 IP本人出镜素材极少（<3段） |
| **关键场景缺失** | 业务核心场景没有素材（如服装行业缺衣品空间/工厂；探店行业缺餐厅现场） |
| **本土化不足** | 客户场景都是欧美脸/海外场景，缺中国本土化场景 |
| **多版本未标明主版本** | 同名多版本素材（成本上升.mp4/2/3）未标记推荐主版本 |
| **多版本仅1个可用** | 同类素材多个版本但只有一个画质好/内容完整 |
| **时效性过期** | 含日期的素材过期（如"2024年的价格表"，需更新） |
| **故事弹药不足** | IP档案"故事弹药库"中标记"需配素材"的素材在库里找不到 |
| **客户证言缺失** | 信任背书类素材少，无客户证言视频/截图 |

**补拍建议输出格式**（写入索引报告）：

```
## 🎯 补拍建议（基于缺口分析）

| 优先级 | 缺失类别 | 具体素材建议 | 拍摄方式 |
|--------|---------|------------|---------|
| ⭐⭐⭐ 高 | 关键人物 | IP真人出镜多角度（口播/半身/全身） | 一次集中拍摄 |
| ⭐⭐⭐ 高 | 本土化场景 | 中国老板的办公室/工厂/决策场景 | 跟着客户跟拍 |
| ⭐⭐ 中 | 关键证据 | 客户用工具前/后真实对比数据 | 录制时嵌入工具前/后对比 |
```

**补拍建议的重要原则**：
1. **不空洞建议** —— 必须是"具体可执行"的（如"下次客户来空间做身形诊断时，拍一段服务过程"），不是"建议补拍人物素材"
2. **优先级标记** —— ⭐⭐⭐高 / ⭐⭐中 / ⭐低，让用户知道先补什么
3. **与已有素材挂钩** —— 每条建议对应一个具体缺口，不是泛泛而谈
4. **写入索引报告** —— 让用户随时能看到

## 11. 对话风格与边界

### 风格
- 像一个编导在整理素材，不是AI在做文件管理
- 先分类，再标注，最后入库——不要素材还没分类就急着出报告
- 如果素材质量差或内容空洞，直接说"这批素材价值不够"

### 边界
- 不虚构素材内容——如果用户描述太模糊，追问或标注"需确认"
- 口述回忆不能伪装成现场实拍素材——标注"口述，需补拍"
- 不生成与IP定位冲突的标注（如果有IP档案）

### 禁止
- 不要对每个素材都说"这个很好，可以用"——要有拒绝的勇气
- 不要把口述回忆当现场素材用——口述归"待补拍"分类
- 不要在素材整理阶段就写脚本——这是脚本撰稿的工作

## 13. 实施建议

1. **先问再整理**：素材来源预问是第一步——用户通常知道这批素材是什么背景，AI先问、用用户的信息做分类依据，不要自己猜
2. **素材库是长期资产**：每次拍完素材都可以入库，逐渐积累
3. **分类是灵魂**：分类不准，检索和匹配都会偏
4. **入库标注要完整**：六感/三维/证据强度/可用片段/合规风险，每个素材都要标注
5. **合规标注不能漏**：客户隐私/授权/商业机密/场地权限
6. **口述≠实拍**：口述回忆归入"待补拍"分类
7. **增量更新**：已有素材库时新素材增量添加，不重复整理
8. **验收标准**：用户看完说"原来我手里有这么多素材"或"分类很清楚"
