# content-production-planner — 制作策划

> 脚本写完了，拿着一堆文字去拍还是不知道怎么下手。这个skill把脚本翻译成可执行的拍摄方案——每段旁白对应拍什么画面、哪些素材已经有了、拍摄顺序怎么排最高效、现场该问IP什么问题。

---

## 1. 触发词

- `帮我做拍摄方案`
- `出个分镜`
- `拍摄清单`
- `规划一批内容`
- `这条脚本怎么拍`
- `帮我排一下拍摄计划`
- `出个拍摄指令`

---

## 2. 核心定位

**不是"帮你写一份漂亮的策划文档"，而是"帮拍摄团队拿到就能干活的操作指令"。**

脚本是给IP和编导看的——讲什么、怎么说。
制作策划是给拍摄团队和剪辑看的——拍什么、怎么拍、用什么顺序拍。

本Skill的工作是：
1. 读懂脚本，把每段旁白/口播拆解成具体的拍摄指令
2. 检查素材库，标注哪些画面已有、哪些必须补拍
3. 按场景/时间分组，排出最高效的拍摄顺序
4. 如果是批量内容，做整体拍摄规划（一次拍多条）
5. 为需要IP现场表达的内容，设计引导提问
6. 标注风险——隐私/授权/场地/合规

**一句话**：脚本撰稿解决"说什么"，制作策划解决"怎么拍"。

---

## 3. 输入

### 必需

| 输入 | 来源 | 说明 |
|------|------|------|
| **脚本文件** | content-script-writer 产出 | 完整的脚本md文件，含段落结构、画面指引、补录清单、事实标注 |

### 可选（增强输出质量）

| 输入 | 来源 | 用途 |
|------|------|------|
| **IP档案** | content-ip-manager | 语言风格参考、拍摄偏好（是否出镜/是否面对镜头） |
| **素材库索引** | content-material-library | 检查已有素材，标注哪些画面可直接用 |
| **季度规划表** | content-marketing-strategy-map | 批量模式——一次规划多条内容的拍摄计划（来自战略大盘/营销日历） |
| **视频类型方法论** | references/{type}-methodology.md | 拍摄配置适配（不同类型的机位/景别/输出物组合不同） |

> **如果没有素材库索引**：拍摄清单中所有画面标注为"需拍摄"，不做已有素材匹配。
> **如果没有IP档案**：现场提问卡使用通用模板，不做个性化调整。
> **如果没有方法论文件**：使用默认拍摄配置（通用三机位+标准景别组合）。

## 4. 两种工作模式

### 模式A：单条模式（标准流程）

用户拿着一条脚本进来，AI生成这条内容的完整拍摄方案。

**典型场景**：
- "这条脚本帮我出个拍摄方案"
- "出个分镜表"
- "这条旁白视频怎么拍"

**流程**：脚本文件 → 方向锁定 → 段落拆解 → 素材匹配 → 生成4大输出物 → 风险提示

### 模式B：批量模式（多内容合并拍摄）

用户拿着多条脚本（或季度规划表+多条脚本）进来，AI做整体拍摄规划——哪些内容可以一次拍完、怎么排序最省事。

**典型场景**：
- "这周5条内容帮我排个拍摄计划"
- "这3条脚本能一起拍吗"
- "季度规划表里的W1-W2内容帮我做个拍摄方案"

**流程**：多脚本文件 → 方向锁定 → 批量层级规划 → 逐条拆解 → 合并拍摄清单 → 排序优化 → 生成整体策划案+各条分镜表+统一提问卡

**批量模式的核心价值**：
- 同场景的内容合并拍——减少场地转换
- 同妆造的内容合并拍——减少换装时间
- 识别一鱼多吃机会——一次拍摄多条内容用
- 排出拍摄优先级——重要内容先拍，状态最好的时候拍

## 5. 工作流

### 第一步：输入确认与方向锁定

**目标**：确认脚本完整，锁定拍摄方向。

**确认清单**：

| 确认项 | 说明 |
|--------|------|
| **视频类型** | 从脚本头部读取"视频类型"字段 → 决定拍摄配置和输出物组合 |
| **段落结构** | 读取脚本正文，确认有多少段、每段的画面指引是什么 |
| **补录清单** | 读取脚本尾部的补录清单 → 这是拍摄清单的基础 |
| **事实核验清单** | 读取脚本的事实核验清单 → 标注哪些需要拍摄前确认 |
| **IP出镜情况** | 从脚本画面指引判断：IP是否需要出镜？面对镜头还是侧拍？ |
| **素材库状态** | 有素材库索引 → 检查已有素材；无 → 全部标注"需拍摄" |
| **方法论状态** | 加载对应视频类型方法论（如存在）的拍摄配置部分 |

**方向锁定输出**：
```
拍摄方向确认：
- 脚本：[脚本文件名]
- 视频类型：[类型名] — 决定拍摄配置
- 段落数：[N段] — 每段都需要对应拍摄指令
- IP出镜：[是/否] — [面对镜头/侧拍/仅旁白]
- 补录清单：[N项] — 其中[X]项必须补拍，[Y]项可用已有素材
- 事实核验：[N项] — 需拍摄前与IP确认
- 素材库匹配：[已匹配X项/无素材库，全部需拍]
- 方法论加载：[已加载XXX拍摄配置/使用默认配置]
- 工作模式：[单条/批量]
```

### 第二步：层级规划

**单条模式**：跳过战略层，直接进入战斗层。

**批量模式**：执行三级规划。

#### 战略层（整体拍摄规划）

| 规划项 | 说明 |
|--------|------|
| **内容总量** | 本次拍摄涉及几条内容 |
| **拍摄session** | 分几次拍完（一次半天/一天/多天） |
| **场地需求汇总** | 所有内容涉及的场地，去重后排序 |
| **妆造需求汇总** | 是否需要换装、换装次数 |
| **人员需求** | IP/拍摄/化妆/道具/其他 |
| **一鱼多吃机会** | 哪些场景可以顺便拍其他内容的素材 |

#### 战役层（单次拍摄session规划）

| 规划项 | 说明 |
|--------|------|
| **本次session拍什么** | 哪几条内容在这次拍 |
| **拍摄顺序** | 按场地分组 → 同场景的内容集中拍 |
| **时间分配** | 每条内容预计拍摄时间 |
| **转场安排** | 场地之间的移动路线 |

#### 战斗层（单条内容拍摄指令）

进入第三步，逐条拆解。

### 第三步：段落拆解 → 证据匹配 → 拍摄指令

**这是核心步骤——把脚本的每一段翻译成可执行的拍摄指令。**

#### 3.1 段落拆解

读取脚本的每一段（段落1、段落2...），提取：

| 提取项 | 来源 | 说明 |
|--------|------|------|
| **旁白/口播文字** | 脚本正文 | 这段说什么 |
| **画面指引** | 脚本正文"画面"字段 | 脚本建议拍什么画面 |
| **时长** | 段落标注的时间区间 | 这段多长 |
| **事实状态** | 脚本"事实状态"字段 | 事实/判断/推测 → 影响拍摄精度要求 |
| **补录需求** | 脚本"补录清单" | 这段需要拍什么素材 |

#### 3.2 证据匹配

对每一段的画面需求，执行素材匹配：

```
这段画面需要：[画面描述]
├─ 素材库搜索 → 有匹配素材？
│   ├─ 有 → 标注"已有素材"，记录素材路径
│   └─ 无 → 标注"需拍摄"
├─ 拍摄类型 → 截图/录屏/实拍/动画
├─ 拍摄条件 → 需要什么道具/场地/人物
└─ 风险标注 → 隐私/授权/合规
```

#### 3.3 生成拍摄指令

每一段生成一条拍摄指令：

```
段落[X]拍摄指令：
- 对应旁白："[旁白文字前20字]..."
- 画面内容：[具体拍什么]
- 拍摄方式：[截图/录屏/实拍/侧拍/面对镜头]
- 景别：[特写/中景/远景/全景]
- 机位/角度：[正面/侧面/俯拍/仰拍/平视]
- 运镜：[固定/推/拉/摇/移/跟拍]
- 道具/素材：[需要什么道具或已有素材]
- 时长：[X秒]
- 优先级：[必须拍/最好拍/可选]
- 风险：[无/隐私处理/需授权/...]
```

### 第四步：生成4大输出物

根据视频类型确定输出物组合（见§6），然后生成。

#### 输出物1：策划案

**给谁看**：操盘手/制作人/IP本人
**解决什么**：整体怎么拍、要什么资源、什么顺序

内容结构：
1. **拍摄概述**：拍什么内容、几条、什么类型
2. **拍摄session规划**：分几次拍、每次拍什么
3. **资源需求清单**：场地/道具/人员/设备
4. **拍摄顺序**：按场景分组的拍摄时间表
5. **一鱼多吃提示**：这次拍摄还能顺便拍到什么
6. **风险提示**：隐私/授权/场地限制/合规

#### 输出物2：拍摄清单

**给谁看**：拍摄团队
**解决什么**：每个镜头拍什么、哪些已有、哪些要拍

内容结构：
表格形式，每行一个镜头：

| 镜头# | 所属段落 | 画面内容 | 拍摄方式 | 素材状态 | 道具需求 | 优先级 | 风险 |
|--------|---------|---------|---------|---------|---------|--------|------|

- **素材状态**：✅已有素材（标注路径）/ ❌需拍摄 / ⚠️需补拍（已有但不完整）
- **优先级**：🔴必须拍 / 🟡最好拍 / 🟢可选
- 按场景分组排列，同场景的镜头在一起

#### 输出物3：分镜表

**给谁看**：摄影师/导演
**解决什么**：每个镜头怎么拍——景别/机位/运镜/时长

内容结构：
表格形式，每行一个镜头：

| 镜头# | 旁白/口播（摘要） | 画面描述 | 景别 | 机位/角度 | 运镜 | 时长 | 备注 |
|--------|-----------------|---------|------|----------|------|------|------|

- 与拍摄清单的镜头编号一一对应
- 备注：特殊要求（如"模糊处理客户信息"、"需客户授权后使用"）

#### 输出物4：现场提问卡

**给谁看**：导演/IP本人
**解决什么**：需要IP现场表达的内容，怎么引导他说出来

**不是所有视频类型都需要提问卡**——旁白视频不需要（IP不说话），场景口播不需要（有逐字稿）。提问卡主要用于：
- VLOG视频（现场采访/即兴表达）
- 嘉宾访谈（提问设计）
- 探访跟拍（现场引导）
- 人物对谈（话题设计）

内容结构：

```
## 现场提问卡

### 开场破冰（5分钟）
- Q1: [问题] — 目的：[要得到什么素材]
- Q2: [问题] — 目的：[要得到什么素材]

### 核心内容引导
- Q3: [问题] — 目的：[对应脚本段落X]
  - 追问：如果他说了[XX]，追问[YY]
  - 追问：如果他没说到[ZZ]，引导[WW]
- Q4: [问题] — 目的：[对应脚本段落Y]
  ...

### 收尾
- QN: [问题] — 目的：[CTA素材/结尾金句]
```

**提问设计原则**：
1. **不要问封闭式问题**——"你觉得这个重要吗？"→"你当时怎么处理这个的？"
2. **给IP讲故事的空间**——不要问"是"或"不是"的问题，问"然后呢？""怎么做的？"
3. **标注每个问题的目的**——这个问题对应脚本的哪一段，要得到什么素材
4. **设计追问路径**——IP可能不会按脚本走，准备好Plan B

### 第五步：风险提示与一鱼多吃

#### 风险扫描

检查所有拍摄指令中的风险：

| 风险类型 | 检查什么 | 处理方式 |
|---------|---------|---------|
| **隐私泄露** | 拍摄内容是否暴露客户真实信息 | 标注"需模糊处理"的具体字段 |
| **授权缺失** | 使用客户素材是否已获授权 | 标注"需获取授权"的具体素材 |
| **场地限制** | 拍摄场地是否需要许可 | 标注"需确认场地许可" |
| **合规风险** | 拍摄内容是否有行业合规限制 | 标注具体合规要求 |
| **事实核验** | 脚本中标注的事实核验项 | 列入"拍摄前确认清单" |
| **IP状态风险** | IP是否适合拍摄（状态/妆造/时间） | 标注注意事项 |

#### 一鱼多吃提示

检查本次拍摄的每个场景，识别额外素材收集机会：

```
一鱼多吃提示：
- [场景A]拍摄时，顺便拍：
  - [额外素材1] → 可用于[未来内容方向]
  - [额外素材2] → 可用于[未来内容方向]
- [场景B]拍摄时，顺便拍：
  - [额外素材3] → 可用于[未来内容方向]
```

一鱼多吃素材类型：
1. **空镜素材**——场地环境、氛围镜头，未来做B-roll用
2. **工作过程**——IP日常工作片段，未来做VLOG用
3. **即兴表达**——让IP即兴聊聊某个话题，未来做观点口播用
4. **客户互动**——如果有客户在场，征得同意后拍互动过程

## 6. 视频类型适配

不同视频类型的拍摄方式不同，输出物组合也不同。

### 适配矩阵

| 视频类型 | 拍摄核心 | 策划案 | 拍摄清单 | 分镜表 | 提问卡 | 特殊配置 |
|---------|---------|--------|---------|--------|--------|---------|
| **旁白视频** | 证据画面配对 | ✅ | ✅ | ✅ | ❌ | 画面素材收集优先，IP可能不出镜 |
| **VLOG视频** | 跟随式拍摄 | ✅ | ✅ | ✅ | ✅ | 时间线拍摄，关键节点标注 |
| **场景口播** | 场景布置+机位 | ✅ | ✅ | ✅ | ❌ | 固定机位为主，注重场景感 |
| **观点科普** | 口播+辅助画面 | ✅ | ✅ | ✅ | ❌ | 可能需要图表/动画辅助 |
| **场景切片** | 长视频截取 | ✅简化 | ✅ | ❌ | ❌ | 从已有素材中截取，非实拍 |
| **探访跟拍** | 探访路线设计 | ✅ | ✅ | ✅ | ✅ | 空间展示+人物引导 |
| **嘉宾访谈** | 提问设计+双机位 | ✅ | ✅ | ✅ | ✅ | 双机位（主机位+侧机位） |
| **人物对谈** | 话题设计+多机位 | ✅ | ✅ | ✅ | ✅ | 多机位（全景+双人特写） |
| **剧情演绎** | 剧本分镜+演员调度 | ✅ | ✅ | ✅ | ❌ | 完整分镜脚本，非口播分镜 |
| **博客日记** | 日常记录式 | ✅简化 | ✅简化 | ❌ | ✅简化 | 轻量化拍摄，手机可拍 |
| **信息流投放** | 产品展示+口播 | ✅ | ✅ | ✅ | ❌ | 注重产品画面质量 |

> **方法论文件不存在时**：使用通用拍摄配置——标准三机位（正面/侧面/全景）、标准景别组合（特写/中景/远景）、固定机位为主。

### 类型特异的拍摄配置

详细的类型特异拍摄配置见 `references/shooting-configs.md`。

加载规则：
1. 从脚本头部读取"视频类型"字段
2. 查找 `references/shooting-configs.md` 中对应类型的配置
3. 如果方法论文件（`content-script-writer/references/{type}-methodology.md`）存在且包含拍摄相关内容，一并加载
4. 配置加载后，在分镜表和拍摄清单中应用对应规则

## 7. 与其他Skill的衔接

### 上游（输入）

| 上游Skill | 衔接方式 | 数据流 |
|-----------|---------|--------|
| **content-script-writer** | 读取脚本文件 | 脚本md文件 → 段落结构、画面指引、补录清单、事实标注 |
| **content-ip-manager** | 读取IP档案 | IP出镜偏好、语言风格、拍摄禁忌 |
| **content-material-library** | 读取素材库索引 | 已有素材匹配、素材路径 |
| **content-marketing-strategy-map** | 读取战略大盘/日历的批量规划 | 多条内容的拍摄规划、优先级排序 |

### 下游（输出）

| 下游环节 | 衔接方式 | 数据流 |
|---------|---------|--------|
| **实际拍摄** | 输出物直接使用 | 策划案+拍摄清单+分镜表+提问卡 → 拍摄团队执行 |
| **content-video-cutter** | 拍摄完成后 | 原始素材 → 切片入库 → 素材库更新 |
| **content-material-library** | 拍摄完成后 | 新素材入库 → 素材库索引更新 |
| **content-quality-guard** | 发布前 | 审查拍摄成片是否与脚本一致 |

### 数据流全景

```
IP档案 → 选题引擎 → 脚本撰稿 → 质量守门 → 【制作策划】 → 拍摄 → 切片/素材入库
                                              ↓
                                         策划案+拍摄清单+分镜表+提问卡
```

## 8. 方法论加载机制

制作策划加载方法论的方式与脚本撰稿相同，但关注的部分不同：

| 方法论部分 | 脚本撰稿用 | 制作策划用 |
|-----------|-----------|-----------|
| 类型定义 | ✅ 理解类型特征 | ✅ 理解拍摄特点 |
| 适合性检查 | ✅ 判断是否适合 | ❌ 不用 |
| 内容方向 | ✅ 选择内容方向 | ❌ 不用 |
| 场景框架 | ✅ 参考场景设计 | ✅ **核心使用**——拍摄场景/人物/画面框架 |
| 素材分类 | ✅ 参考素材需求 | ✅ **核心使用**——拍摄清单的素材分类 |
| 脚本格式 | ✅ **核心使用** | ❌ 不用 |
| 钩子模板 | ✅ **核心使用** | ❌ 不用 |
| 信任信息配比 | ✅ 参考配比 | ❌ 不用 |
| 校验规则 | ✅ **核心使用** | ✅ 参考使用——检查拍摄方案是否满足方法论要求 |

**加载流程**：
1. 从脚本头部读取视频类型
2. 查找 `content-script-writer/references/{type}-methodology.md`
3. 提取"场景框架"和"素材分类维度"部分用于拍摄清单
4. 提取"校验规则"部分用于最后验收
5. 文件不存在 → 使用 `references/shooting-configs.md` 中的通用配置

## 9. 验收标准

制作策划输出物交付前，逐项检查：

| # | 检查项 | 标准 | 不通过处理 |
|---|--------|------|-----------|
| 1 | **段落覆盖** | 脚本每一段都有对应的拍摄指令 | 补充缺失段落 |
| 2 | **素材状态** | 每个镜头标注了"已有/需拍/需补拍" | 补充标注 |
| 3 | **优先级标注** | 每个镜头标注了优先级（必须/最好/可选） | 补充标注 |
| 4 | **场景分组** | 同场景的镜头排列在一起 | 重新排序 |
| 5 | **风险标注** | 隐私/授权/合规风险全部标注 | 补充标注 |
| 6 | **事实核验** | 脚本的事实核验项列入拍摄前确认清单 | 补充 |
| 7 | **一鱼多吃** | 识别了额外素材收集机会 | 补充 |
| 8 | **输出物完整** | 按视频类型输出了对应的输出物组合 | 补充缺失输出物 |
| 9 | **方法论校验** | 如方法论存在，检查拍摄方案是否满足方法论要求 | 调整方案 |
| 10 | **可执行性** | 拍摄团队拿到就能干活，不需要再猜 | 简化指令、补充细节 |

## 10. 示例对话

### 场景1：单条模式

**用户**：这条旁白视频脚本帮我出个拍摄方案

**AI**：
> 读取脚本...确认方向：
> - 视频类型：旁白视频 — 证据画面配对型拍摄
> - 7段旁白，每段都有画面指引
> - 补录清单7项，其中1项必须补拍
> - IP不出镜（纯旁白），拍摄重点是画面素材收集
> - 素材库未找到，全部需拍摄/收集
>
> 开始生成拍摄方案...

### 场景2：批量模式

**用户**：这周3条内容帮我排个拍摄计划，能一起拍的合并

**AI**：
> 读取3条脚本...
> - 脚本A：旁白视频，需云吞面馆+维港场景
> - 脚本B：场景口播，需办公室场景
> - 脚本C：旁白视频，需维港+办公室场景
>
> 场景合并分析：
> - 维港场景：脚本A+C可合并拍（同一天维港取景）
> - 办公室场景：脚本B+C可合并拍（同一天办公室）
> - 云吞面馆：脚本A独有，单独安排
>
> 建议分2次拍摄：
> - Session 1（半天）：办公室 → 拍脚本B全部 + 脚本C办公室部分
> - Session 2（半天）：云吞面馆 → 维港 → 拍脚本A全部 + 脚本C维港部分
>
> 开始生成详细方案...

### 场景3：VLOG视频（需要提问卡）

**用户**：这条VLOG脚本出个拍摄方案

**AI**：
> 读取脚本...确认方向：
> - 视频类型：VLOG视频 — 跟随式拍摄+现场采访
> - IP需要出镜，有即兴表达环节
> - 5个关键节点，每个节点需要引导IP说话
>
> 生成提问卡...
> - 开场破冰：2个问题
> - 核心内容：5个问题（对应5个节点），每个设计追问路径
> - 收尾：1个问题（CTA引导）
>
> 开始生成完整方案...
