# 视觉配图心法（content-illustrator）— 内容配图 Skill

> 文案写好之后，配图不该再是「随便找张图」。本 Skill 把 content-script-writer 输出的**朋友圈文案**与**公众号文章**变成风格统一、与文案同声的配图资产。

---

## 1. 触发词

### 朋友圈配图类
- `给这条朋友圈配图`
- `朋友圈配图` / `朋友圈配张图`
- `发圈的图` / `朋友圈图片`
- `把配图做了` / `配图建议落地`
- `这条朋友圈配几张图`

### 公众号配图类
- `给这篇文章配图` / `公众号配图`
- `公众号插图` / `文章插画`
- `给文章加图` / `推文配图`
- `长文配图` / `深度文配图`

### 封面图类
- `给公众号做封面` / `公众号封面` / `文章首图`
- `视频封面` / `视频缩略图` / `口播封面`
- `做张封面图` / `封面图` / `头图`
- `分享卡` / `转发封面`

### 上游联动（content-script-writer 产出后）
- 模式C 交付里的「**配图建议**」字段 → 本 Skill 把它从「类型方向」变成「真实图片」
- 模式D 边界里「**不含配图…由其他环节负责**」→ 本 Skill 接管公众号配图

---

## 2. 核心定位

**不是「帮你找张网图」，而是「帮你的内容配上它该有的图」。**

- 朋友圈的图是**卡片**——独立、抢眼、能单张成立，文字负责钩住、图片负责说服（模式C 六条铁律第5条）。
- 公众号的图是**插画**——嵌入文章结构，在核心论点、抽象概念、数据对比、流程处补位（模式D 任务书/主张清单驱动的论证补强）。

两种配图都遵循同一套底层纪律（见§5）：**先存提示词文件再出图、确认后生成、CJK 文字零乱码、绝不用 SVG/HTML 替代位图、IP 视觉风格对齐**。

**与文案 skill 的关系**：
- 本 Skill 是 **下游**。朋友圈模式吃「模式C 成稿 + 配图建议」；公众号模式吃「模式D 成稿 + brief + claims」。
- 本 Skill **不写文案、不写文章**——那是 content-script-writer 的职责。它只解决「配图」这一环。
- 若有 IP 档案（content-ip-manager 产出），本 Skill 读取**风格定位**与**精神内核**，把 IP 的「声」翻译成「视觉调性」（见§9）。

---

## 3. 两种工作模式

### 模式M：朋友圈配图

把一条朋友圈文案拆成 **1-3 张图卡**（默认 1 张封面卡；含强观点/多要点时可 2-3 张）。

**来源**：xhs-images 的「图卡系列」范式——Style × Layout × Palette 三个维度自由组合，image-1 锚点链保证系列一致性。

**典型场景**：
- "这条朋友圈帮我配张图"
- "配图建议说用 1-3 张图，给我出"
- "这篇口播发朋友圈，顺手配个图"

**流程**：输入确认 → 视觉机会分析（封面/内容/结尾）→ **自动匹配 Top-3 风格，各出一张样张（3 张不同风格）→ 用户挑选其一**（或显式指定单一风格覆盖默认）→ 大纲 outline.md → 提示词 prompts/ → 生成（选定风格后锚点链）→ 交付（图片 + 插入建议）

### 模式A：公众号配图

按公众号文章结构，在 **关键论证位置** 生成 1-N 张插画（信息图/场景/流程/对比/框架/时间线）。

**来源**：article-illustrator 的「文章配图」范式——Type × Style × Palette，先分析结构定位配图位置，再逐张出图。

**典型场景**：
- "这篇公众号文章帮我配图"
- "这个对比观点加张对比图"
- "文章里那个框架画成图"

**流程**：输入确认（文章 + brief + claims）→ 结构分析定位配图位置 → **确认该篇统一风格（系统自动匹配 Top-1／用户指定一种）；⚠️ 同一篇文章所有插画强制共用该 Style+Palette（硬规则，非选项）** → 确认设置（Type×Style×Palette×密度）→ 大纲 outline.md → 提示词 prompts/ → 生成（全篇共用同一 Style+Palette）→ 交付（图片 + 文章内插入位置）

### 模式K：封面图

把**公众号文章成稿**或**视频脚本成稿**变成用于发布的封面/头图/缩略图。

**来源**：cover-image 的「五维体系」范式——Type × Palette × Rendering + Text/Mood + Font/Aspect，改编为可在 content-illustrator 内统一运行的封面流程（详见 references/cover-methodology.md）。

**典型场景**：
- "给这篇公众号文章做个封面"
- "视频封面帮我出一张"
- "这篇口播配个缩略图"

**两个子场景**：
- **公众号封面**：读模式D 成稿的「标题区」+ brief 核心主张 → 出 16:9 首图 / 2.35:1 头图横幅 / 1:1 分享卡
- **视频封面/缩略图**：读模式A/B 脚本钩子 → 出 16:9 横屏 / 3:4 竖屏封面

**流程**：输入确认（成稿标题/钩子 + IP 档案风格定位）→ **五维自动匹配 Top-3 风格组合（Type/Palette/Rendering 各取最优，生成 3 张不同风格样张）→ 用户挑选其一**（或显式指定单一组合）→ 大纲 outline.md → 提示词 prompts/ → 生成 → 交付（图片 + 插入位置 + 平台建议）

> 朋友圈封面由**模式M 的封面卡**承担，本模式 K 主要服务公众号封面 + 视频封面。

## 4. 统一维度

两个模式共用「**风格 × 配色**」底座，差异在第三个维度：

| 模式 | 第三维度 | 控制什么 |
|------|---------|---------|
| 朋友圈（M） | **布局 Layout** | 单卡信息密度与排布（sparse/balanced/dense/list/comparison/flow/mindmap/quadrant） |
| 公众号（A） | **类型 Type** | 插画的信息结构（infographic/scene/flowchart/comparison/framework/timeline） |
| 封面（K） | **类型 Type + 渲染 Rendering** | 封面整体调性、文字层级（五维：Type/Palette/Rendering/Text/Mood + Font/Aspect） |

> **朋友圈（M）与封面（K）默认自动匹配 Top-3 风格**：两种模式都按 IP 风格定位（或内容信号）评分排序，取最匹配的 **前 3 种风格**，各自生成一张样张让用户挑；用户可显式指定单一风格跳过样张。公众号（A）因一篇文章多张图，**强制单篇统一风格**：生成前确认该篇用哪一种统一风格（由 IP 定位或内容信号自动匹配 Top-1，用户可覆盖；"多种风格"指跨文章多样，非单篇内多风格）。

**风格 Style（两模式共用精选集）**：

| 风格 | 观感 | 朋友圈适配 | 公众号适配 |
|------|------|-----------|-----------|
| `notion` | 极简手绘线条·知识感 | 知识/观点卡 | 干货/框架文 |
| `warm` | 温馨·亲和力 | 情感/故事/种草 | 人物故事文 |
| `minimal` | 极简高级·精致 | 金句/专业封面 | 专业总结/商务 |
| `sketch-notes` | 手绘教育信息图·马卡龙纸底 | 教程/清单 | 概念科普 |
| `bold` | 高冲击·引人注目 | 观点/避坑/警告 | 观点文封面 |
| `screen-print` | 大胆海报·网点半色调 | 氛围封面 | 观点/文化评论 |
| `fresh` | 清新自然·干净 | 生活/种草/自然 | 健康/生活方式 |
| `cute` | 甜美可爱 | 种草/日常 | （少用，除非IP人设匹配） |
| `chalkboard` | 彩色粉笔黑板·教学 | — | 教程/操作步骤 |
| `vector-illustration` | 扁平矢量·黑描边 | 清单/对比 | 信息图/数据 |

**配色 Palette（可选覆盖，替换风格默认色）**：

| 配色 | 底色 | 区域色 | 强调 | 调性 |
|------|------|--------|------|------|
| `macaron` | 暖奶油 #F5F0E8 | 蓝/薰衣草/薄荷/桃 | 珊瑚 #E8655A | 柔和教育风 |
| `warm` | 柔桃 #FFECD2 | 橙/陶土/金/玫瑰 | 赭石 #A0522D | 大地色·温馨 |
| `neon` | 深紫 #1A1025 | 青/品红/绿/粉 | 黄 #FFFF00 | 高能量·未来感 |

> 无 `--palette` → 用风格内置色；`--palette <名>` → 只换色，渲染规则不变。

**IP 视觉风格对齐（来自 IP 档案 风格定位）**：

| IP 风格定位（文字） | 推荐视觉风格 |
|--------------------|-------------|
| 大白话、犀利直接、戳痛点 | `bold` / `minimal` |
| 温柔、有温度、共情 | `warm` / `sketch-notes` |
| 专业沉淀、理性靠谱 | `notion` / `minimal` |
| 教育者、爱讲方法 | `sketch-notes` / `chalkboard` |
| 生活方式、审美在线 | `fresh` / `minimal` |
| 观点鲜明、爱输出立场 | `screen-print` / `bold` |

无 IP 档案时，按内容类型自动推荐（见各模式方法论的自动匹配表）。

## 5. 底层纪律（两模式通用，硬规则）

### 5.1 图片生成后端解析

出图前按以下顺序确定后端：

1. **当前请求指定**——用户在本条消息点名某个后端，则用它。
2. **本地图像生成能力**——若运行时暴露了图像生成工具（如 `ImageGen` / `GenerateImage` 等原生位图工具），优先用原生工具。这是本环境的默认后端。
3. **多个非原生后端**——问用户一次（与确认步骤合并）。
4. **无任何后端**——明确告知用户并询问如何继续，**不得**静默用 SVG/HTML/Canvas 替代。

**⛔ 绝不用 SVG / HTML / Canvas / 代码渲染替代位图**。配图是发布资产，必须是位图（PNG/JPG）。即便内容像「图表」，也走位图后端出图。

### 5.2 提示词文件优先（硬性）

每一张图**出图前**必须把最终完整提示词写入独立文件 `prompts/NN-{type-or-layout}-{slug}.md`（YAML frontmatter + 正文）。该文件是：
- 可复现记录（换后端不用重写提示词）；
- 一致性校验基准（系列图共用同一风格描述）。

**禁止**不经提示词文件直接把临时文本丢给后端。

### 5.3 确认后生成（默认）

默认**生成前确认一次**（AskUserQuestion，合并风格/布局或类型/配色/张数等问题，≤4 问）。

- 以下表述视为**显式跳过确认**：`直接生成` / `不用确认` / `跳过确认` / `按默认出图` / `配图建议落地`。
- 跳过时，在下一条用户可见更新里**先声明**假设的风格/布局/配色/张数/后端，再出图。

> **Top-3 样张机制（模式M / 模式K）**：这两种模式默认不弹「选风格」题，而是直接出 **3 张不同风格的样张**让用户挑——样张即选风格。仍会确认布局/张数/比例（除非说"直接生成"）。用户显式指定单一风格（如"用 warm"）或说"出一张""按最匹配的来"时，按 Top-1 单张出图，不出 3 张。公众号（A）走"确认该篇统一风格"询问（不默认出 3 样张；风格在单篇文章内强制统一，跨文章可多样）。

### 5.4 批量生成

所有提示词文件就绪后默认批量出图：
- 后端原生批量接口优先；
- 运行时可并行调用则每批 ≤ `generation_batch_size`（默认 4）；
- 否则顺序出图。
- 失败项重试一次，不重生成成功项。

**出图后核对路径**：后端在并行调用时可能不分别采用 `output_dir`（如实测中 ImageGen 并行调用两张图落入了同一目录）。遇到这种情况：改用统一输出目录，出图后按 outline 移动到目标目录；或顺序调用确保每个 `output_dir` 生效。移动前按备份规则重命名冲突文件。

> **Top-3 样张彼此独立**：模式M / 模式K 的 3 张样张是不同风格对比用途，彼此**不要求锚点链**（锚点链仅用于用户选定某风格后，要出同风格多张系列图时启用）。

### 5.5 CJK 文字零乱码（关键）

含中文/日文/韩文等任何非拉丁文字的图（标签、标题、注解）：

1. 所有文字**必须完美清晰，零乱码、零缺笔、零错字**。
2. 只用标准易认排版（避免装饰性/实验性字形）。
3. 若模型不能稳定渲染中文：**减少/去掉图上文字**，用视觉、图标、布局传达；文字尽量短（标签 ≤3-5 字）。
4. **绝不交付乱码图**——生成乱码则重出（简化或去文字）。
5. 每个含文字的提示词都追加：`CRITICAL: All text must be perfectly legible with ZERO garbled characters or incorrect text. If text cannot be rendered perfectly, omit it entirely and use visual elements instead.`

### 5.6 文字不覆盖修复

**绝不**用 ImageMagick / Pillow / Canvas / SVG / HTML 等程序化叠加去修补已生成图里的文字。文字错了就**从修正后的提示词重出**，或改用少文字/无文字版式，或问用户保留哪张次品。

### 5.7 水印（可选）

若用户要求，在提示词追加：`Include a subtle watermark "[内容]" positioned at [位置].`  watermark 应清晰但不抢眼。

### 5.8 参考图（可选）

用户可用 `--ref <文件...>` 或贴图提供风格/构图参考：
- 文件路径 → 存入 `refs/NN-ref-{slug}.{ext}`，记入对应提示词 frontmatter 的 `references`（仅当文件确实存在）。
- 无路径仅描述 → 提取风格/配色文字，追加到提示词正文（不入 frontmatter）。
- 朋友圈模式：参考图叠加在 image-1 锚点链之上（见方法论）。

## 6. 工作流

```
- [ ] Step 1: 输入确认（读文案/文章 + 配图建议/brief + 可选 IP 档案）
- [ ] Step 2: 内容分析 → 视觉机会 / 配图位置
- [ ] Step 3: 风格策略（M/K：Top-3 样张挑一 / A：单篇统一风格确认 ⚠️ 硬规则）
- [ ] Step 4: 生成大纲 outline.md
- [ ] Step 5: 生成提示词 prompts/NN-*.md ⛔ 出图前必存
- [ ] Step 6: 出图（朋友圈锚点链 / 公众号风格一致 / 封面五维定调）
- [ ] Step 7: 交付（图片文件 + 插入建议 + 输出摘要）
```

详细步骤见：
- 朋友圈：**references/moments-methodology.md**
- 公众号：**references/article-methodology.md**
- 封面：**references/cover-methodology.md**
- 提示词构造模板：**references/prompt-templates.md**

## 7. 与 content-script-writer 的衔接

| 上游产出 | 模式 | 本 Skill 接管 |
|---------|------|--------------|
| 模式C 朋友圈文案 + 「配图建议」字段 | 模式M | 把「图片类型/张数/风格」方向变成真实图卡；读文案正文提取视觉机会 |
| 模式D 公众号成稿 + brief + claims | 模式A | 接管「不含配图」边界，按文章结构定位插画位置 |
| 模式D 公众号成稿 + 标题区 / brief 核心主张 | 模式K | 接管「公众号封面」——读原文标题作封面文字，五维定调（Type/Palette/Rendering/Text/Mood+Font/Aspect） |
| 模式A/B 视频脚本 + 钩子 | 模式K | 接管「视频封面/缩略图」——读脚本钩子作封面文字，按平台选 Aspect |

**数据流**：
```
content-script-writer（模式C/D 成稿 / 模式A/B 脚本）
    ↓ 配图建议 / 不含配图边界 / 标题·钩子
content-illustrator（模式M / 模式A / 模式K）
    ↓ 图片文件 + 插入建议
发布（朋友圈 / 公众号后台 / 视频平台）
```

**输入读取规则**：
- 若用户给了模式C 交付文件 → 读其「配图建议」「内容类型」「六感触发」作为模式M 的起点建议。
- 若用户给了模式D 交付文件 → 读其「框架」「正文各节」「claims 类型」作为模式A 定位配图位置的依据；读其「标题区」+ brief 核心主张作为模式K 封面文字与视觉隐喻来源。
- 若用户给了模式A/B 脚本文件 → 读其「钩子」「核心主张」作为模式K 视频封面文字来源。
- 始终优先用**原文案/文章正文**而非只依赖建议字段。

## 9. IP 视觉风格对齐

若存在 IP 档案（content-ip-manager 产出），读取：

| IP 档案字段 | 配图用途 |
|-----------|---------|
| **风格定位** | 翻译为视觉风格（§4 对齐表）；覆盖自动推荐的默认风格。模式K 封面用「风格定位 → 五维（Type/Palette/Rendering/Font）」映射，详见 references/cover-methodology.md §4.1 |
| **精神内核** | 配图情绪/调性与其一致（不把「不认命」画成「躺平」） |
| **红线清单** | 配图不碰红线（如财经 IP 不画「稳赚」类误导图；封面隐喻只用方案隐喻、不用立场隐喻） |
| **标签库** | 图中可复用 IP 专属标签作水印/角标 |

**无 IP 档案**：按内容类型自动匹配（见各模式方法论的自动匹配表），并建议用户先完成 IP 建档以获得风格一致性。

## 10. 边界

- **不写文案、不写文章**——那是 content-script-writer 的职责；本 Skill 只出图。
- **不编造事实**——图中文字只能来自文案/文章已确认内容或用户本次提供；不新增数据。
- **不覆盖修复文字**——乱码/错字从提示词重出，不程序化修补（§5.6）。
- **绝不用 SVG/HTML 替代位图**（§5.1）。
- **朋友圈图卡**默认 1:1（最兼容），可选 4:5 / 3:4；**公众号插画**默认 16:9（信息图/流程/对比），场景图可用 4:3 / 1:1；**封面图**默认 16:9（公众号首图/视频横屏），可选 2.35:1（头图横幅）/ 1:1（分享卡）/ 3:4（视频竖屏封面）。
- **高危行业（财经/医疗/法律）配图**：不画「收益保证」「治愈率」等越界承诺图；遵守模式C/D 已有的合规声明要求。
- **一致性是底线**：朋友圈选定风格后的同系列图用锚点链（图1 定调，后续以图1 为 ref）；公众号同一篇文章强制共用同一 Style+Palette（这是底线，非选项）；所谓"多种风格"仅指不同文章可各自选用不同统一风格，而非单篇内多风格；封面 Top-3 样张彼此独立，选定后再按该风格出同系列。

## 12. 示例对话

### 示例1：模式M — 朋友圈配图（Top-3 样张）

**用户**：这条朋友圈帮我配张图。[贴入模式C 交付：配图建议=1张·情感共鸣]

**AI**：好，读到你这条是情感共鸣类。按自动匹配，我给你出 **Top-3 风格样张**（warm / notion / bold）各一张，你挑最顺眼的那张用。布局默认 sparse，1:1。

> 出图中（3 张不同风格，同钩子句）……
>
> ✅ 配图/朋友圈/{slug}/01-cover-warm.png —— warm 温馨风
> ✅ 配图/朋友圈/{slug}/02-cover-notion.png —— notion 极简知识风
> ✅ 配图/朋友圈/{slug}/03-cover-bold.png —— bold 高冲击风
>
> 挑一张用；要同风格再出 2-3 张系列图（锚点链一致）就说一声。

**用户**：用 warm，再给我补一张内容卡。

**AI**：（warm 选定，内容卡以 01-cover-warm.png 为锚点链 ref）出图……

> ✅ 配图/朋友圈/{slug}/02-content-warm.png ✓ 内容卡（balanced，锚点链 warm）

> 插入建议：01 配文案最上方做情绪铺垫，02 配核心价值段旁。

### 示例2：模式A — 公众号配图

**用户**：这篇公众号文章帮我配图。[贴入模式D 成稿 + brief + claims]

**AI**：读到你这篇文章是「观点型」框架，claims 里有个强对比主张（C2）。我建议在 3 个位置配图：

> 配图位置：
> 1. 开头核心判断 → 框架图（framework）定调
> 2. C2 对比主张 → 对比图（comparison）左右分栏
> 3. 结尾行动建议 → 场景图（scene）收束
>
> 确认：Type 用 framework+comparison+scene（推荐）/ 统一 infographic？Style 用 notion（推荐）/ minimal？

**用户**：可以，按默认出。

**AI**：（声明假设后）已存 3 个提示词，批量出图……

> ✅ 配图/公众号/{slug}/01-framework-xxx.png → 插入「开头核心判断」段后
> ✅ 配图/公众号/{slug}/02-comparison-xxx.png → 插入「C2 对比」段后
> ✅ 配图/公众号/{slug}/03-scene-xxx.png → 插入「结尾行动」段后
>
> 注意：3 张虽 Type 不同（framework/comparison/scene），但 **Style 统一 notion**——单篇文章内风格必须一致，"多种风格"指跨文章多样，而非单篇内多风格。

### 示例3：模式K — 封面图（Top-3 样张）

**用户**：给这篇公众号文章做个封面。[贴入模式D 成稿：标题「万科高管被裁后，半年没发出一条朋友圈」]

> ✅ 配图/封面/{slug}/02-cover-elegant-digital.png —— elegant + digital（低调奢华·数字感）

>
> 标题都用了原文「万科高管被裁后，半年没发出一条朋友圈」，文字清晰无乱码。挑一张；要换比例（2.35:1 头图 / 1:1 分享卡）就说。
