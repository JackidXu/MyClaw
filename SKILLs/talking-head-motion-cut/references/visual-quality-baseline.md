# 视觉质量基准（Visual Quality Baseline）

本文件是技能的「质量底线」，高于一切风格变体和模板。每条视频必须逐条达标，不达标禁止渲染。

**本基准与风格无关**：无论通过 `style-skins/` 选浅色 / 深色 / 霓虹 / 奶油哪一种皮肤，以下九节全部强制适用。皮肤只改 `:root` 配色与底板光学，不改结构丰富度——所以"换皮"绝不等于"降质"。出片前必须再过 `quality-gate.md` 的可计数门禁（G1–G12），任何一项红禁止渲染。

---

## 一、设计系统（每条视频必须自建一套，不可直接套用 37 种风格变体）

37 种风格变体是「色板起点」，不是「成品设计」。每条视频必须为自身主题构建一套完整设计系统：

1. **调色板**：主背景、卡片表面、主文字、辅文字、强调色 ×2-3（语义分工：功能/问题/成功）、分割线
2. **字体层级**：至少 4 级——主标题(72-96px)、副标题(52-68px)、导语/正文(32-40px)、标签/kicker(22-28px)，各级字号差异 ≥1.3 倍
3. **卡片系统**：圆角(20-30px)、阴影(至少 2 层：近投影 + 远投影)、边框(1px 低透明度)、表面色
4. **网格系统**：72px 基线网格、内容安全区(左右 ≥72px、顶部 ≥196px、底部 ≥168px)
5. **纹理**：至少 1 种——颗粒噪点(5px radial-gradient)、纸纹、网格线、暗角，opacity 0.03-0.08

**禁止**：直接复制 style-variants.md 的色板变量当 `<style>` 用，不做上述 5 项设计决策。

---

## 二、景深层次（每场景至少 4 层，从后到前）

| 层 | 作用 | 示例 |
|---|---|---|
| L0 底板 | 纯色/渐变背景 | `--bg` + 径向光斑 |
| L1 纹理 | 网格/颗粒/暗角 | `.grid` + `.grain` + `.vignette` |
| L2 实拍窗 | b-roll 视频或图片，裁成圆角画框 | `.vframe` 含 `<video>` + veil + tag |
| L3 内容卡 | 白/深色卡片承载 UI mockup 或数据 | `.card` 含投影、圆角 |
| L4 前景叠层 | 印章、徽标、胶囊标签、浮动元素 | `.stamp` rotate -8~12° |

**每场景至少出现 L0+L1+L2/L3+L4 四层**。只有 L0+L3 两层的场景判定为「平面化」，禁止渲染。

---

## 三、UI 具象化（每场景至少 1 个具体界面/产品 mockup）

「抽象图形」（线框脑图、发光球、柱状图、箭头）是最低标准，不是成品。每个场景至少包含 1 个**具体可辨认的产品界面元素**：

| 类型 | 示例 |
|---|---|
| 手机界面 | 课表卡、聊天窗、通知列表、播放器 |
| 数据面板 | 指标卡、进度环、时间轴、柱状图 |
| 流程图 | 多步骤连线、任务清单、状态流转 |
| 文档/卡片 | 报价单、对比表、评价卡 |
| 设备三连屏 | 手机+平板+桌面并排 |

**禁止整条视频全是抽象图形**——如果 7+ 个场景没有一个具体界面 mockup，判定为「PPT 感」，禁止渲染。

UI mockup 用 HTML+CSS 搭建（不用图片），这样可以逐元素动画入场。

---

## 四、实拍素材使用（视频 b-roll 是硬性要求，不是可选项）

1. **必须搜索并下载 b-roll 视频素材**——Pexels/Pixabay/Coverr/Mixkit 至少搜 3 个关键词组合
2. **b-roll 当「窗口」用，不当全屏背景**——裁成圆角画框(896×330 / 480×560 / 720×420 等)，加 veil 暗化 + tag 标签
3. **每个 b-roll 窗口配 1 个 veil 层**——半透明渐变蒙版保证前景文字可读
4. **b-roll 视频在场景开始时播放**——GSAP `call()` 控制 `currentTime=0 + play()`
5. **搜不到视频才退图片**——必须在 `scene-plan.json` 里标注 `bg_type: "image"` 并说明搜了哪些关键词

**目标覆盖率**：至少一半场景含 b-roll 窗口（以 iWOD 满血范例 5/10 = 50% 为准；这是达标下限，越多越好）。不足一半的场景须用设计过的色块 / UI 面板 / 数据卡补足层次，不得整片纯色渐变当背景。

**禁止跳过视频搜索直接用 CSS 渐变当背景**。全条视频 0 条 b-roll 判定为违规。

---

## 五、动效丰度（每个节拍至少 3 组同时发生的动画）

「节拍」= 旁白说到一个语义点时对应的画面时刻。每个节拍至少 3 组动画同时发生：

| 动画组 | 作用 |
|---|---|
| A 主元素入场 | 卡片升起/滑入/弹出 |
| B 子元素级联 | 卡片内行/项逐条错位入场 |
| C 辅助元素 | 印章砸下/标签弹出/线条绘制 |
| D 持续动效 | 轻微浮动(±4px)/呼吸缩放(1.0-1.04)/光斑漂移 |

**每节拍至少 A+B+C 三组**，入场完成后启动 D。禁止整场景只有 1 组 fade+translateY。

GSAP easing 多样化：`back.out`、`power3.out`、`sine.inOut`、`elastic` 交替使用，不可全片只用 `power2.out`。

---

## 六、场景密度与节奏

1. **每 60 秒 6-8 个场景**（平均 7.5-10 秒/场景），不足 1 分钟按 `场景数 ≈ 时长秒 ÷ 9` 比例缩减（下限 3 个）。少于 6 偏疏、多于 8 偏碎
2. **场景间过渡 0.3-0.5 秒**（不占额外时长，用画面重叠实现）
3. **旁白无气口**——场景间不留静默，前场景尾音接后场景首音
4. **渲染后必须跑紧凑化**（见 `references/tighten-guide.md`），剪掉所有场景间静默

---

## 七、排版层级

同一画面至少 3 级字号同时出现：

1. 主标题 72-96px（800 字重）
2. 副标题/导语 32-40px（400-600 字重，muted 色）
3. 标签/kicker/数据 22-28px（600 字重，强调色）

**禁止整屏只有 1 级字号**。标题占比不超过画面高度的 35%，留空间给内容层。

---

## 八、允许有意重叠

layout-rules.md 的「bbox 不相交」规则仅适用于同一层级的元素。以下情况允许且鼓励重叠：

1. 前景印章压在卡片边缘上（L4 压 L3）
2. 手机卡部分覆盖 b-roll 窗口（L3 压 L2）
3. 胶囊标签叠在卡片右上角
4. 副标题与主标题行间部分重叠

重叠创造层次感，是「 filming」与「PPT 排版」的核心区别。

---

## 九、反模式黑名单（出现以下任一项 = 退回旧模板，禁止渲染）

以下模式是旧模板的签名特征。新对话中如果 HTML/CSS 出现这些模式，说明 AI 复制了 `composition-template.html` 而非自建设计系统：

1. **`.bg img` 全屏背景图 + 深色暗化层**——背景图 `opacity < 0.5` + 多层 `rgba(0,0,0,0.6+)` 渐变叠加 + vignette 暗角
2. **深色底 + `opacity:0.3-0.4` 的背景图**——内容可读全靠暗化层，画面发脏发灰
3. **从 `composition-template.html` 复制的 CSS 类名和属性**——`.scene/.clip/.bg/.vignette/.grain` 直接搬用，没有自建 `:root` 变量
4. **没有自建设计系统**——直接把 `style-variants.md` 的 `:root` 色板变量当 `<style>` 用，没有做调色板/字体层级/卡片系统/网格/纹理 5 项设计决策
5. **全条视频 0 条 b-roll**——跳过视频搜索直接用 CSS 渐变或静态图片当背景

**默认配色方向是浅色纸底**（#F0–#F8 范围）+ 白卡 + 双层阴影 + 2-3 个语义强调色。这是最稳妥、最接近 iWOD 质量的方向。如需深色底，必须在 `scene-plan.json` 里写明理由（如"夜景/科技感/品牌调性"），且仍须满足景深 4 层 + UI mockup + b-roll 窗口要求。
