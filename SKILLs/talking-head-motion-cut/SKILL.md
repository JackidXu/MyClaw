# 口播动效剪辑（talking-head-motion-cut-v2）— 口播原片→动效剪辑视频

## 这个技能做什么

收到一段口播视频原片，了解用户最终输出的视频比例，然后输出一个完整剪辑视频：原片整段保留 + 在画面上叠加与口播节奏同步的动效信息卡 + 逐句字幕 + 开头标题卡 + 结尾全屏总结卡。原声保留，人物全程可见（画中画模式除外）。

核心价值：把"一段口播原片"变成"信息重点提炼、讲到哪出现对应重点信息、有视觉效果辅助的剪辑视频"，不是简单加字幕，而是根据口播内容性质为每段选合适的动效呈现形式。

## 输入输出

- 输入：一段口播原片 mp4（人物口播，竖屏 9:16 或横屏 16:9；横屏源也可产出竖屏成片，用信箱居中变体：视频 object-fit:contain 居中、上下黑边承载动效区/字幕区），最终要求剪辑后视频比例（横屏还是竖屏）
- 输出：带动效的剪辑视频 output.mp4（原声保留）
- 依赖：node（技能自带 render.js 渲染器，用 puppeteer + ffmpeg 渲染 HTML composition 到 mp4）+ ffmpeg。其中 **puppeteer 由 render.js 首次运行时自动安装**、**ffmpeg 为系统级二进制需自备**（render.js 启动时会检测缺失并提示各平台安装命令）；ASR 为独立转录工具，不在渲染链路内。

## 六阶段工作流

### 阶段 0 · 环境自动就绪（加速直通）

环境已完全内置就绪，无需手动测试环境：
1. **ASR 转录**：优先直接调用系统内置或宿主提供的语音转录工具（如 `heyclaw_audio_transcribe`）毫秒级获取精准时间码 `transcript.json`。
2. **渲染环境**：本技能自带的 `render.js` 已内置系统 Chrome/Edge 智能嗅探、FFmpeg 就绪检测与透明图层极速合成，开箱即用。
3. **禁止多模态 probe**：原片路径与基础信息直接可用，**严禁自行写脚本抽帧探查（如 `_probe/f01.png`）或调用 `image` 工具分析画面**，零延迟直接启动创作。
直接进入阶段 1。

### 阶段 1 · 转录与分段

拿到口播原片后，先检查原片视频是横屏还是竖屏的，如果原片视频为横屏，需要咨询最终输出成片是横屏还是竖屏，然后再把口播文案转成带时间码的文本，再按语义切段。

1. **调用内置 ASR 转录原片（绝对严禁额外调用 Whisper 或 whisper-tool）**：
   - 直接调用宿主提供的内置转录工具（如 `heyclaw_audio_transcribe`），**绝对严禁自作主张寻找本地 whisper/whisper-cli 或执行静音探测脚本**；
   - **短句切分与时间码分配规则**：若 ASR 返回的是粗时间段（如 `[00:00 ~ 00:12]` 包含整段连续口播），**直接由大模型按标点符号将文案拆为独立短句（一次一组，≤2 行），并在该时间段内按字数比例自动线性分配每句的 `start` 与 `end`（秒，保留两位小数）**；
   - 快速产出 `transcript.json`，格式：每句一条 `{text, start, end}`。每段是一个完整语义句，不要把一句话切两半。
2. 根据原片时长每1分钟按 4-6 个语义段落把转录句归组：钩子 / 第一步 / 第二步 / … / 价值段 / CTA
   - 每个段落记录起止时间（取该段第一句 start 和最后一句 end）
   - 段落边界尽量落在口播的自然停顿处，避免把一句话劈到两个段落
   - **每段同时标注「挂动效面板 / 留背景白」**（判断标准见阶段 2「段落模型」）：用动效能讲清的挂面板（建界面/对话/累积/素材展示），可有可无的留白；**至少保留 1 个素材展示段（类型 B）** 作模板素材区；所有留白段合计目标 ≈ 总时长 20%。
   - **钩子 = 口播正文第一句**，属于字幕内容（会作为字幕逐句显示），**不是视频标题，开头第一段落动效区域留给标题展示**，见阶段 4「标题卡专属规则」。
3. 这套时间轴是后续动效卡和字幕组的骨架，所有 `data-start`/`data-duration` 都从这里来

### 阶段 2 · 动效选型思考

这是决定成品质量的关键阶段。**先想清楚每段该用什么呈现形式，再动手写 HTML。** 核心方法论见 `references/scene-design.md` 的「动效选型四步法」，动效实现从本技能的 100+ 模式库里取（见下方工具箱）。

**🚫 动效类型绝对不能写死**：本技能**不预设"固定 4 种面板"或"每段必须用 A/B/C"**。每一段挂什么动效元素，必须**根据该段口播文案的语义当场判断**——同样是 3 个步骤段，第一段适合具象 UI、第二段适合素材展示、第三段可能适合聊天气泡 / 数据面板 / 对比表，全由内容决定，绝不一刀切套同一个模板。参考技能 `script-to-motion-video` 的动效质量，正来自这种"逐段按内容选型 + 每节拍 3+ 组动画"的丰度。

**动效选型四步法（每段必过，缺一不可）**：
1. **理解信息类型**：这段在讲什么？（数据 / 对比 / 概念 / 关系 / 案例 / 转化 / 结论 / 情绪……）信息有几层（核心 + 辅助）？
2. **找讲这个故事的视觉元素（强制）**：基于信息类型推导具体图形 + 文字元素——问"用什么图形最能讲这个故事"，不是"要不要图形"（默认永远是"要"）。元素就是 HTML+CSS+GSAP，必须按文案语义现场创作（inline SVG / CSS），禁止因为库里没有就退回纯文字容器。图形精致四要素见 `references/scene-design.md`（有光感/有层次/有细节/有质感，绝不平涂单线）。
3. **用构图表达概念**：对比→左右/强弱对比构图；流程→步骤连线；堆叠→层次卡片；强调→大元素居中。主元素占大区域，辅助元素烘托。
4. **选动效让元素入场**：从下方工具箱选，动效性质匹配信息性质——冲击型信息用冲击型动效（`back.out`/`elastic`），铺垫型用平静型（`sine.inOut`/`power2`）。

**硬原则：区域越大内容越多**——大区域（动效面板 900×740）放核心元素（大字/数据/引言块/具象 UI），小区域放装饰（图标/光晕）。元素视觉权重（大小/位置/动效强度）要跟它在文案里的重要性匹配。

**动效工具箱（100+ 模式，按需求从对应文档取，非必选清单、可自由组合或创造）**：
- 先查基础原语（`references/motion-patterns.md`，22 种：scale-pop / slide-in / grow-x / grow-y / typewriter / count-up / blur-in / mask-reveal / draw-path / morph-to / pulse / kinetic-chars …）→ 不够查完整蓝图（`references/motion-blueprints.md`，22 个）→ 转场查（`references/motion-transitions.md`，13 个）→ 特定效果查规则（`references/motion-rules.md`，48 个）。
- 当某段内容需要画完整流程图/关系图、面板放不下时，把该面板 zone 设成 fullscreen 即可（选型思考的结果，不是固定模式）。

### 段落模型：动效面板 vs 背景留白（呼吸感的核心）

每段口播二选一：**挂动效面板** 或 **留背景白**（只显示真人 + 字幕，不挂任何面板）。这套模型决定了成片"一直在展示动效"还是"有节奏呼吸"。

**判断标准（按内容价值，不是随机）**：
- 用动效能更直观讲清的，挂面板：建界面/搭流程（类型 A 具象 UI）、一问一答（类型 C 聊天气泡）、随时间沉淀/累积（类型 D 记忆中枢）、**需要展示一段素材视频的（类型 B 素材展示）**。
- 动效对讲解帮助小、可有可无的，留背景白：纯利益陈述、纯情感共鸣、概念性收尾等——这类用真人直述 + 字幕即可，不必硬做面板。
- **固定区不能省**：开头标题卡（0–4.5s）+ 结尾全屏总结卡必须保留，不纳入背景白判断。
- **至少保留 1 个素材展示面板（类型 B）**：作为模板的"素材演示区"，方便后续换不同素材复用。**类型 B 的素材视频必须按文案语义从免费平台获取（见阶段 4「素材获取」），严禁直接沿用模板自带的 `material-DEMO.mp4`——那是占位演示片，出片必须替换成与文案主题相关的真实素材。**
- **目标：背景留白 ≈ 总时长 20%**。算法：把所有"留白段"时长相加 ÷ 总时长。通常拆成 1–2 段留白（各 5–10s）即可达标，不必每段都留白。

**节奏对齐硬规则**：面板 `data-start` = 该段口播起点，`data-duration` = 该段口播时长（面板时长 = 口播时长）；面板内部元素逐句跟口播弹出，时间点落在讲到对应信息的时刻。错把面板提前收掉 = 文案还在讲、画面已空，是头号观感 bug。背景留白段**不要调用 `blurOn`**，背景承接上一段 `blurOff` 保持清晰，直到下一段面板或结尾总结卡才重新虚化。

**面板类型按文案语义选（绝不写死为 A/B/C/D 固定四种）**：每段挂什么面板，由阶段 2 四步法判定的信息类型决定。常见可选类型举例（**无预设清单、可组合/创造**）：
- **具象 UI**：建界面 / 搭流程，含进度计数（0→100% 真实数字，用 `this.progress()` 驱动，别写死 0%）。
- **素材展示**：嵌入 `vid/*.mp4` 素材视频（**必须按文案语义从免费平台获取，见阶段 4「素材获取」**，禁止用模板自带的 `material-DEMO.mp4`）+ 扫描线 + 四角信息卡。
- **聊天气泡**：一问一答，AI 答句用打字机 `clipPath` 揭幕。
- **记忆/累积**：中枢节点 + 卡片汇聚，随时间沉淀。
- **数据面板 / 对比表 / 流程连线 / 引用卡 / 设备三连屏**——任何能讲清该段文案的具象形式都可。关键是"具象、可辨认、逐元素动画"，而非套某个固定模板。
- **至少保留 1 个素材展示面板**：作模板素材演示区，且必须替换为语义相关真实素材（见阶段 4）。

### 阶段 3 · 字幕标色 vs 动效分工

明确每段的重点信息，哪些靠字幕标色强调、哪些靠动效呈现。

- **单纯强调某个词** → 字幕标色就够（关键词紫色 `.hl-key`、数字金色 `.hl-num`、普通文字默认白色）
- **信息有结构关系** → 必须动效呈现
- 判断标准：如果只是让观众注意某个词，标色即可；如果要帮观众理解几个信息点之间的关系，就要动效

**动效卡里只放从文案提取的重点信息，整句口播文字交给字幕。** 两者各司其职，不重叠：字幕管"完整文字"，动效管"信息结构可视化"。

### 选视觉身份（写 HTML 前先定 · 每片只选 1 次）

视觉库分三层，这是防"整体感崩塌"的关键：**身份层每片只选 1 次，节奏层 / 装饰层才按段变**。

- 从 `references/design-guide.md` 的「内容类型 → 建议组合」挑 **1 个 Style**（academic / audit / editorial / geom / minimal / spotlight / swiss / terminal / whiteboard / xhs）。
- 选 **1 个 Frame**（clean / hairline / polaroid，默认 clean 最安全）。
- 把该 Style 文件顶部的 `:root 重映射` 块拷进 composition 顶部 `<style>`，全片配色即统一（详见 design-guide.md 第四节）。
- **绝不**在每张卡换一套风格 / 边框 / 主题——那是随机幻灯片。变化交给"布局 + 动效原语 + 稀疏装饰"。

### 阶段 4 · 写 HTML composition

基于 `references/composition-template.html`（v2 框架模板）改。这是主体工作。该模板已锁定**成片框架骨架**：固定开头标题卡 → 若干步骤面板（每段挂什么类型由文案语义决定，**不写死为「具象UI→素材→气泡」的固定顺序**）→ 背景留白段（呼吸感）→ 固定结尾总结卡；布局几何锁定为居中浮卡（见下方「布局锁定」）。**动效质量对齐成片 + 参考技能基准**（见「动效丰度标准」）。照模板注释把占位文案换成实际内容、把顶部 `步骤时间码 config` 换成 transcript 真实值，并按每段文案语义替换面板内部动效元素即可。关键规范：

#### 素材获取（类型 B 面板：必须按文案语义从免费平台获取，禁止用模板自带 demo）

⚠️ **类型 B 素材展示面板的视频，严禁直接沿用模板自带的 `material-DEMO.mp4`**——那是占位演示片。出片必须按本段文案语义，从免费素材平台获取一段**主题相关**的视频，替换进去。具体获取方法见 `references/material-fetch.md`（已适配本技能面板内嵌场景）。要点：

1. **语义映射**：先提炼该段文案的主题关键词（中英双语，英文素材更多），例如「健身约课换场地」→ `fitness`, `gym class`, `booking`, `schedule change`, `training session`。
2. **视频优先**：Pexels / Pixabay 视频首选（需 API key 搜列表→直链下载）；无 key 用 Coverr / Mixkit 免 key 站解析兜底；实在搜不到主题视频，退回 Unsplash 图片（用 Ken Burns 补动态感）；AI 生图仅作最后手段且必须标注。
3. **压缩落盘**：下载后 `ffmpeg` 压到 **1080×1920 30fps、去音频**（`-an`），放进 `public/vid/`（如 `public/vid/gym-reschedule.mp4`），文件名按主题命名。
4. **接进面板**：把类型 B 面板里的 `<video class="material-clip" src="vid/material-DEMO.mp4">` 的 `src` 改成你的素材路径，并保留 `data-scene-start="该段起点秒"`（渲染器按场景相对时间循环）。

**降级阶梯（视频 → 图片 → AI 生图）**：上一级成功就用上一级，不要跳过；严禁把 AI 生图当默认背景。

**布局锁定（v2 框架唯一默认布局：居中浮卡式 · 严禁改成顶部窄条 / 侧边窄条）**

⚠️ 本技能 v2 框架**只锁定一种布局**，直接照 `references/composition-template.html` 用，**不要自行切换成旧版「上下/左右 25% 窄条」布局**——那会触发「动效区域位置错 / 变小」的观感 bug。

- **画布**：竖屏 9:16（1080×1920）。横屏源产出竖屏成片时用「信箱居中」变体（视频 object-fit:contain 居中、上下黑边承载动效区/字幕区），但普通口播原片一律用默认居中浮卡式。
- **动效面板几何（写死、禁止改）**：每个面板 `.card-host` 的 inline style **必须是 `left:90px; top:540px; width:900px; height:740px`**（水平居中、纵向占据中下黄金带）。真人通常在画面上 1/3，面板压在中下部、虚化真人作背景，**不挡脸、不压字幕区（字幕在 top:1540）**。
- **为什么是这个位置/尺寸**：这是 v4 成片验证过的「区域够大、内容撑得满、不挡人」的黄金比例。把面板挪到顶部做成 ~25% 窄条、或缩到 `<900×740`，都会出现「位置错 / 变小」问题——**严禁**。
- **四角装饰（`.bracket`）常驻**：属于 HUD 层（`data-card-id="hud"`，`data-start="0"` 覆盖全片），四角 L 形括号 **全程可见**；**绝不绑定到任何面板、绝不随面板出现/消失**。
- **背景留白段**：不挂面板、不调 `blurOn`，背景 `blurOff` 恢复清晰，纯真人 + 字幕（呼吸感）。

**唯一共同铁律（所有布局/变体都适用）**：字幕 track-index=10 永远最顶层，任何动效卡（含全屏总结卡）都不能盖住字幕。

#### 动效丰度标准（对齐参考技能质量 · 硬性）

本技能动效质量对标参考技能 `script-to-motion-video` 的视觉质量基准（`references/visual-quality-baseline.md`）。**每个节拍（旁白说到某语义点的画面时刻）至少 3 组动画同时发生**：

| 动画组 | 作用 | 示例 |
|---|---|---|
| A 主元素入场 | 卡片升起/滑入/弹出 | `back.out` 让面板主卡弹入 |
| B 子元素级联 | 卡内行/项逐条错位入场 | `power3.out` stagger 0.08s |
| C 辅助元素 | 印章砸下/标签弹出/线条绘制 | `elastic` 砸印、`draw-path` 画线 |
| D 持续动效 | 轻微浮动/呼吸缩放/光斑漂移 | ±4px 浮动、1.0–1.04 呼吸、光斑缓慢漂移（入场完成后 `repeat:-1, yoyo:true` 启动） |

**每节拍至少 A+B+C 三组**，入场完成后启动 D。禁止整段只有 1 组 `fade+translateY`——那是「没动效感」的头号原因。

**GSAP easing 多样化（强制）**：`back.out` / `power3.out` / `sine.inOut` / `elastic` 交替使用，**不可全片只用 `power2.out`**。冲击型信息用 `back.out`/`elastic`，铺垫型用 `sine.inOut`/`power2.out`。

> 实现示范见 `references/composition-template.html` 内各面板的动画脚本——每个面板都按 A+B+C+D 丰度 + 多 easing 编写，复制后按本段文案替换元素即可，**不要退化成单组 fade**。

### 标题卡专属规则

视频标题 和 口播第一句（钩子）是**两回事**，必须分清，这是出片最常见的两个失误来源：

- **视频标题（title card）**：开场 0-4.5s 显示的封面式标题，是一句**单独提炼**的短标题（8-14 字最佳），概括整条视频的价值 / 主题 / 悬念，例如「为什么你越努力越焦虑」「3 个方法让效率翻倍」。它**不在口播稿里**，是额外写给观众看的"封面"。
- **口播第一句（钩子 / hook）**：口播正文的第一句话，属于字幕内容，会作为字幕逐句显示。它是**字幕**，不是标题。

三条铁律：

1. 标题卡的 `.ttl` 文字**绝不能**是口播第一句 / 钩子的原文——必须是重新提炼的短标题。
2. 标题卡是"视频封面式标题"：**纯文字 + 顶部渐变遮罩，没有圆角卡片容器、没有卡片背景色块、没有元素错峰动效**。它和动效卡是两种不同性质的元素（动效卡 = 信息结构可视化，标题卡 = 封面标题）。
3. **不要用动效卡的方式去呈现标题**：不要套用动效卡的卡片样式（圆角卡片底 / `--c-bg-card` 背景），不要给标题做 scale-pop / 逐字出场 / 元素错峰等动效。标题就是干净地淡入淡出。

写标题卡前，先根据原文文案总结一句标题再落 HTML；写完后确认标题卡存在、且文字不是第一句口播原文。

**写 HTML 的技术规范**（这些是让渲染不出错的前提）：

- **节奏对齐硬规则（最高优先级）**：每个动效面板的 `data-start`/`data-duration` 必须与该段口播时间码一致（面板时长 = 口播时长），面板内部元素用 `tl.fromTo(..., S+N)` 逐句跟口播弹出，错峰间隔 0.1–0.5s。背景留白段**不挂面板、不调用 `blurOn`**，背景承接上一段 `blurOff` 保持清晰。绝不允许面板提前收掉而口播还在讲。
- **进度计数等"数字类"动效用 `this.progress()` 驱动**：如类型 A 的 0→100% 进度条，在 `fromTo` 的 `onUpdate` 里用 `this.progress()` 取进度写 `textContent`，**禁止写死 0% 文字**也不依赖外部闭包变量（会触发 TDZ 让整段动画失效）。
- **素材展示面板（类型 B）的素材视频放 `public/vid/`**，`<video class="material-clip" data-scene-start="段落起点秒">`，渲染器会自动按场景相对时间循环播放；换素材只改 `src`，不动结构。

1. **动效进出只用 opacity tween，clip 可见性由 data-start/data-duration 控制**
   - 进场：`tl.set(H(id), {visibility:"visible"}, s)` + `tl.fromTo(H(id), {opacity:0,y:-16}, {opacity:1,y:0,...}, s)`
   - 出场：`tl.to(H(id), {opacity:0,...}, s+d-0.25)` + `tl.set(H(id), {visibility:"hidden"}, s+d)`
   - 只 tween opacity，可见性交给框架，不自己 tween visibility/display/autoAlpha
2. **card-host 直接包 root，root height:100% 全链贯通**
   - 结构：`<div class="card-host clip" data-card-id="X" ...><div class="card" data-card-id="X"><style>...</style><div class="root">...</div></div></div>`
   - `.card` 和 `.root` 都设 `height:100%`，保证内部 `height:100%` 的子元素能撑开
   - 不在 card 和 root 之间加多余的中间层（中间层 height:0 会让子元素 height:100%=0）
3. **内部动画选择器用纯 `#id`，配合 Q(id) helper**
   - helper：`const Q = (id) => '.card[data-card-id="' + id + '"] ';`
   - 调用：`tl.fromTo(Q("m2")+"#m2-step", {...}, {...}, 5.5)`
   - 用 `.card[data-card-id=X] #id` 前缀避免跨卡选择器冲突
4. **每段动效卡内 4-8 个元素分层错峰出场**
   - 不是一次性把字铺上去，是元素逐个按时间点弹出（scale-pop/slide-in/grow-x/typewriter 混合）
   - 每个元素在卡进场后 0.1-0.5s 依次出现，营造"讲到哪出现对应信息"
   - 元素要满足动效前提：kinetic-chars 要把每个字包进 `<span class="char">`，count-up 要标 from/to 值，draw-path 要元素是 SVG `<path>`
5. **开头标题卡 + 结尾全屏总结卡**
   - 开头 0-4.5s 标题卡：视频标题 + 副标题，4.1s 开始淡出
   - **标题是单独提炼的短标题（非口播第一句 / 钩子原文），视觉为封面式（纯文字 + 顶部渐变遮罩，无圆角卡片容器、无卡片背景色块、无元素错峰动效），和动效卡区分明显**
6. **字幕 rail 用逐句分组**（见 `references/rail-subtitle-spec.md` 详述）
   - 一次一组、≤2 行、150-250ms fade、emphasis 词 inline 标色
   - **修复字幕被全屏卡遮挡 Bug（CSS 层级映射契约）**：字幕 track-index 设为 10，且**必须在 CSS 显式声明 `.card-host[data-track-index="10"]{ z-index:10; }`**，确保无论 DOM 顺序如何，字幕在最终渲染图层中 100% 处于最顶层（防止全屏总结卡覆盖字幕）
   - **内部临时文件隔离**：所有 HTML 文件（无论是分段中间件还是用于渲染的主 index.html）必须统一保存在以点开头的隐藏目录中（如 .tmp），严禁暴露在非隐藏目录中，防止界面弹出工件卡片

### 阶段 5 · HTML 渲染前静态自查与字幕逐句校对（0 耗时）

在纯文本代码中完成秒速核验，无需启动浏览器：
1. **图层层级**：字幕 track-index=10（最顶层），大于所有动效卡与总结卡
2. **空间分区**：竖屏动效卡 = 居中浮卡 `left:90 top:540 width:900 height:740`（覆盖在虚化真人之上），字幕在底部（top:1540），严格对照 `references/composition-template.html` 坐标，互不重叠；四角装饰（`.bracket`）常驻全片可见
3. **GSAP Seek 安全**：动效属性均可静态重现；数字滚动使用安全闭包
4. **显隐契约**：只 tween opacity 与 transform，显隐切换由 tl.set 托管
5. **标题隔离**：开头标题是提炼的短标题（封面式），绝不是口播正文第一句
6. **字幕校对**：字幕逐句对照 transcript.json 原文校对过，错字补全纠正，每组 ≤2 行
7. **卡片时长闭环**：动效卡登场后内部主体 0.3s 内进场展开，严禁数秒时差空窗

### 阶段 6 · 极速渲染与双重门禁自检（单向终点 · 严禁二次全量重渲染）

1. **执行单次全量渲染**：
   ```bash
   node "<技能根目录>/render.js" public -o output.mp4 --fps 30
   ```
   - 严禁在命令末尾加 `| tail`、`| grep` 等管道符重定向，确保进度条实时输出到控制台。
2. **第一道防线：FFmpeg 快速机器探针（黑屏与合成熔断检测 · 0.2 秒）**：
   渲染完成后，用 FFmpeg 探针命令行秒级读取成片中段（如第 5 秒）的亮度均值，确保合成未黑屏：
   ```bash
   ffmpeg -ss 5 -i output.mp4 -vframes 1 -vf "signalstats,metadata=print" -f null - 2>&1 | grep "YAVG"
   ```
   - 若 `YAVG` 正常输出（非全黑 `YAVG > 10`），即代表视频正常合成且原片画面存在。
3. **第二道防线：黄金代表帧单次视觉核验（限死 1 帧 · 严禁循环抽帧）**：
   仅提取**唯一的一张**动效展开代表帧图片（如 `t=6s`），且**只允许调用唯一一次**图片查看工具过目：
   ```bash
   ffmpeg -y -ss 6 -i output.mp4 -vframes 1 check_preview.jpg
   ```
   - **核验三要素**：① 动效卡是否规整在顶部（未盖住五官）；② 字幕是否在底部正常显示；③ 文字排版未严重挤压重叠。
   - **绝对红线禁令**：**严禁写脚本对每个分段循环抽多张图（如 `f_17.5.jpg`、`f_24.5.jpg`...），绝对严禁调用工具读取第二张图片！**
4. **单向终点成片交付（绝对红线禁令 · Zero Re-render Rule）**：
   - **除致命全黑屏崩溃（YAVG ≤ 10）外，100% 绝对禁止、严禁执行第二次 `node render.js` 全量重渲染！**
   - 无论在核验代表帧中看到任何情况（例如**原片有自带硬字幕冲突**、希望字幕条更暗、想微调卡片颜色、动效速度稍快或稍慢等任何所谓“改善性”主观瑕疵），**均绝对严禁自作主张修改 HTML 再次全量渲染**！
   - **单次全量渲染完成的 `output.mp4` 必须且只能作为本次剪辑的唯一成片终点立即交付给用户！** 任何细微发现与优化建议，只允许在交付回复中用文字客观告知用户。
   - **成果交付铁律**：最终交付物单一且唯一：`output.mp4` 成片视频！所有过程中的 HTML 页面、分段文件、抽检图片仅作为内部渲染临时中间件，**绝对禁止向用户输出或展示任何 HTML 文件的链接或预览**。向用户直接交付 `output.mp4`！

## 渲染器说明

本技能自带 `render.js` 渲染器（位于技能根目录），用 puppeteer 启动 headless Chrome → 加载 HTML composition → 按 fps 逐帧 `tl.seek(time)` + 截图 → ffmpeg 帧序列合成视频 + 合并原片音频。

**音频处理铁律**：合成时直接映射原片音轨（`-map 1:v:0 -map 0:a?`），**绝不**先抽 `audio.aac` 再 `-shortest` 合成——后者会误判最短输入把音频截到约 37s（口播后半段失声）。原声必须完整保留到成片结尾。

composition 的 HTML 结构规范、GSAP timeline 机制、clip 可见性托管（data-start/data-duration + `tl.set` visibility），都是本技能自己的规范，全部写在 `references/composition-template.html` 骨架和各 references 文档里。

技能职责：给 AI 一套"口播原片→动效剪辑视频"的完整工作流和思考方法，让 AI 知道每一步该怎么做、怎么判断、怎么避坑。具体 HTML 写法照骨架搭，动效实现按 motion-thinking 选型自己设计。
