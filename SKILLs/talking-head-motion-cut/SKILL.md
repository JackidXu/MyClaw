# 口播动效剪辑（talking-head-motion-cut）— 口播原片→动效剪辑视频

## 这个技能做什么

收到一段口播视频原片，了解用户最终输出的视频比例，然后输出一个完整剪辑视频：原片整段保留 + 在画面上叠加与口播节奏同步的动效信息卡 + 逐句字幕 + 开头标题卡 + 结尾全屏总结卡。原声保留，人物全程可见（画中画模式除外）。

核心价值：把"一段口播原片"变成"信息重点提炼、讲到哪出现对应重点信息、有视觉效果辅助的剪辑视频"，不是简单加字幕，而是根据口播内容性质为每段选合适的动效呈现形式。

## 输入输出

- 输入：一段口播原片 mp4（人物口播，竖屏 9:16 或横屏 16:9；横屏源也可产出竖屏成片，用信箱居中式，见 layout-zones.md 模式 4），最终要求剪辑后视频比例（横屏还是竖屏）
- 输出：带动效的剪辑视频 output.mp4（原声保留）
- 依赖：node（技能自带 render.js 渲染器，用 puppeteer + ffmpeg 渲染 HTML composition 到 mp4）+ ffmpeg。其中 **puppeteer 由 render.js 首次运行时自动安装**、**ffmpeg 为系统级二进制需自备**（render.js 启动时会检测缺失并提示各平台安装命令）；ASR 为独立转录工具，不在渲染链路内。

## 六阶段工作流

### 阶段 0 · 环境自动就绪（加速直通）

环境已完全内置就绪，无需手动测试环境：
1. **ASR 转录**：优先直接调用系统内置或宿主提供的语音转录工具（如 `heyclaw_audio_transcribe`）毫秒级获取精准时间码 `transcript.json`。
2. **渲染环境**：本技能自带的 `render.js` 已内置系统 Chrome/Edge 智能嗅探、FFmpeg 就绪检测与透明图层极速合成，开箱即用。
3. **禁止多模态 probe**：原片路径与基础信息直接可用，**严禁自行写脚本抽帧探查（如 `_probe/f01.png`）或调用 `image` 工具分析画面**，零延迟直接启动创作。
直接进入阶段 1。

### 阶段 1 · 转录与分段

拿到口播原片后，先检查原片视频是横屏还是竖屏的，如果原片视频为横屏，需要咨询最终输出成片是横屏还是竖屏，然后再把口播文案转成带时间码的文本，再按语义切段。

1. **调用内置 ASR 转录原片（绝对严禁额外调用 Whisper 或 whisper-tool）**：
   - 直接调用宿主提供的内置转录工具（如 `heyclaw_audio_transcribe`），**绝对严禁自作主张寻找本地 whisper/whisper-cli 或执行静音探测脚本**；
   - **短句切分与时间码分配规则**：若 ASR 返回的是粗时间段（如 `[00:00 ~ 00:12]` 包含整段连续口播），**直接由大模型按标点符号将文案拆为独立短句（一次一组，≤2 行），并在该时间段内按字数比例自动线性分配每句的 `start` 与 `end`（秒，保留两位小数）**；
   - 快速产出 `transcript.json`，格式：每句一条 `{text, start, end}`。每段是一个完整语义句，不要把一句话切两半。
2. 根据原片时长每1分钟按 4-6 个语义段落把转录句归组：钩子 / 第一步 / 第二步 / … / 价值段 / CTA
   - 每个段落记录起止时间（取该段第一句 start 和最后一句 end）
   - 段落边界尽量落在口播的自然停顿处，避免把一句话劈到两个段落
   - **钩子 = 口播正文第一句**，属于字幕内容（会作为字幕逐句显示），**不是视频标题，开头第一段落动效区域留给标题展示**，见阶段 4「标题卡专属规则」。
3. 这套时间轴是后续动效卡和字幕组的骨架，所有 `data-start`/`data-duration` 都从这里来

### 阶段 2 · 动效选型思考

这是决定成品质量的关键阶段。**先想清楚每段该用什么呈现形式，再动手写 HTML。** 选型思路见 `references/motion-thinking.md`，核心是四步：

1. 读这段口播，先理解它在讲什么——信息结构是什么（在对比？列举？讲流程？讲累积？对话？数值？状态？还是其他结构类型）
2. 想什么样的视觉呈现最能帮观众理解这个结构——从动效工具箱里选合适的，或自由组合、甚至创造新的呈现形式
3. 动效卡里只放从文案提取的重点信息，单个卡内元素文字数量控制尽可能少一些，只放重点信息
4. **唯一硬原则：展示动效的区域越大，卡内要承载的内容元素越多，色彩对比明显，让画面合理**

动效工具箱（12 种可选，可自由组合或创造新形式，非必选清单）：scale-pop、slide-in、grow-x、grow-y、typewriter、count-up、blur-in、mask-reveal、draw-path、morph-to、pulse、kinetic-chars。

当某段内容需要画完整流程图或关系图、动效卡小条放不下时，需要切换到全屏分析模式——这是选型思考的结果，把动效卡 zone 设成 fullscreen 即可，这时需要注意全屏模式下元素数量与呈现方式。具体动效形式的实现见 `references/motion-thinking.md`。

### 阶段 3 · 字幕标色 vs 动效分工

明确每段的重点信息，哪些靠字幕标色强调、哪些靠动效呈现。

- **单纯强调某个词** → 字幕标色就够（关键词紫色 `.hl-key`、数字金色 `.hl-num`、普通文字默认白色）
- **信息有结构关系** → 必须动效呈现
- 判断标准：如果只是让观众注意某个词，标色即可；如果要帮观众理解几个信息点之间的关系，就要动效

**动效卡里只放从文案提取的重点信息，整句口播文字交给字幕。** 两者各司其职，不重叠：字幕管"完整文字"，动效管"信息结构可视化"。

### 选视觉身份（写 HTML 前先定 · 每片只选 1 次）

视觉库分三层，这是防"整体感崩塌"的关键：**身份层每片只选 1 次，节奏层 / 装饰层才按段变**。

- 从 `references/design-guide.md` 的「内容类型 → 建议组合」挑 **1 个 Style**（academic / audit / editorial / geom / minimal / spotlight / swiss / terminal / whiteboard / xhs）。
- 选 **1 个 Frame**（clean / hairline / polaroid，默认 clean 最安全）。
- 把该 Style 文件顶部的 `:root 重映射` 块拷进 composition 顶部 `<style>`，全片配色即统一（详见 design-guide.md 第四节）。
- **绝不**在每张卡换一套风格 / 边框 / 主题——那是随机幻灯片。变化交给"布局 + 动效原语 + 稀疏装饰"。

### 阶段 4 · 写 HTML composition

基于 `references/composition-template.html` 模板改。这是主体工作。照模板的注释，把每段换成实际内容。关键规范：

**布局选 3 种之一**（见 `references/layout-zones.md` 详述）：

| 模式   | 适用画幅     | 动效卡位置         | 字幕        | 人物           |
| ---- | -------- | ------------- | --------- | ------------ |
| 上下结构 | 竖屏 9:16  | 顶部约 25% 高度    | 底部        | 视频满屏，人脸全程可见  |
| 左右结构 | 横屏 16:9  | 左侧或右侧约 25% 宽度 | 底部        | 视频满屏，动效卡浮在侧边 |
| 画中画  | 任意       | 动效卡占满屏        | 底部        | 人物缩成角落圆角小窗   |
| 信箱居中 | 横屏源→竖屏成片 | 上方黑边(动效区)     | 下方黑边(字幕区) | 视频居中不裁切，上下黑边 |

**四种布局共同点**：

- 字幕永远在最顶层（track-index 数值最大），任何动效卡（含全屏分析卡/总结卡）都不能盖住字幕
- 一段视频可混用布局（比如竖屏前 5 段用上下结构，中间一段流程图切画中画全屏分析，结尾总结卡全屏）
- 信箱居中式是横屏源→竖屏成片的专用布局：视频居中不裁切、上下黑边分别承载动效区与字幕区

### 标题卡专属规则

视频标题 和 口播第一句（钩子）是**两回事**，必须分清，这是出片最常见的两个失误来源：

- **视频标题（title card）**：开场 0-4.5s 显示的封面式标题，是一句**单独提炼**的短标题（8-14 字最佳），概括整条视频的价值 / 主题 / 悬念，例如「为什么你越努力越焦虑」「3 个方法让效率翻倍」。它**不在口播稿里**，是额外写给观众看的"封面"。
- **口播第一句（钩子 / hook）**：口播正文的第一句话，属于字幕内容，会作为字幕逐句显示。它是**字幕**，不是标题。

三条铁律：

1. 标题卡的 `.ttl` 文字**绝不能**是口播第一句 / 钩子的原文——必须是重新提炼的短标题。
2. 标题卡是"视频封面式标题"：**纯文字 + 顶部渐变遮罩，没有圆角卡片容器、没有卡片背景色块、没有元素错峰动效**。它和动效卡是两种不同性质的元素（动效卡 = 信息结构可视化，标题卡 = 封面标题）。
3. **不要用动效卡的方式去呈现标题**：不要套用动效卡的卡片样式（圆角卡片底 / `--c-bg-card` 背景），不要给标题做 scale-pop / 逐字出场 / 元素错峰等动效。标题就是干净地淡入淡出。

写标题卡前，先根据原文文案总结一句标题再落 HTML；写完后确认标题卡存在、且文字不是第一句口播原文。

**写 HTML 的技术规范**（这些是让渲染不出错的前提）：

1. **动效进出只用 opacity tween，clip 可见性由 data-start/data-duration 控制**
   - 进场：`tl.set(H(id), {visibility:"visible"}, s)` + `tl.fromTo(H(id), {opacity:0,y:-16}, {opacity:1,y:0,...}, s)`
   - 出场：`tl.to(H(id), {opacity:0,...}, s+d-0.25)` + `tl.set(H(id), {visibility:"hidden"}, s+d)`
   - 只 tween opacity，可见性交给框架，不自己 tween visibility/display/autoAlpha
2. **card-host 直接包 root，root height:100% 全链贯通**
   - 结构：`<div class="card-host clip" data-card-id="X" ...><div class="card" data-card-id="X"><style>...</style><div class="root">...</div></div></div>`
   - `.card` 和 `.root` 都设 `height:100%`，保证内部 `height:100%` 的子元素能撑开
   - 不在 card 和 root 之间加多余的中间层（中间层 height:0 会让子元素 height:100%=0）
3. **内部动画选择器用纯 `#id`，配合 Q(id) helper**
   - helper：`const Q = (id) => '.card[data-card-id="' + id + '"] ';`
   - 调用：`tl.fromTo(Q("m2")+"#m2-step", {...}, {...}, 5.5)`
   - 用 `.card[data-card-id=X] #id` 前缀避免跨卡选择器冲突
4. **每段动效卡内 4-8 个元素分层错峰出场**
   - 不是一次性把字铺上去，是元素逐个按时间点弹出（scale-pop/slide-in/grow-x/typewriter 混合）
   - 每个元素在卡进场后 0.1-0.5s 依次出现，营造"讲到哪出现对应信息"
   - 元素要满足动效前提：kinetic-chars 要把每个字包进 `<span class="char">`，count-up 要标 from/to 值，draw-path 要元素是 SVG `<path>`
5. **开头标题卡 + 结尾全屏总结卡**
   - 开头 0-4.5s 标题卡：视频标题 + 副标题，4.1s 开始淡出
   - **标题是单独提炼的短标题（非口播第一句 / 钩子原文），视觉为封面式（纯文字 + 顶部渐变遮罩，无圆角卡片容器、无卡片背景色块、无元素错峰动效），和动效卡区分明显**
6. **字幕 rail 用逐句分组**（见 `references/rail-subtitle-spec.md` 详述）
   - 一次一组、≤2 行、150-250ms fade、emphasis 词 inline 标色
   - **修复字幕被全屏卡遮挡 Bug（CSS 层级映射契约）**：字幕 track-index 设为 10，且**必须在 CSS 显式声明 `.card-host[data-track-index="10"]{ z-index:10; }`**，确保无论 DOM 顺序如何，字幕在最终渲染图层中 100% 处于最顶层（防止全屏总结卡覆盖字幕）
   - **内部临时文件隔离**：所有 HTML 文件（无论是分段中间件还是用于渲染的主 index.html）必须统一保存在以点开头的隐藏目录中（如 .tmp），严禁暴露在非隐藏目录中，防止界面弹出工件卡片

### 阶段 5 · HTML 渲染前静态自查与字幕逐句校对（0 耗时）

在纯文本代码中完成秒速核验，无需启动浏览器：
1. **图层层级**：字幕 track-index=10（最顶层），大于所有动效卡与总结卡
2. **空间分区**：竖屏动效卡在顶部 25%（top:30 width:1000），字幕在底部，严格对照 `references/composition-template.html` 坐标，互不重叠
3. **GSAP Seek 安全**：动效属性均可静态重现；数字滚动使用安全闭包
4. **显隐契约**：只 tween opacity 与 transform，显隐切换由 tl.set 托管
5. **标题隔离**：开头标题是提炼的短标题（封面式），绝不是口播正文第一句
6. **字幕校对**：字幕逐句对照 transcript.json 原文校对过，错字补全纠正，每组 ≤2 行
7. **卡片时长闭环**：动效卡登场后内部主体 0.3s 内进场展开，严禁数秒时差空窗

### 阶段 6 · 极速渲染与双重门禁自检（单向终点 · 严禁二次全量重渲染）

1. **执行单次全量渲染**：
   ```bash
   node "<技能根目录>/render.js" public -o output.mp4 --fps 30
   ```
   - 严禁在命令末尾加 `| tail`、`| grep` 等管道符重定向，确保进度条实时输出到控制台。
2. **第一道防线：FFmpeg 快速机器探针（黑屏与合成熔断检测 · 0.2 秒）**：
   渲染完成后，用 FFmpeg 探针命令行秒级读取成片中段（如第 5 秒）的亮度均值，确保合成未黑屏：
   ```bash
   ffmpeg -ss 5 -i output.mp4 -vframes 1 -vf "signalstats,metadata=print" -f null - 2>&1 | grep "YAVG"
   ```
   - 若 `YAVG` 正常输出（非全黑 `YAVG > 10`），即代表视频正常合成且原片画面存在。
3. **第二道防线：黄金代表帧单次视觉核验（限死 1 帧 · 严禁循环抽帧）**：
   仅提取**唯一的一张**动效展开代表帧图片（如 `t=6s`），且**只允许调用唯一一次**图片查看工具过目：
   ```bash
   ffmpeg -y -ss 6 -i output.mp4 -vframes 1 check_preview.jpg
   ```
   - **核验三要素**：① 动效卡是否规整在顶部（未盖住五官）；② 字幕是否在底部正常显示；③ 文字排版未严重挤压重叠。
   - **绝对红线禁令**：**严禁写脚本对每个分段循环抽多张图（如 `f_17.5.jpg`、`f_24.5.jpg`...），绝对严禁调用工具读取第二张图片！**
4. **单向终点成片交付（绝对红线禁令 · Zero Re-render Rule）**：
   - **除致命全黑屏崩溃（YAVG ≤ 10）外，100% 绝对禁止、严禁执行第二次 `node render.js` 全量重渲染！**
   - 无论在核验代表帧中看到任何情况（例如**原片有自带硬字幕冲突**、希望字幕条更暗、想微调卡片颜色、动效速度稍快或稍慢等任何所谓“改善性”主观瑕疵），**均绝对严禁自作主张修改 HTML 再次全量渲染**！
   - **单次全量渲染完成的 `output.mp4` 必须且只能作为本次剪辑的唯一成片终点立即交付给用户！** 任何细微发现与优化建议，只允许在交付回复中用文字客观告知用户。
   - **成果交付铁律**：最终交付物单一且唯一：`output.mp4` 成片视频！所有过程中的 HTML 页面、分段文件、抽检图片仅作为内部渲染临时中间件，**绝对禁止向用户输出或展示任何 HTML 文件的链接或预览**。向用户直接交付 `output.mp4`！

## 关键正面规范（踩过的坑→该怎么做）

| 踩过的坑                        | 该怎么做（正面写法）                                                                     |
| --------------------------- | ------------------------------------------------------------------------------ |
| 黑屏：tween 了 visibility 和框架冲突 | 动效进出用 opacity tween，clip 可见性由 data-start/data-duration 控制                      |
| 卡片不显示：多层嵌套导致中间层 height:0    | card-host 直接包 root，root 用 height:100% 全链贯通                                     |
| 效果差只是平铺字，没动效感               | 每段卡内 4-8 元素分层错峰，元素要满足动效前提（包 span.char / 标 from-to / 用 SVG path）                |
| 动效卡放了整句口播文字                 | 动效卡只放提取的重点信息，单个卡内元素文字数量控制尽可能少一些，只放重点信息，整句交给字幕                                  |
| 动效卡放中部遮住人脸                  | 动效卡放顶部约 25% 区域（上下结构）或侧边约 25%（左右结构），只遮额头不遮五官                                    |
| 增长线套错非数值文案                  | 先理解口播内容性质再选动效形式，数值/累积才用增长线，其他结构选对应形式                                           |
| 字幕凭记忆写，漏平台名、改了列举结构          | 字幕逐句对照 transcript.json 原文校对，保留关键信息词，不改语义结构                                     |
| 区域变大了内容量没变                  | 动效卡尺寸与承载元素数量同步，扩容素材从口播原文找未可视化的关键词                                              |
| 标题字号超画宽裁边                   | 竖屏 1080 宽下标题单行字号上限约 96px                                                       |
| 把口播第一句 / 钩子当标题，还套动效卡样式呈现    | 标题是单独提炼的短标题（封面式：纯文字 + 渐变遮罩，无卡片容器 / 无背景色块 / 无错峰动效）；钩子是字幕内容，两者严格分开               |
| 全屏总结卡盖住了字幕                  | 字幕 track-index 永远最大（> 所有动效卡），全屏卡不能盖字幕                                          |
| 每卡换一套风格/边框/主题，像随机幻灯片        | 身份层每片只选 1 次（1 风格 + 1 边框 + 1 套 `:root` 变量），见 design-guide.md；变化交给布局 + 动效 + 稀疏点缀 |
| snapshot 多个 --at 只存最后一个     | 用成片 + ffmpeg 抽帧验证，比 snapshot 可靠                                                |
| 横屏源转竖屏被裁成竖屏、人物变形            | 信箱居中式：object-fit:contain 居中，上下黑边作动效区/字幕区，原片不裁切                                 |

## 渲染器说明

本技能自带 `render.js` 渲染器（位于技能根目录），用 puppeteer 启动 headless Chrome → 加载 HTML composition → 按 fps 逐帧 `tl.seek(time)` + 截图 → ffmpeg 帧序列合成视频 + 合并原片音频。

composition 的 HTML 结构规范、GSAP timeline 机制、clip 可见性托管（data-start/data-duration + `tl.set` visibility），都是本技能自己的规范，全部写在 `references/composition-template.html` 骨架和各 references 文档里。

技能职责：给 AI 一套"口播原片→动效剪辑视频"的完整工作流和思考方法，让 AI 知道每一步该怎么做、怎么判断、怎么避坑。具体 HTML 写法照骨架搭，动效实现按 motion-thinking 选型自己设计。
