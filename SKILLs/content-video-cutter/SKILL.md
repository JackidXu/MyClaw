# content-video-cutter — 长视频切片

> 客户丢过来一个长视频，AI理解内容后按自然断点切成多段可用素材，每段独立标注入库。
> 切片完成后，调用 content-material-library（素材库管理）将切片标注入库。

---

## 1. 触发词

- `长视频切片`
- `这个视频太长了，帮我切一下`
- `把这段视频切成小段`
- `视频拆分`
- `这段视频里讲了好几个点，每个点切出来`

---

## 2. 核心定位

**视频编导的切片工具。**

客户丢过来一个长视频（如5分钟口播/演示/活动记录），AI理解视频内容，按内容自然断点切成多段10-30秒的可用素材，每段独立分类标注入库。

**与素材库管理的关系**：切片完成后，调用 content-material-library 将每个切片作为独立素材标注入库。切片标注使用素材库管理的同一套分类体系和标注维度。

---

## 3. 输入

### 必需
- **长视频**（至少1种）：
  - 视频文件（用户上传）
  - 视频内容口述描述（用户描述视频内容和结构）

### 可选（增强输出质量）
- **IP档案**（来自 content-ip-manager）— 用于三维定调标注和故事弹药发现
- **已有素材库**（来自 content-material-library）— 用于切片编号接续

## 4. 长视频切片工作流

### 第零步：确认素材库位置

**目标**：在切片保存前，先确认素材库的存储位置。AI不能自行决定保存路径。

**确认逻辑**：
1. 问用户："切片保存前先确认一下——你的素材库放在哪个文件夹？"
2. 如果用户已有素材库（之前用 content-material-library 整理过），让用户告知路径
3. 如果用户还没有素材库："那我帮你新建一个素材库文件夹，你希望放在哪个目录下？比如桌面、Documents、或者项目文件夹里？"
4. 用户指定路径后，本次切片保存到该目录下

> ⚠️ **禁止自行决定保存路径**：不能默认保存到项目目录、Downloads、或任何AI自行选择的路径。路径必须由用户指定或确认。
>
> **引用规则**：素材库位置的完整管理规则见 content-material-library §5。

---

### 第一步：视频内容理解

**目标**：理解长视频的内容结构，识别内容主题切换点。

**技术实现**（按可用工具选择路径）：

> **环境准备（ffmpeg安装）**：系统通常没有预装ffmpeg。通过Python包安装最方便：
> ```
> pip install imageio-ffmpeg
> ```
> 安装后ffmpeg二进制路径：`[Python site-packages]/imageio_ffmpeg/binaries/ffmpeg-macos-aarch64-v7.1`
> 设为变量：`FFMPEG="[上述路径]"`
> whisper转录需要ffmpeg在PATH中：`cp "$FFMPEG" /tmp/ffmpeg && PATH="/tmp:$PATH"`

**路径A：有视频文件 + ffmpeg可用**
1. 获取视频基本信息（时长/分辨率/编码）：
   ```
   $FFMPEG -i [视频文件] 2>&1 | grep -E "Duration|Stream|Video|Audio"
   ```
2. 用ffmpeg提取关键帧：每隔5-15秒提取一帧画面（短视频用5秒间隔，长视频用10-15秒）
   ```
   $FFMPEG -y -i [视频文件] -vf "fps=1/5,scale=480:-1" -q:v 2 keyframe_%03d.jpg
   ```
   - `scale=480:-1` 缩小到480px宽，便于AI快速查看
3. AI逐帧查看关键帧图片，理解视觉内容变化（场景切换/动作变化/展示内容变化）
4. 如果视频有音频，提取音频并用whisper转录文字：
   ```
   # 提取音频为16kHz单声道WAV（whisper所需格式）
   $FFMPEG -y -i [视频文件] -vn -acodec pcm_s16le -ar 16000 -ac 1 audio.wav
   
   # 用whisper转录（tiny模型速度快，base/medium模型更准确）
   PATH="/tmp:$PATH" python3 -m whisper audio.wav --language Chinese --model tiny --output_dir [输出目录] --output_format json
   ```
5. whisper输出JSON包含每段文字的start/end时间戳，用于精确定位内容断点
6. 综合关键帧画面 + 音频转录（如有），建立视频内容时间线

> **whisper模型选择**：tiny（最快，中文有少量错字但语义可理解）/ base（推荐平衡）/ medium（最准确但较慢）

**路径B：有视频文件 + ffmpeg不可用**
1. AI请用户描述视频内容结构和时间节点
2. 追问："这5分钟里你主要讲了几个点？大概每个点在什么时间？"
3. 基于用户描述建立内容时间线

**路径C：用户口述描述视频内容**
1. AI追问视频中的内容结构和时间节点
2. 追问关键断点："讲完第一个点后，是不是换了个话题？大概在几分几秒？"
3. 基于用户描述建立内容时间线

**内容结构识别规则**：
- 按内容主题切换识别断点（"讲完面料工艺，开始讲客户案例" → 断点）
- 按自然停顿识别断点（明显停顿/场景转换/话题转换）
- 每个片段应该是一个完整的内容单元（一个观点/一个演示/一个故事）
- **不要在话说到一半时切——断点必须在语义完整处**

### 第二步：切片方案确认

**目标**：在切片前跟用户确认切分方案，避免切错。

**切片原则**：
- 按内容自然断点切分，**不机械固定时长**
- 每个切片是一个完整的内容单元（一句话/一个观点/一个演示动作）
- 切片时长10-30秒为主，关键黄金片段可更短（5-10秒）
- 如果一段内容超过30秒但不可分割（如一个完整的故事），保留完整，不强切
- 如果一段内容不足5秒，合并到相邻片段

**输出切分方案**：
```
长视频切片方案：

源视频：[文件名/描述] · [总时长：X分X秒]

| 切片 | 时间段 | 时长 | 内容摘要 | 预判分类 |
|------|--------|------|---------|---------|
| C-01 | 00:00-00:15 | 15秒 | 开场介绍+抛出话题 | 人物形象·口播画面 |
| C-02 | 00:15-00:45 | 30秒 | 面料工艺对比演示 | 产品服务·工艺细节 |
| C-03 | 00:45-01:08 | 23秒 | "同款不同命"核心观点 | 人物形象·口播画面 |
| C-04 | 01:08-01:40 | 32秒 | 客户买明星同款翻车案例 | 客户相关·客户案例 |
| ... | ... | ... | ... | ... |

切片统计：共X段，总可用时长X分X秒，弃用X秒（废片）

确认后开始切片。如有需要调整的段落，告诉我。
```

**用户确认规则**：
- **必须等用户确认后才执行切片**
- 用户可能要求调整：合并某两段/拆分某段/调整断点
- 调整后重新输出方案，再确认

### 第三步：执行切片

**目标**：用ffmpeg按确认的方案切分视频。

**技术实现**（有视频文件 + ffmpeg可用时）：
```
# 按时间段提取片段（-c copy速度快，直接复制不重编码）
$FFMPEG -y -i [源视频] -ss [起始时间] -to [结束时间] -c copy [输出文件名].mp4

# 示例：提取00:00-00:25
$FFMPEG -y -i input.mp4 -ss 00:00:00 -to 00:00:25 -c copy output_C01_0000-0025.mp4
```

> **切片后验证**：用ffmpeg检查每个切片的时长是否正确
> ```
> $FFMPEG -i [切片文件] 2>&1 | grep "Duration"
> ```

**文件命名规则**：
**文件命名规则**（必须包含内容描述，不能只写编号）：
- `[原文件名]_C01_[内容关键词]_[时间段].mp4`
- 示例：`7月30日_C01_露脸就一定行吗_开场Hook_0000-0025.mp4`
- 示例：`7月30日_C02_张拉拉案例_拍几千条没效果_0025-0055.mp4`
- 示例：`7月30日_C03_亮哥案例_百万播放零客户_0055-0115.mp4`
- 内容关键词从切片内容摘要中提炼，8-15个字，让人看文件名就知道这段讲什么
- ❌ 不要只写 `C01_0000-0025.mp4`——编号和时间段无法区分内容

**切片保存位置**：
- 保存到第零步确认的素材库目录中
- 如果第零步用户指定的路径为 `~/Desktop/江总_素材库/`，则切片保存到 `~/Desktop/江总_素材库/视频切片/`
- ❌ 不要自行默认保存到项目目录、Downloads或任何AI选择的路径

**无ffmpeg时的降级方案**：
- 输出切片清单（时间段+内容描述），用户用剪辑软件手动切
- 或者推荐用户安装ffmpeg后重试

### 第四步：切片标注入库

**目标**：每个切片作为独立素材，调用 content-material-library 的标注体系和入库流程。

**每个切片标注**（使用素材库管理同一套标注维度）：
```
切片标注：
C-01 [视频·15秒] → 人物形象·口播画面
- 源视频：[文件名] · 00:00-00:15
- 内容描述：江总开场介绍今天要聊的话题
- 六感标签：鲜度
- 三维标签：人物感性·独立观点
- 证据强度：中 — 有观点表达，但缺具体佐证
- 可用片段：整段可用
- 合规风险：无
- 特殊标签：切片来源（源视频+时间段）
- 文件路径：素材库/江总/video_C01_开场Hook_0000-0015.mp4
```

**入库规则**：
1. 每个切片作为独立素材，分配素材库编号（S-XX），接续已有编号
2. 按主分类归入素材库对应分类（使用 content-material-library 的6大分类体系）
3. 在素材库中标注"切片来源"字段，记录源视频+时间段
4. 如果切片中包含新的故事弹药，标注"📝 可入库"
5. 弃用的废片不入库，但在切片报告中记录弃用原因
6. **入库后必须更新索引表**（见下方"索引表更新操作"）

**索引表更新操作**（切片入库时的强制步骤）：

> ⚠️ **切片入库不更新索引表 = 切片等于没入库**。索引表是AI检索素材的唯一入口，不入索引表的切片在选题匹配时无法被发现。

1. 读取素材库根目录的 `_索引表.csv`，获取最大编号
2. 为每个入库切片生成一行记录，填写全部22个字段（字段定义见 content-material-library §5.5）
3. 追加到CSV末尾
4. 切片的"切片来源"字段填入：`[源视频文件名] [时间段]`（如 `7月30日.mp4 00:00-00:15`）
5. 更新 `_索引报告.md`（人类可读报告同步更新）

**切片索引表追加示例**（CSV格式）：
```
S-15,7月30日_C01_露脸就一定行吗_开场Hook_0000-0025.mp4,01_人物形象/7月30日_C01_露脸就一定行吗_开场Hook_0000-0025.mp4,人物形象,口播画面,视频,0:25,8.2M,开场抛出"露脸就一定行吗"的话题,鲜度,人物感性·独立观点,中,整段可用,无,7月30日演讲,演讲现场,2026-07-30,中,7月30日.mp4 00:00-00:25,active,2026-07-30,
```

## 5. 与其他Skill的衔接

| 关系 | Skill | 说明 |
|------|-------|------|
| **调用** | content-material-library（素材库管理） | 切片完成后，调用素材库管理的标注体系和入库流程将切片入库，并更新索引表（`_索引表.csv`） |
| **上游** | content-ip-manager（IP定位管家） | 提供IP档案用于标注参考 |

| **被调用** | content-ip-operator（操盘手系统） | 操盘手的视频切片环节 |

> **切片入库流程**：本skill负责切片+初步标注 → 调用 content-material-library 的分类体系和入库流程完成入库 → 素材库更新后通知用户。

## 6. 交互模式

### 老板模式（默认）
- 快节奏，提取关键帧后快速出方案
- 追问最多1轮
- 适合"这段视频帮我切一下"

### 编导模式
- 深入细节，逐帧分析内容
- 会仔细判断每个断点的合理性
- 追问可到3轮
- 适合"这段视频要仔细切，每段都要能单独用"

---

## 7. 对话风格与边界

### 风格
- 先理解内容，再出方案，确认后才切——不要内容还没看就急着切
- 切片方案要清晰——让用户一眼看出每段切的是什么、多长
- 如果视频内容空洞或质量差，直接说"这段视频可用的内容不多"

### 边界
- 不虚构视频内容——如果看不懂关键帧，追问用户
- 切片不在话说到一半时断开——断点必须在语义完整处
- 不机械按固定时长切片——按内容自然断点切

### 禁止
- **不要未经用户确认就执行切片**——切片方案必须先给用户看，确认后再切
- 不要机械按固定时长切片——每个切片必须语义完整
- 不要在切片阶段就写脚本——这是脚本撰稿的工作
- 不要忽略废片——弃用的片段要记录弃用原因

## 9. 实施建议

1. **先问素材库位置**：切片前必须先确认素材库路径，不能AI自行决定保存位置
2. **按内容断点切**：不机械固定时长，每个切片必须是一个完整的内容单元
3. **切片必须用户确认**：先给方案，确认后再切，避免切错浪费
4. **废片要记录**：弃用的片段不入库，但记录弃用原因
5. **切片标注入库走素材库管理**：切片完成后调用 content-material-library 的分类体系和标注维度，保证一致性
6. **入库后必须更新索引表**：切片入库后追加行到 `_索引表.csv`，不入索引表=切片没入库（详见第四步"索引表更新操作"）
6. **ffmpeg是核心工具**：路径A（有ffmpeg）是最佳路径，路径B/C是降级方案。系统未预装ffmpeg时，通过`pip install imageio-ffmpeg`获取二进制
7. **whisper音频转录**：提取音频后用whisper转录带时间戳的文字，是精确定位内容断点的关键手段。tiny模型够用，base模型更准
8. **切片后验证时长**：用ffmpeg检查每个切片的Duration是否与方案一致
9. **验收标准**：用户看完说"每段都能单独用"或"切得很准，没切碎"
