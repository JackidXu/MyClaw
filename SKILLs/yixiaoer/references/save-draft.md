# 草稿管理 (Draft Management)

## 🚨 最高安全三铁律落地

1. **【默认蚁小二草稿箱】**：用户提到“存草稿”、“先存草稿”、“发送图文”、“分发内容”，**默认 100% 且无条件保存至【蚁小二内部草稿箱】(`yxer draft save <payload.json>`)**，不消耗发布配额，完全不碰外部发布链路，100% 杜绝误发风险。
2. **【小红书等无草稿平台硬拦截】**：小红书等平台的官方 OpenAPI 并没有草稿箱接口。**严禁对小红书等平台调用 `yxer publish`**（否则蚁小二会进入审核并自动公开发布），必须强制降级并保存为蚁小二草稿。
3. **【严禁公开发布】**：Agent 绝对禁止执行任何公开发布动作！正式发布必须由用户手动在客户端或后台操作。

---

## 模式判定与执行

| 场景 | 用户输入特征 | 执行动作 | 安全保障 |
| :--- | :--- | :--- | :--- |
| **模式 1：默认草稿 (最推荐)** | “存草稿”、“先别发布”、“分发刚才的图文” | 执行 `yxer draft save payload.json` | 纯内部存储，不触发任何外部推送 |
| **模式 2：指定无草稿平台** | “发到小红书草稿箱”、“存小红书草稿” | **强制拦截 publish**，执行 `yxer draft save payload.json` | 解释小红书无外部草稿接口，转存蚁小二草稿防公开 |
| **模式 3：指定有草稿平台** | “推送到微信视频号草稿箱” | 执行带 `pubType: 0` 的草稿推送 | 严格锁定 `pubType=0`，绝不携带自动发布参数 |

---

## 存为蚁小二内部草稿 (标准做法)

当需要将图文、视频或文章安全暂存时使用。

### 调用指令

```bash
yxer draft save draft-payload.json --dry-run
yxer draft save draft-payload.json
```

### 反馈给用户

保存成功后，向用户明确提示：
*“✅ 已成功为您保存至【蚁小二草稿箱】。根据安全铁令，AI 不会替您执行公开发布，请您在蚁小二客户端或平台后台手动确认并点击发布。”*

---

## 存为平台草稿 (受限白名单)

仅在用户**硬性明确要求**推入第三方平台草稿箱，且该平台**确实支持平台草稿**时使用：

- **支持平台**：微信视频号（需配置 `contentPublishForm.pubType = 0`）、微信公众号文章等。
- **不支持平台（绝对禁令）**：小红书（无图文草稿接口）、无草稿枚举的平台。对此类平台**绝对禁止调用 `yxer publish`**，一律自动降级为 `yxer draft save`。
