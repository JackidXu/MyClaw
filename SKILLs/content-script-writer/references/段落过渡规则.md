# 段落过渡规则（老板IP口播 · 衔接加强）

> 用途：解决"段落之间衔接不顺滑"的问题。本文件是 `content-script-writer` §4「段落衔接」的可落地操作手册——把"要融合"从原则变成可填空的动作。
> 借鉴来源：`paid-traffic-operator/references/投流脚本格式.md` §5 段落过渡机制，但**适配老板IP口播结构**，并保留本 skill 的两条硬约束（见 §5）。
> 配套使用：`SKILL.md` §4 段落衔接、脚本模板的「过渡：接上/启下」字段、连读版先出规则。

---

## 1. 核心认知：流畅感在"段间"不在"段内"

口播脚本的顺滑，不在单段写多漂亮，而在段与段"接得顺"。选题卡给出的结构（钩子→现象/热点/故事→观点→卖点→CTA）是一条**递进链，不是拼盘**——每段既要接住上一段、又要引出下一段。IP 拿到逐字稿读出来，不应该在画面切换处"卡一下"。

---

## 2. 过渡三原则

1. **每段末埋「启下钩子」**：段落结尾那句，自然抛"然后呢 / 怎么办 / 你看"的钩子，把观众推向下一段。启下钩子不是独立过渡句，是**前一段落点的自然延伸**。
2. **每段首用口语连接词「接上」**：不硬切，用"说白了 / 其实 / 关键就在这 / 你品品"接住上一段情绪与话题。连接词只起"接住"作用，真正的推进靠内容本身。
3. **递进不跳跃**：所有段落服务同一个核心判断（选题卡的观点），一层推一层（现象→观点→卖点→行动）。**删掉连接词，上一句仍能引出下一句**——否则就是跳跃，需补启下钩子。

> ⚠️ 原则 3 是自检的总开关：如果必须把"所以呢""接下来"这类词留下句子才通，**说明段落本身没有递进关系**，不是加词能救的——要回结构。

---

## 3. 四组桥接范式（可填空 · 老板IP口播结构）

| 过渡 | 桥接句范式 | 示例（PCB老板IP·选题2风格） |
|------|-----------|------------------------------|
| 钩子→现象/热点 | 钩子抛反常 → "你发现没{同款现象} / 问题就出在{现象}" | "上半年PCB涨成那样你以为只是行情？你发现没，好多厂子订单看着满了，利润反倒薄了——问题就出在'只盯便宜'这习惯上。" |
| 现象/热点→观点 | 现象讲完 → "这事儿我看不是{表面}，是{观点} / 说白了{观点}" | "都在喊量价齐升，我倒觉得不全是好事。说白了，薄利多销那套，在材料一涨的时候最先露怯。" |
| 观点→卖点 | 观点戳完 → "那怎么办 / 我们厂里是这么干的{具体动作}" | "光盯着便宜要吃大亏。那怎么办？选型上我们帮客户把层数、材料、管理标准先卡死——同样的板子，成本能压下来，品质一动不动。" |
| 卖点→CTA | 方法讲完 → "你想不想也这样 / 现在有个低门槛办法{动作}" | "这套我们做了快三十年。你想不想知道你那块板子有没有更省的路子？把图纸甩给我，免费给你出份优化建议。" |

> 范式是"填空骨架"，不是模板话术。填进去的内容必须来自 IP 真实立场 / 业务事实（见 `SKILL.md` §8 事实标注），不得编造。

---

## 4. 口语连接词库（去AI味友好版）

> 重要：以下词用于"接上"上一段，**只用一次或偶尔**，不构成独立过渡句。避免任何"路牌式"套路词（见 §5 红线）。

- **承接现象**：说白了 / 其实 / 你品品 / 说穿了
- **引出观点**：关键就在这 / 我看得更透一点 / 换个角度看
- **引出卖点/方案**：那怎么办 / 我们拆开看 / 真正的做法是 / 我厂里是这么干的
- **引出行动**：想不想也这样 / 现在有个办法 / 你只需要一步

> ❌ 禁用词（典型 AI 腔 / 路牌式，与去AI味目标冲突）："那问题来了""那么这对我们意味着什么""接下来我们来聊聊""话说回来"。这些要么制造假悬念、要么像 PPT 翻页，观众一听就出戏。

---

## 5. 两条硬约束（本 skill 独有，必须遵守）

1. **⚠️ 首尾融合在去AI味之前完成**：段落衔接写进完整脚本**初稿**，在去AI味优化**之前**。顺序：初稿写段落 → 首尾融合（调衔接）→ 去AI味（去 AI 腔）→ 终稿。去AI味之后**不要**再改段落结构，否则破坏去味效果。
2. **⚠️ 禁止路牌式过渡**：不写"那这对我们意味着什么？""接下来讲另一件事"这类独立过渡句。过渡通过前段落点自然引出下段起点实现，观众听不出"这里在过渡"，只感觉"讲完这个，自然想到下一个"。

---

## 6. 过渡自检清单（组装后必过）

- [ ] 删掉每段首句连接词，上一句能否自然引出下一句？不能 → 补启下钩子或回结构
- [ ] 每段是否接住上段 + 引出下段？有硬切 → 补过渡（用 §3 范式）
- [ ] 所有段落是否层层递进服务同一核心判断（选题卡观点）？跳脱段 → 重排或删
- [ ] 有无路牌式过渡词（§4 禁用词）？有 → 删，改用首尾融入
- [ ] 连读版（见 §7）是否顺滑？不顺 → 回到 §2 原则 3 重调

---

## 7. ★ 连读版先出（治本招）

**终稿先交付"连起来能读"的完整版，再给分段版。** 用户上次看到的"分段脚本"恰恰是衔接感弱的根源——分段把过渡切断了，看不出顺不顺。

**输出顺序**：
1. 先出 `## 连读版（逐字稿全文）`：把各段口播 + 过渡连接词**织成一段连续可读的文字**，过渡处用〔接〕标记（如：`…薄利多销那套不好使了。〔接〕光盯着便宜要吃大亏——`）。IP 一眼能判断"读起来顺不顺"。
2. 再出 `## 分段版（带过渡字段）`：按模板逐段展开，每段标注「过渡：接上/启下」。

> 〔接〕标记只在连读版用于可视化过渡点，不进入最终拍摄稿。拍摄稿就是连读版清掉标记后的纯口播。
