> 状态：7/9项已完成（其中2项基于已有内容补全完善），钩子模板(§7)和信任/信息配比(§8)待后续补充

## 1. 类型定义

### 一句话定义

Vlog以一段真实发生的经历或过程为叙事主线，以人物行动、现场变化和真实细节为主要证据，再通过同期声、旁白和字幕完成表达。

### 核心特征

- **事件驱动**：有一条真实的经历或过程作为叙事主线，不是纯观点表达
- **行动为主**：以人物行动、现场变化为主要内容，旁白负责解释、串联和升华
- **证据来自现场**：同期声、真实画面、现场反应是核心证据，旁白是补充

### 与旁白视频的区别

| 维度 | VLOG视频 | 旁白视频 |
|------|---------|---------|
| 叙事主线 | 事件和人物行动 | 文案和观点 |
| 画面角色 | 画面是主要证据 | 画面辅助表达 |
| 旁白角色 | 解释、串联、升华 | 承载核心内容 |
| 同期声 | 核心证据之一 | 较少使用 |

## 2. 适合性检查标准

### 四项检查

| 序号 | 检查项 | 通过标准 | 不通过的含义 |
|------|--------|---------|------------|
| 1 | 有真实事件 | 有一件即将发生或已经发生的具体事件，而不只是一个观点 | 如果只是想表达观点，应用口播或旁白视频 |
| 2 | 有人物行动 | 有人物在事件中的实际动作（出发、沟通、处理、交付等），不只是坐着讲话 | 如果只是坐着讲话，应用场景口播 |
| 3 | 有过程变化 | 事件有起因、经过、结果的过程变化，不是静态状态 | 如果没有过程，素材会匮乏 |
| 4 | 有现场证据 | 有值得记录的细节、关系、反应、冲突或结果 | 如果没有现场证据，Vlog会变成流水账 |

### 判断规则

- **四项中三项以上成立** → 适合做Vlog
- **四项中两项成立** → 需评估是否有足够素材支撑，建议考虑其他类型
- **四项中一项以下成立** → 不适合做Vlog，应建议改用口播或旁白视频

> 若多数条件不成立，应建议改用口播或旁白视频，而不是强行套Vlog。

## 3. 内容方向类型

### 三类内容任务

| 内容类型 | 核心问题 | 主要目标 |
|---------|---------|---------|
| 传播型 | 别人为什么要认识你？ | 获得触达、讨论、分享或公共认知 |
| 人设型 | 别人为什么要信任你？ | 展示经历、选择、价值观、状态与关系 |
| 业务型 | 别人为什么要购买你？ | 展示客户问题、专业判断、服务路径与结果 |

### 判断原则

- **场景名称不能直接决定内容类型**。同样是客户拜访，展示关系可做人设型，展示诊断能力可做业务型，借现场讲行业普遍问题可做传播型。
- **一次只设一个主要内容任务**；允许一个次要任务，但不能三类平均用力。
- **不为了凑数强行生成传播、人设、业务三个方向**。

### 主旨锚点

六选一为主：认知 / 能力 / 信任 / 结果 / 位置 / 关系

## 4. 场景框架

### 五类场景

| 场景 | 优先类型 | 常见证明方向 | 典型叙事主线 |
|------|---------|------------|------------|
| 客户拜访 | 业务 / 人设 | 专业判断、客户关系、服务态度 | 为何去 → 发现什么 → 如何处理 → 反馈 |
| 出差 | 人设 / 传播 | 工作状态、选择、见闻、行业观察 | 为何出发 → 途中经历 → 关键见闻 → 判断 |
| 参加活动 | 人设 / 传播 | 行业位置、关系、现场观察 | 为何参加 → 谁在场 → 看到什么 → 判断 |
| 个人生活 | 人设 / 传播 | 性格、习惯、家庭关系、身份反差 | 生活切口 → 真实细节 → 人物选择 → 价值观 |
| 项目交付 | 业务 / 人设 | 服务流程、专业标准、结果、责任感 | 背景 → 难点 → 执行动作 → 结果与复盘 |

### 拍摄配置

| 配置 | 必须输出 |
|------|---------|
| 老板自拍 | 5-8个必拍镜头；手机如何摆；每镜建议时长；现场说什么；哪些回来补旁白 |
| 摄影师跟拍 | 环境、人物、动作、细节、反应五类镜头；景别；同期声；必拍与备选；客户采访问题 |
| 编导+摄影师 | 主线、分段目标、完整分镜、现场调度、采访、情绪节点、转场、同期声、备用叙事 |

### 旁白视角

| 视角 | 优先适用 |
|------|---------|
| 第一人称 | 老板亲历、个人选择与感受、出差生活、创业经历、人设型 |
| 第三人称 | 纪录片感、多人物多时间线、观察视角、老板不适合自行讲述 |
| 第一人称+同期声 | **默认优先**：旁白交代背景与判断，同期声证明真实，画面展示行动 |

### 两类用户模式

| 用户 | 交互原则 | 输出侧重 |
|------|---------|---------|
| 老板本人 | 少术语、少填写、用对话追问；优先保证能完成 | 必拍镜头、手机摆放、现场说什么、回来补什么 |
| IP编导 | 允许更完整的策划字段和专业表达 | 内容主线、分镜、同期声、调度、采访、备选叙事 |

## 5. 素材分类维度

### 五类素材

| 类别 | 作用 | 示例 |
|------|------|------|
| 环境 | 交代时间、地点和事件背景 | 办公室、客户公司门口、出差途中、活动现场 |
| 行动 | 证明老板实际做了什么 | 沟通、演示、检查、处理问题、签字 |
| 对话 | 保留真实判断、信息和关系 | 客户原话、同行交流、团队讨论 |
| 反应 | 证明情绪、信任和变化 | 客户表情、犹豫、认可、现场冲突 |
| 结果 | 证明事情最终产生了什么 | 签约、交付物、反馈截图、前后对比 |

### 事实状态标记

| 状态 | 处理规则 |
|------|---------|
| 已有证据 | 素材中真实存在，可直接用于成片 |
| 口述事实 | 老板复盘提供但画面没有；可用旁白交代，不伪装成现场 |
| 待核实 | 数据、结果、客户说法需确认后使用 |
| 不可使用 | 涉及隐私、保密或未经授权的信息 |
| 缺失内容 | 可提出补录建议，不得虚构 |

### 拍摄后核心原则

> 拍摄后的内容判断可以推翻拍摄前策划。实际拍到的最强素材是什么，就优先围绕什么成立内容，不能为了服从原计划而浪费真实证据。

## 6. 脚本格式

### 6.1 总体结构

Vlog脚本的叙事主线是**事件的时间线**，不是观点的逻辑线。脚本结构遵循"事件起因 → 过程展开 → 关键转折 → 结果/认知"的自然叙事弧。

#### 通用Vlog脚本结构

| 段落 | 占比 | 时长（60秒基准） | 核心内容 | 主要素材类型 |
|------|------|----------------|---------|------------|
| 1. 钩子 | 5-8% | 0-4s | 用最抓人的画面/同期声/悬念引入事件 | 反应/结果类 |
| 2. 事件背景 | 15-20% | 4-15s | 交代为什么发生、谁参与、要解决什么 | 环境类 |
| 3. 过程展开 | 35-45% | 15-40s | 关键行动、现场变化、同期声——事件的核心过程 | 行动/对话类 |
| 4. 高潮/转折 | 15-20% | 40-50s | 最强证据、关键对话或反应——证明主旨的时刻 | 反应/结果类 |
| 5. 感悟/判断 | 10-15% | 50-56s | IP的判断、认知或价值观——事件说明了什么 | 旁白为主 |
| 6. CTA | 5-8% | 56-60s | 行动号召——与事件和主旨相关 | IP出镜 |

> 注：以上为60秒基准。实际时长按选题要求调整，各段占比保持不变。

### 6.2 按场景的叙事结构变体

通用结构不变，不同场景的叙事弧侧重不同：

| 场景 | 段落3"过程展开"的叙事弧 | 段落4"高潮/转折"的重点 |
|------|----------------------|---------------------|
| 客户拜访 | 发现问题 → 专业判断 → 处理方式 | 客户反馈/认可时刻 |
| 出差 | 途中见闻 → 关键遭遇 → 行业观察 | 意外发现或认知刷新 |
| 参加活动 | 谁在场 → 看到了什么 → 关键交流 | 行业位置感知或关系确认 |
| 个人生活 | 生活切口 → 真实细节 → 人物选择 | 价值观碰撞或身份反差 |
| 项目交付 | 背景 → 难点 → 执行动作 | 结果展示或复盘发现 |

### 6.3 旁白与同期声的使用规则

| 内容类型 | 使用方式 | 理由 |
|---------|---------|------|
| 事件背景、时间地点 | 旁白交代 | 同期声太碎，旁白更高效 |
| 现场对话、客户原话 | 同期声保留 | 旁白无法替代真实声音 |
| IP的判断和认知 | 旁白表达 | 需要提炼升华，现场不一定说得出 |
| 现场反应、情绪 | 同期声+画面 | 反应是证据，旁白描述不如现场呈现 |
| 数据、结果 | 旁白交代+画面展示 | 需要准确性，旁白可控 |

**默认视角**：第一人称+同期声——旁白交代背景与判断，同期声证明真实，画面展示行动。

### 6.4 脚本格式示例

```markdown

**选题来源**：[选题卡标题]
**视频类型**：VLOG视频
**内容任务**：[传播型/人设型/业务型]
**主旨锚点**：[认知/能力/信任/结果/位置/关系]
**预计时长**：[XX秒]
**目标平台**：[抖音/小红书/视频号/全平台]
**旁白视角**：[第一人称+同期声 / 第一人称 / 第三人称]

---

## 钩子方案
[由content-script-writer第二步生成]

## 平台标题
[由content-script-writer第二步生成]

---

## 脚本正文

### 段落1：钩子（0-4秒）
**画面**：[画面描述 / 素材编号 / 拍摄需求]
**同期声**：[如有现场原话，保留并标注] 或 **旁白**：[旁白逐字稿]
**事实状态**：🟢事实 / 🟡判断 / 🟠推测 / 🔴需验证
**补录提示**：[如需补录，写明拍什么]

### 段落2：事件背景（4-15秒）
**画面**：[环境类素材 — 交代时间、地点、事件背景]
**旁白**：[逐字稿]
**同期声**：[如有现场原话]
**事实状态**：[标注]

### 段落3：过程展开（15-40秒）
**画面**：[行动/对话类素材 — 关键行动、现场变化]
**旁白**：[串联和解释，不抢同期声]
**同期声**：[保留关键现场对话]
**事实状态**：[标注]

### 段落4：高潮/转折（40-50秒）
**画面**：[反应/结果类素材 — 最强证据]
**同期声**：[关键原话或反应]
**旁白**：[点题——这个时刻说明了什么]
**事实状态**：[标注]

### 段落5：感悟/判断（50-56秒）
**画面**：[IP出镜或相关画面]
**旁白**：[IP的判断、认知或价值观]
**事实状态**：🟡判断（感悟通常是IP的主观判断）

### 段落6：CTA（56-60秒）
**画面**：[IP出镜直视镜头]
**旁白**：[行动号召]
**事实状态**：[标注]
**CTA类型**：[评论区互动/私信咨询/关注追更/...]

---

## 话题标签
#标签1 #标签2 #标签3 #标签4 #标签5

## 补录清单（如有）
- [ ] [补录内容] — 用于段落X — [拍什么/怎么拍]

## 事实核验清单（如有🔴需验证项）
- [ ] [需验证内容] — 验证方式：[怎么验证]
```

### 6.5 与通用脚本格式的差异

Vlog脚本与content-script-writer默认脚本格式的主要差异：

| 项目 | 通用脚本格式 | Vlog脚本格式 |
|------|------------|------------|
| 叙事主线 | 观点逻辑线（钩子→论点→论据→CTA） | 事件时间线（起因→过程→转折→结果） |
| 口播/旁白 | 口播为主，全程IP对着镜头说 | 旁白+同期声交替，旁白串联、同期声证明 |
| 同期声 | 无 | 有，且是核心证据 |
| 画面指引 | 辅助说明 | 核心内容，画面本身就是证据 |
| 段落结构 | 钩子→正文2-3段→CTA | 钩子→背景→过程→高潮→感悟→CTA |

## 7. 钩子模板

> ⏳ **待补充**：Vlog类型的专属钩子模板待后续提供。

### 已有规则（来自交互规则）

- 不使用"今天我来到了……"作为默认开头，除非地点或事件本身具有稀缺性
- 钩子应与事件最抓人的部分挂钩，不按时间顺序开头

### Vlog钩子特征（基于类型定义推导）

Vlog是事件型内容，钩子应优先使用：
- **事件结果前置**：直接抛出事件最出人意料的结果
- **现场同期声开场**：用一句真实对话/反应引入
- **悬念引入**：暗示事件有反转或意外

> 待用户提供Vlog专属钩子模板后，本节将替换为完整的钩子风格和模板表。

## 9. 方法论校验规则

### 9.1 类型合规检查

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 事件真实性 | 脚本基于一个真实事件，不是纯观点表达 | 建议改用口播或旁白视频 |
| 行动存在性 | 脚本中有人物的实际行动，不只是坐着讲话 | 补充行动素材或改用场景口播 |
| 过程完整性 | 脚本有事件起因、过程、结果的完整弧线 | 补充缺失环节或调整结构 |
| 证据充分性 | 脚本中的关键判断有现场证据支撑 | 补录素材或标注为判断/推测 |

### 9.2 内容质量检查

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 非流水账 | 每段有明确目的和记忆点，不是行程记录 | 删除流水账段落，强化主线 |
| 记忆点明确 | 观众看完能说出一个具体记忆点 | 重新聚焦主旨锚点 |
| 证据主线 | 有一条清晰的证据链支撑主旨 | 梳理证据逻辑，补录缺失素材 |
| 主次分明 | 一个主要内容任务+至多一个次要任务 | 删除次要任务或合并 |

### 9.3 旁白与同期声检查

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 同期声使用 | 关键对话和反应保留了同期声，不用旁白替代 | 恢复同期声或补录 |
| 旁白角色 | 旁白用于背景交代和判断升华，不抢同期声 | 调整旁白内容 |
| 旁白伪装 | 口述事实不用同期声伪装成现场原话 | 改为旁白交代 |
| 旁白开头 | 不使用"今天我来到了……"作为默认开头 | 修改开头方式 |

### 9.4 事实完整性检查

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 事实标注 | 每段标注事实状态（🟢/🟡/🟠/🔴） | 补充标注 |
| 数据出处 | 所有具体数字有出处或标🔴需验证 | 补充出处或标注 |
| 不虚构 | 不编造客户细节、数据、结果、对话或冲突 | 删除虚构内容 |
| 口述vs证据 | 口述事实与画面证据明确区分 | 标注区分 |

### 9.5 风险合规检查

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 客户隐私 | 未经许可不公开客户身份、数据、对话 | 删除或脱敏处理 |
| 结果承诺 | 不把单个案例写成普遍承诺或保证结果 | 修改措辞 |
| 冲突夸大 | 不为传播性人为制造或夸大冲突 | 修改或删除 |
| IP立场 | 不把IP表达得比真实立场更极端 | 修改措辞 |
| 授权检查 | 拍摄前已提示客户授权、员工出镜、场地风险 | 补充授权提示 |

### 9.6 拍摄后推翻检查

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 素材优先 | 成片围绕实际拍到的最强素材成立，不服从原计划 | 根据实际素材重构 |
| 缺失处理 | 缺失内容提出补录建议，不虚构 | 补录或删除相关段落 |
| 素材分类 | 素材按环境/行动/对话/反应/结果分类盘点 | 补充分类 |
