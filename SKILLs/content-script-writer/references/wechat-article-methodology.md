# 公众号文章方法论（模式D专用）

> 本文件是 content-script-writer「模式D：公众号文章脚本」的详细方法库。
> 融合了 WeWrite 公众号写作的核心文案方法论（文章任务书 / 主张清单 / 七种框架 / 内容增强 / 编辑质量五维 / 风格校准），并适配到 IP 内容流程：
> **IP 档案替代 style.yaml 与写作人格，选题复用 content-topic-engine 的一鱼多吃，事实标注沿用 🟢🟡🟠🔴 体系。**
> 本文档不含配图 / 发布 / 数据方法（按流程约定不纳入）。

---

## 0. 与 IP 流程的关系

公众号文章是 IP 内容矩阵的「深度长文」形态，与短视频（模式A/B）、朋友圈（模式C）构成内容三形态：

| 形态 | 角色 | 长度 | 核心目标 |
|------|------|------|---------|
| 短视频（模式A/B） | 公域引流·立骨架 | 60-90秒 | 抓眼球、讲清一个点 |
| 朋友圈（模式C） | 私域养信任 | 50-150字 | 熟人场建信任、轻互动 |
| **公众号文章（模式D）** | **深度沉淀·立言场** | **1200-2500字** | **系统讲透一个判断、建立专业权威** |

**风格来源**：IP 档案的「风格定位」+「精神内核」替代 WeWrite 的 style.yaml 与 7 个内置人格。
**选题来源**：优先复用 content-topic-engine 的「一鱼多吃」建议（同一事件 → 公众号深度版）；或用户直接给选题；或按本文件 §3 七种框架 + 内容策略树自行拆选题。
**事实标注**：沿用 §8 的 🟢🟡🟠🔴 体系，与主张清单（claims）的类型/状态字段一一对应。

---

## 1. 文章任务书（brief）

动笔前必须先定义文章任务书 —— 让「写得像一篇文章」变成「解决一个明确的读者问题」。字段可补充，但核心项不能省略。

### brief 模板

```yaml
version: 1
audience:
  who: "具体读者（来自IP档案核心客户·三层靶子）"
  context: "读者在什么情境下读这篇文章"
  question: "读者真正要解决的问题"
goal:
  takeaway: "读完能复述的一个结论"
  action: "读完可以采取的行动；纯观点文可写判断方法"
thesis:
  statement: "全文核心判断"
  novelty: "相较常见说法新增了什么（不强行唱反调）"
  boundary: "结论在什么条件下成立"
  counterpoint: "最强反方或替代解释"
personal_materials:
  available: false
  items: []          # 只记录用户在本次任务明确提供的经历/观察/原话；IP档案故事弹药库算可用材料
framework: "观点"      # 痛点/故事/清单/对比/热点解读/观点/复盘
sections:
  - purpose: "本节推进什么"
    claim_ids: [C1]
constraints:
  desired_length: "1200-2500 字"
  must_include: []
  must_avoid: []
```

### 与 IP 档案的映射

| brief 字段 | IP 档案来源 |
|-----------|------------|
| audience.who / question | 核心客户·三层靶子（最外层人群 → 中间层痛点 → 内层决策焦虑） |
| thesis.statement | IP 的核心判断 / 精神内核 / 业务性感主张 |
| personal_materials.items | 故事弹药库（真实事件，标注「可用」的才能用） |
| framework | 内容策略树分支（业务定调→干货/科普；信任定调→故事/案例；人物定调→情绪/共鸣） |
| constraints.must_avoid | 红线清单 |

### novelty 的边界

`novelty` 不是强行唱反调。找不到可靠新角度时，**缩小问题、补充适用条件、或提供更好用的判断框架**。

## 2. 主张清单（claims）

围绕文章真正需要证明的 3-6 个主张，每条标注类型、来源与状态。

### claims 模板

```yaml
version: 1
claims:
  - id: C1
    text: "正文准备表达的主张"
    type: fact              # fact / inference / opinion / user_experience
    source_ids: []          # 对应素材/来源编号；意见可为空
    status: supported       # supported / bounded / unsupported
    boundary: "适用范围或不确定性"
```

### 与 🟢🟡🟠🔴 事实标注体系的映射

| claims.type | 对应标注 | 说明 |
|-------------|---------|------|
| fact | 🟢 事实 | 必须有能直接支持它的来源；否则删除或标 unsupported |
| inference | 🟠 推测 | 要列出依据并明确这是推断 |
| opinion | 🟡 判断 | IP 的主观观点，不伪装成共识 |
| user_experience | 🟢/🟡 | 只来自 IP 档案故事弹药库或本次用户明确提供的材料 |

- `unsupported` 的主张**不得进入初稿**。
- 每一节至少服务一个主张；无法对应主张的段落默认删除。
- 与 §8 事实标注规则一致：数据必须有出处、IP 观点不标🟢事实、热点信息标🔴需验证。

## 3. 七种框架（frameworks）

按读者问题选框架。框架是组织工具，不是必须填满的模板；材料不足时缩小主张，不用空话补齐结构。

| 框架 | 适用 | 基本推进 | IP 四柱映射 |
|------|------|---------|------------|
| **痛点** | 读者有明确困难 | 场景 → 根因 → 解法 → 边界 | 业务定调（立言） |
| **故事** | 人物与变化是核心 | 冲突 → 选择 → 结果 → 含义 | 信任定调（立信）/ 人物定调（立人） |
| **清单** | 读者要快速行动 | 目标 → 条目 → 用法 → 避坑 | 业务定调（立言） |
| **对比** | 需要做选择 | 标准 → A/B 证据 → 适用人群 → 建议 | 业务定调（立言） |
| **热点解读** | 事件正在变化 | 发生了什么 → 为什么 → 影响 → 观察点 | 业务定调（立言） |
| **观点** | 核心价值是判断 | 主张 → 证据 → 反方 → 边界 | 业务定调（立言）/ 立势 |
| **复盘** | 过程经验可迁移 | 目标 → 做法 → 偏差 → 学到什么 | 信任定调（立信）/ 立势 |

**选题缺位时的拆法**：如果用户只给了一个大方向没有具体选题，用内容策略树 + 七种框架自行拆 2-3 个候选选题让用户选（如「这个方向可以写痛点型/观点型/清单型，你要哪个？」）。

## 4. 内容增强（content-enhance）

增强目标是让主张更值得读、更能被证据支撑，**不是强行反转、堆数字或制造故事**。先完成 brief 与 claims，再按框架选一项主策略；材料不够时缩小主张或换框架。

| 框架 | 主增强策略 |
|------|-----------|
| 观点 / 热点解读 | **可支持的新角度**：浏览代表性已有解释，列出共识/分歧/被忽略条件，选一个有证据的新贡献（更准确因果、更清楚边界、对具体读者的影响、更好用判断框架）。不能为了尖锐反对主流，也不能把推测写成内幕 |
| 痛点 / 清单 | **行动可用性**：逐节检查读者能否开始行动，补齐步骤/条件/成本/风险/失败信号。具体工具/参数/价格/版本都属事实，必须核实且注时效 |
| 故事 / 复盘 | **有来源的真实细节**：只使用 IP 档案故事弹药库或可靠来源明确记载的时间/地点/对话/细节。材料不足时改事实叙述或换框架，禁止「合理重建」、拼接人物、添加感官细节 |
| 对比 | **决策条件**：先定义共同标准，再比较证据/限制/总成本/适用人群。官方信息用于功能价格，用户评价只代表被引用者体验，不能外推为普遍事实 |

**通过检查**：新角度能由证据和逻辑支持；具体信息都有来源或边界；没有把第三方故事/范文改写成 IP 亲历；每个增强点都服务读者问题和核心主张。

## 5. 编辑质量五维（editorial-quality）

五项各按 1-5 分判断。交付要求：平均分至少 4，单项不低于 3，且没有阻断问题。

| 维度 | 标准 |
|------|------|
| **准确** | 核心事实有直接来源；事实/推断/意见分得开；结论没超出证据边界 |
| **观点** | 核心判断明确，说明新增价值、适用范围、最强反方，不重复常识充数 |
| **有用** | 真正回答目标读者的问题，给出可执行行动/决策条件/可迁移理解框架 |
| **合声** | 符合 IP 语气但不被模板绑架；个人经历只来自 IP 档案故事弹药库或本次用户材料；没有挪用范文 |
| **好读** | 开头迅速进入问题，各节各有任务，论证连贯，标题准确，语言直接无重复 |

### 阻断问题（任一出现都不能交付）

- 编造 IP 亲历、朋友、采访、对话、场景或身份（超出故事弹药库范围的）
- 核心具体事实没有来源，或来源不支持正文说法
- 核心论点与证据脱节，或把推断写成确定事实
- 文章没有给目标读者明确的结论、行动或判断方法

### 编辑决定

- `pass`：没有阻断问题，五项达交付要求
- `revise`：问题能在现有材料内修正 —— 必须直接修改并重新检查，不能只列建议
- 最多两轮。第二轮仍未达到要求时，不得假装通过：删除不可靠内容、缩小承诺，交付能被证据支持的版本

## 6. 标题 / 摘要 / 标签

文章成稿后（去AI味后）产出：

- **主标题**：准确、有明确对象和利益点（不靠标题党）
- **2 个备选标题**：角度略有差异，供 IP 选
- **摘要**：40 字内，点明核心判断与读者收益
- **标签**：3-5 个（1 个 IP 专属 + 2 个行业 + 1 个热点/话题 + 1 个泛流量），来自 IP 档案标签库

> 关键词自然出现，不按密度硬塞，也不为打开率虚构数字或承诺。

## 7. 长文去AI味（qu-ai-wei 集成）

公众号文章由 AI 生成长文，AI 腔密度远高于短视频口播和朋友圈，**去AI味是强制步骤**。

| 项目 | 规则 |
|------|------|
| **语体** | 内容/自媒体（公众号长文） |
| **处理范围** | 整篇正文 + 标题 + 摘要（不含任务书/主张清单/编辑报告） |
| **分段处理** | 1200-2500 字整篇处理；如单次过长，按「节」切分后逐节处理，保持节间衔接自然 |
| **语音校准** | IP 档案风格定位（高频词/句长/段首词/标点/语域）+ 精神内核 |
| **核心规则** | 51 条模式全扫；#48 否定对举（「不是X，是Y」）无论 X/Y 是否具体均触发，且须**重组整句**而非换词保结构（判定标准：改写后是否还能看出对举骨架，看得出→继续重组） |
| **长文特殊关注** | ① 段落节奏过齐（每段同长同构）→ 打乱；② 小标题套话（「综上所述」「总而言之」）→ 清除；③ 论证空转（用共识/套话凑字数）→ 补具体；④ 万能开头（「今天跟大家分享」）→ 替换具体场景 |
| **禁止** | 不改事实内容（不发明事实）、不改段落数与顺序（除非为节奏重排且经用户确认）、不改 IP 语体档位（语体降级保护） |

---

## 8. 风格从 IP 档案校准

公众号文章的人格来源 = **IP 档案风格定位 + 精神内核**，不使用 WeWrite 的 7 个内置人格（midnight-friend / industry-observer / sharp-journalist / warm-editor / cold-analyst / humor-storyteller / tech-coder）。

| IP 档案字段 | 校准用途 |
|-----------|---------|
| 风格定位（5 项清单） | 高频词、句长、段首词、标点偏好、语域 —— 直接作为语音校准样本 |
| 精神内核 | 确保文章价值观一致（如「顺其自然」「不认命」），改写不偏离 |
| 红线清单 | 改写不触碰红线（如「不追单」→ 结尾不能改成催促语） |
| 故事弹药库 | 个人材料唯一合法来源，禁止超出范围编造 |

**缺 IP 档案时**：风格定位使用中性默认（第一人称、像懂行的朋友在分享见解），并提示用户先完成 IP 建档；不强行套用任何内置人格。
