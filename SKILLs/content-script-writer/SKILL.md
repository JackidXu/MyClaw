# content-script-writer — 内容脚本路由器

> 选题卡进来，写钩子、出标题、生成可拍摄的完整脚本。事实标注让每句话经得起检验，补录提示让拍摄不漏料。

## 2. 核心定位

**不是"帮你写一篇作文"，而是"帮你把选题卡变成一份能直接拿去拍的脚本"。**

脚本是拍摄现场的操作文档，不是阅读材料。本Skill的工作是：
1. 读懂选题卡（或用户文案），锁定讲什么、怎么讲
2. 生成3+个钩子和平台标题，让前3秒抓住人
3. 生成2-3个脚本大纲，让用户选结构
4. 选定大纲后，写出完整逐字稿——每一段标画面、标素材、标事实状态
5. 标注哪些是事实、哪些是判断、哪些需要验证——让IP对自己说的话负责
6. 列出补录清单——拍摄时别忘了拍什么

**朋友圈文案模式（模式C）**：不是"帮你写一条广告"，而是"帮你在熟人社交场里说一句有价值的话"。朋友圈的本质是熟人社交场，不是广告投放渠道。每条文案都要回答朋友心里那个问题："这跟我有什么关系？"

**公众号文章模式（模式D）**：不是"帮你凑一篇长文"，而是"帮你在深度长文里系统讲透一个判断"。公众号是 IP 的「立言场」——短视频立骨架、朋友圈养信任、公众号立权威。公众号文章要像一个有专业沉淀的人在认真讲一件事：先明确读者问题、核心判断与证据边界，再动笔；审稿不通过就直接改稿，禁止编造 IP 经历。

## 3. 输入

### 必需（二选一）

| 输入类型 | 说明 | 工作模式 |
|---------|------|---------|
| **选题卡** | 来自 content-topic-engine，包含选题标题、三维映射、六感、公式拆解、内容方向、推荐视频类型 | 模式A：从选题卡出发 |
| **用户文案** | 用户自己写的文案/口播稿/AI初稿，需要结构化为可拍摄脚本 | 模式B：从文案出发 |
| **选题/方向**（公众号文章） | 用户直接给的公众号选题/方向，或 content-topic-engine 的「一鱼多吃」建议中标注的公众号深度版 | 模式D：公众号文章脚本 |

### 可选（增强输出质量）

| 输入 | 来源 | 用途 |
|------|------|------|
| **素材匹配报告** | content-material-matcher | 告诉脚本每段用什么素材，哪些段缺素材需要补录 |
| **IP档案** | content-ip-manager | 语言风格对齐、购买理由植入、红线检查 |
| **视频类型偏好** | 用户指定 | 如果用户已有明确的视频类型偏好，优先使用 |

> **如果没有素材匹配报告**：脚本仍可生成，但每段的画面/素材指引改为"拍摄需求"——标注需要拍什么，而不是用哪个已有素材。相当于同时输出脚本+拍摄需求清单。

## 4. 三种工作模式

### 模式A：从选题卡出发（标准流程·视频）

用户拿着选题卡（可能还有素材匹配报告）进来，AI从零生成脚本。

**典型场景**：
- "选题卡选好了，帮我写个脚本"
- "方向B确认了，出口播稿"

**流程**：选题卡 → 视频类型确认+方法论加载 → 钩子标题 → 大纲 → 完整脚本（初稿）→ 去AI味优化 → 事实标注 → 补录清单

### 模式B：从文案出发（优化/结构化·视频）

用户已有文案（自己写的或AI初稿），需要AI把它整理成可拍摄的结构化脚本。

**典型场景**：
- "帮我把这个文案整理成脚本"
- "优化一下这个口播稿"
- "这个文案帮我改成拍摄脚本"

**流程**：用户文案 → 视频类型确认+方法论加载 → 分析结构 → 钩子标题优化 → 结构化脚本（初稿）→ 去AI味优化 → 事实标注 → 补录清单

**模式B的特殊规则**：
1. **不推翻用户文案重写**——用户文案是基础，AI做的是结构化+优化，不是另起炉灶
2. **保留用户的语言风格**——如果文案有明显个人风格（口语化/书面化/幽默/严肃），保留它
3. **补全缺失要素**——如果文案缺钩子、缺CTA、缺事实标注，补上
4. **标注优化点**——告诉用户改了什么、为什么改

### 模式C：朋友圈文案生成

用户需要生成朋友圈文案，或进行朋友圈运营规划。朋友圈是独立于短视频的内容渠道，遵循不同的创作法则。

**典型场景**：
- "帮我写条朋友圈"
- "今天发生了XX事，发个朋友圈"
- "这周朋友圈怎么排"
- "新品上市，写几条朋友圈"

**流程**：IP档案加载+行业规则匹配 → 事件/主题确认 → 六感判断 → 内容类型选择 → 文案生成（六条铁律）→ 去AI味优化 → 合规检查 → 交付

**模式C的核心差异**（与模式A/B的区别）：
1. **不是脚本而是文案**——不需要画面指引、素材标注、补录清单，产出的是可直接复制粘贴的朋友圈文字
2. **熟人社交场逻辑**——不是公域流量的"抓眼球"，是私域的"建信任"。每条文案都在回答"这跟我有什么关系"
3. **行业规则驱动**——18个行业有各自的人设定位、内容类型配比、文案模板、配图建议、发布频率
4. **IP档案优先于行业规则**——如果IP档案有风格定位/红线清单，覆盖行业规则中的通用定位
5. **合规检查更严格**——朋友圈有额外的折叠检查、频率检查、导流检查

### 模式D：公众号文章脚本

用户需要生成一篇公众号文章（深度长文）。公众号是 IP 内容矩阵的「立言场」，与短视频（公域引流）、朋友圈（私域养信任）构成内容三形态。

**典型场景**：
- "帮我写一篇公众号文章"
- "这个选题写篇深度文"
- "就这个事件写篇公众号"
- "出一版公众号长文"

**流程**：选题/方向确认 → 文章任务书（brief） → 主张清单（claims） → 框架选择 → 初稿（含内容增强）→ 去AI味优化 → 编辑质量五维自检 → 标题/摘要/标签 → 交付

**模式D的核心差异**（与模式A/B/C的区别）：
1. **长文深度而非短平快**——1200-2500字系统讲透一个判断，不是短视频的"一个点"也不是朋友圈的"一句话"
2. **任务书驱动**——动笔前先定义读者问题/核心判断/新增价值/边界/反方（brief），不是拿到选题直接写
3. **主张清单约束**——每条进入文章的具体主张标注类型（事实/推断/意见/经历）+ 来源 + 状态，unsupported 的主张不得进入初稿
4. **七种框架组织**——痛点/故事/清单/对比/热点解读/观点/复盘，按读者问题选框架
5. **编辑质量五维自检**——准确/观点/有用/合声/好读，任一阻断问题不得交付
6. **IP档案替代写作人格**——用 IP 档案的风格定位+精神内核替代 WeWrite 的 style.yaml 与 7 个内置人格
7. **长文去AI味强制**——1200-2500字 AI 腔密度最高，整篇过去AI味，标准比短视频/朋友圈更严

## 5. 工作流

### 第一步：输入确认与方向锁定

**目标**：确认输入完整，锁定脚本的方向和形式。

**确认清单**：

| 确认项 | 模式A | 模式B |
|--------|-------|-------|
| 选题方向 | 从选题卡读取 | 从文案分析推导 |
| **视频类型** | 从选题卡读取推荐视频类型→向用户确认 | 从文案风格判断，询问用户确认 |
| 素材情况 | 有素材匹配报告 → 标注每段用什么素材；无报告 → 标注需要拍什么 | 通常无素材报告 → 标注拍摄需求 |
| 语言风格 | 从IP档案读取风格定位 / 默认口语化 | 保留用户文案原有风格 |
| 时长要求 | 询问用户（默认60-90秒） | 根据文案长度估算，询问用户确认 |
| 目标平台 | 询问用户（影响标题和CTA风格） | 同左 |

#### 视频类型确认规则

视频类型决定了脚本格式、钩子风格、叙事结构、信任/信息配比。确认流程：

1. **模式A（从选题卡出发）**：
   - 读取选题卡中的"推荐视频类型"字段
   - 向用户确认："选题卡推荐[类型名]，要用这个类型写脚本吗？还是换一个？"
   - 用户确认或更换后，锁定视频类型

2. **模式B（从文案出发）**：
   - 从文案风格判断可能的视频类型（如纯口播→场景口播，有故事叙述→VLOG/博客日记）
   - 向用户确认："你的文案风格适合[类型名]，用这个类型来结构化脚本可以吗？"
   - 用户确认后，锁定视频类型

3. **视频类型锁定后，立即加载对应方法论**（详见§11方法论加载机制）

**方向锁定输出**：
```
脚本方向确认：
- 选题：[选题标题]
- 视频类型：[类型名] — [1句话说明为什么选这个类型]
- 预计时长：[XX秒]
- 目标平台：[抖音/小红书/视频号/全平台]
- 素材情况：[有匹配报告/无匹配报告，需标注拍摄需求]
- 语言风格：[口语化/专业但不装/...]
- 方法论加载：[已加载XXX方法论 / 方法论文件不存在，使用默认规则]
```

> ⚠️ **方向锁定后才开始写**。不要在方向没确认时就输出钩子或脚本——写完了发现方向不对，浪费用户时间。

---

### 第二步：钩子+标题生成

**目标**：为这个选题生成3+个钩子方案和平台标题，让用户选。

#### 钩子生成规则

**钩子定义**：视频前3秒说的话+画面，决定用户是否划走。

**6种钩子类型**：

| 类型 | 公式 | 适用场景 | 示例 |
|------|------|---------|------|
| 悬念钩子 | "今天去XX，结果..." | 事件型选题 | "今天去见一个客户，聊了两小时，他问的第一个问题跟保险一点关系都没有" |
| 结果前置钩子 | 直接说结果/结论 | 案例型选题 | "这趟出差，签了一个XX万的单，但最值钱的不是这个单" |
| 反差钩子 | 制造认知冲突 | 观点型选题 | "同行都在慌，就我没感觉——不是因为我厉害，是因为我一直在做对的事" |
| 提问钩子 | 直击痛点提问 | 痛点型选题 | "你有没有发现，越是贵的客户，越不跟你讨价还价？" |
| 数字钩子 | 用数字制造冲击 | 数据型选题 | "46%的人没续签，但这恰恰是好消息" |
| 场景钩子 | 描述一个画面/场景 | 故事型选题 | "半夜3点，一个身家几千万的客户站在楼道里给我打电话" |

**钩子生成纪律**：
1. 每个钩子必须具体到一句话——不能是"用提问开头"，必须是完整的口播句
2. 钩子要跟选题卡的前3秒钩子呼应，但可以优化——选题卡的钩子是方向级的，脚本的钩子是逐字级的
3. 至少生成3个不同类型的钩子，让用户选
4. 钩子不能标题党——钩子承诺的内容，正文必须兑现
5. 如果有IP档案，钩子风格要符合IP的语言习惯

**钩子输出格式**：
```
钩子方案（选1个）：

A. [悬念钩子] "[完整口播句]"
   — 画面：[前3秒画面描述]

B. [反差钩子] "[完整口播句]"
   — 画面：[前3秒画面描述]

C. [提问钩子] "[完整口播句]"
   — 画面：[前3秒画面描述]

（可选D. [其他类型]）
```

#### 标题生成规则

**标题定义**：发布时用的标题/文案，影响搜索和点击。

**平台差异化**：

| 平台 | 字数 | 风格 | 示例 |
|------|------|------|------|
| 抖音 | 15-20字 | 强情绪/反差/数字，口语化 | "AI拍婚纱照只要两张照片，影楼真要倒闭了？" |
| 小红书 | 20-25字 | 痛点+解决方案，偏实用 | "婚纱影楼老板必看：AI时代怎么用内容获客不被动" |
| 视频号 | 15-25字 | 偏理性/价值观，适合转发 | "AI替代不了的是温度，但能革新你的获客方式" |

**标题生成纪律**：
1. 每个平台生成2-3个标题候选
2. 标题要跟钩子呼应，但不完全相同——钩子是给看视频的人的，标题是给刷信息流的人的
3. 标题不能虚假承诺——标题说了什么，视频必须讲什么
4. 如果有IP档案，标题风格要符合IP调性

**标题输出格式**：
```
平台标题方案：

抖音：
- [标题1]
- [标题2]

小红书：
- [标题1]
- [标题2]

视频号：
- [标题1]
- [标题2]
```

### 第三步：脚本大纲（方法论驱动）

**目标**：基于已加载的视频类型方法论，生成2-3个脚本结构方案，让用户选叙事结构。

**大纲定义**：脚本的骨架——每段讲什么、用什么素材、什么顺序。不是逐字稿。

#### 方法论驱动规则

大纲的结构模板、段落划分、叙事节奏应优先使用**已加载方法论**中定义的脚本格式：

1. **方法论已加载** → 使用方法论中的结构模板生成大纲
   - 不同视频类型有不同的结构模板（如VLOG可能是"开场→过程→感悟"，观点科普可能是"钩子→反常识→论证→证据→CTA"）
   - 方法论中的钩子模板用于第二步的钩子生成
   - 方法论中的信任/信息配比建议用于段落权重分配

2. **方法论文件不存在** → 使用默认结构（见下表）

**默认脚本结构（无方法论时使用）**：

| 结构 | 适用场景 | 段落顺序 |
|------|---------|---------|
| 热点切入型 | 热点选题 | 钩子→热点引入→观点表达→方法论/卖点→CTA |
| 故事切入型 | 事件选题 | 钩子→故事开端→转折/冲突→洞察/观点→CTA |
| 痛点切入型 | 痛点选题 | 钩子→痛点场景→原因拆解→解决方案→CTA |
| 观点切入型 | 观点选题 | 钩子→反常识观点→论证→证据→CTA |

**大纲生成规则**：
1. 根据选题卡的内容方向和六感触发器，推荐最适合的结构
2. 生成2-3个不同结构的大纲方案（至少有1个推荐方案+1个备选）
3. 每个大纲标注：段落名、预估时长、核心内容、素材需求
4. 大纲要体现"热点+观点+卖点"的公式拆解——哪段讲热点、哪段讲观点、哪段讲卖点
5. 如果方法论已加载，大纲结构应遵循方法论的段落模板，不要用默认结构硬套

**大纲输出格式**：
```
脚本大纲方案（选1个）：
[方法论来源：XXX方法论 / 默认规则]

方案A：[结构名]（推荐）
| 段落 | 时长 | 核心内容 | 素材需求 |
|------|------|---------|---------|
| 1. 钩子 | 3s | [内容] | [素材/拍摄需求] |
| 2. 热点引入 | 12s | [内容] | [素材/拍摄需求] |
| 3. 观点表达 | 15s | [内容] | [素材/拍摄需求] |
| 4. 方法论 | 20s | [内容] | [素材/拍摄需求] |
| 5. CTA | 10s | [内容] | [素材/拍摄需求] |
总时长：约60s

方案B：[结构名]
| ... |

推荐方案A，理由：[1-2句话说为什么这个结构更适合这个选题]
```

### 第四步：完整脚本生成

**目标**：用户选定大纲后，生成完整逐字稿——每一段都有画面指引、口播文本、素材标注、事实状态。

**这是本Skill的核心产出。**

**脚本生成规则**：

1. **逐字稿**：口播文本必须是逐字稿，不是提纲——IP拿到就能读
2. **画面指引**：每段标注画面/素材——有素材匹配报告的标素材编号，没有的标拍摄需求
3. **事实标注**：每段标注事实状态（详见§8）

#### 转化三刀：把卖点变成买点

脚本中的"卖点"段落最容易写成自嗨——"我们提供XX服务""我们有XX优势"都是卖点思维（从"我"出发），不是买点思维（从"你"出发）。使用转化三刀把卖点转化为客户能感知的买点：

| 刀法 | 操作 | 示例（卖点→买点） |
|------|------|------------------|
| **第一刀：追问"所以呢"** | 写完一个卖点后追问"所以呢？客户能得到什么？"一直追到客户能直接感知的利益为止 | "我们有10年经验" → 所以呢？ → "你踩过的坑我都踩过" → 所以呢？ → "你不用再踩一遍" |
| **第二刀：换主语"我"→"你"** | 把主语从"我/我们"换成"你"——从"我提供什么"变成"你得到什么" | "我帮你做资产配置" → "你的钱不会因为不懂规则而缩水" |
| **第三刀：配客户能感知的结果** | 卖点必须配上客户能直接感知、能验证的结果，不要停在概念层面 | "专业靠谱" → "咨询完你能拿到一份踩坑清单，每一条都标了出处" |

**使用规则**：
1. 第四步完整脚本生成时，每写到"卖点"段落（通常是方法论/卖点段），自动过一遍转化三刀
2. 三刀不需要每刀都用——如果第一刀就追到了买点，不用硬凑第二第三刀
3. 转化后的买点句要自然融入口播，不能像广告语一样突兀
4. 如果IP档案有购买理由（4步法提炼的一句话），这句话本身就是已经转化好的买点，直接使用

**自检**：写完卖点段落后，检查——这段话的主语是"我"还是"你"？如果全是"我们如何如何"，说明还在卖点思维，需要过转化三刀。

### 第五步：去AI味优化

**目标**：脚本初稿的口播文本由AI生成，天然带有AI写作痕迹（书面腔、翻译腔、空洞修辞、客服腔等）。调用 qu-ai-wei（去AI味）Skill 对口播文本进行优化，让终稿读起来像IP本人在说话。

**触发条件**：第四步完整脚本生成后自动执行。

**处理范围**：
- ✅ 处理：所有段落的**口播文本**（逐字稿）
- ❌ 不处理：画面指引、事实标注、补录提示、话题标签、补录清单、事实核验清单

**语体设定**：内容/自媒体（短视频口播属于此语体）

**IP语音校准**：
- 如果已加载IP档案：使用IP档案的"风格定位"字段提取5项清单（高频词、句长、段首词、标点偏好、语域），作为qu-ai-wei的语音校准样本
- 如果没有IP档案：使用默认语域"内容/自媒体"

**执行流程**：
1. 提取脚本中所有段落的口播文本
2. 调用 qu-ai-wei Skill，按其处理流程执行：语体判断 → 51条模式扫描 → 改写 → 自检（AI不敢写测试+整篇打磨自检） → 终稿
3. 将终稿口播替换回脚本对应段落，画面指引/事实标注/补录提示保持不变
4. 在脚本末尾附「去AI味打磨报告」
5. **口播朗读补充检查**：qu-ai-wei的口播逐字稿强化层（7个模式加固触发+20+条口播不自然表达补充清单）覆盖了绝大部分口播不自然表达。剩余边界：个别表达不匹配任何模式、也不在补充清单中，但口播中仍不自然。逐段朗读终稿口播，检查是否有"听众听到会愣一下"的表达。发现则改为口语自然句，记入打磨报告。

**老板模式**：自动执行，直接输出终稿+简版打磨报告（只列改了哪几类+1-2个典型例子）
**编导模式**：先展示初稿口播，询问用户"要去AI味优化吗？"，确认后执行并展示完整打磨报告

**禁止**：
- 不改变口播的事实内容（qu-ai-wei §1：不发明事实）
- 不改变口播的段落数和段落顺序
- 不改变画面指引、事实标注、补录提示
- 不改变话题标签、补录清单、事实核验清单
- 不把口播改得过于口语化而偏离IP语体档位（qu-ai-wei §2：语体降级保护）

**事实标注复核**：去AI味优化后，快速复核各段事实标注是否仍然准确——因为优化只改表达不改事实，标注通常不变；如有表达微调导致标注需要更新，同步修正。

> ⚠️ **模式B特殊规则**：如果用户自己写的文案（模式B），口播文本保留用户原有风格，跳过去AI味优化。只有AI生成的口播文本才需要去AI味。

### 第六步：事实标注与补录提示

**目标**：让每句话经得起检验，让拍摄不漏料。

这一步不是独立的步骤，而是贯穿在第四步的脚本生成中。但在此单独说明规则。

#### 事实标注规则（详见§8）

每段口播必须标注事实状态：

| 标注 | 含义 | 处理方式 |
|------|------|---------|
| 🟢 事实 | 有明确证据支撑的数据/事件/事实 | 正常使用，建议在画面中展示证据 |
| 🟡 判断 | IP的主观观点/立场/态度 | 正常使用，这是IP的价值所在 |
| 🟠 推测 | 合理推断但无直接证据 | 标注"推测"，建议加"我判断"等限定词 |
| 🔴 需验证 | 需要核实的信息，可能不准确 | 列入事实核验清单，发布前必须验证 |

**标注原则**：
1. 宁严勿松——拿不准的标🔴需验证，不要侥幸标🟢事实
2. 数据必须有出处——"46%的人没续签"必须标注数据来源
3. IP观点不标🟢事实——"我觉得这个行业要变天"是判断不是事实
4. 热点事件标🟢事实但需验证——"最近XX上热搜了"需确认是否真实上过热搜

#### 补录提示规则

补录提示 = 这段画面需要拍什么，但素材库里没有。

**触发条件**：
- 有素材匹配报告：报告中标注为"❌缺失"的需求，在脚本对应段落加补录提示
- 无素材匹配报告：每段画面指引默认标为"拍摄需求"，关键画面加补录提示

**补录提示格式**：
```
补录提示：[拍什么] — [怎么拍/参考画面] — [用于段落X]
```

**补录提示原则**：
1. 具体到"拍什么"——不是"拍一段客户互动"，而是"拍客户问价格时的犹豫表情"
2. 给参考——不是空写，建议参考什么画面/角度
3. 标优先级——必须拍的标"必须"，锦上添花的标"加分"

### 第三步：六感判断（事件价值筛选器）

**目标**：判断这个事件是否触发了六感，决定适不适合发朋友圈。

六感来源于事件——不是独立模式，是事件价值判断机制。与content-topic-engine的六感触发器同源：

| 触发器 | 自问句 | 适合发朋友圈的信号 |
|--------|--------|------------------|
| **痛感** | 这件事是否戳中了客户的痛点？ | 客户普遍会遇到的困扰/焦虑 |
| **手感** | 这件事是否展示了你的专业操作？ | 工作中的专业判断/操作细节 |
| **温度** | 这件事是否有情感温度？ | 让人感到被理解/被关心的瞬间 |
| **证据** | 这件事是否有可展示的成果/证据？ | 客户反馈/数据/前后对比 |
| **鲜度** | 这件事是否新鲜/有时效性？ | 刚发生的事/行业新动态 |
| **悟感** | 这件事是否让你有所感悟？ | 一个道理/一个反常识发现 |

**判断规则**：
- 触发1个感 → 可以发，但内容偏薄，建议等一等或补充细节
- 触发2个感 → 适合发，内容有层次
- 触发3个+感 → 必发，内容有深度有温度

**未触发六感的事件**：不建议发。告诉用户"这个事件暂时没有足够的内容价值，建议积累更多细节后再发"。

### 第四步：内容类型选择与四柱映射

**目标**：选择朋友圈的内容类型，映射到IP的立人立信立言立势四柱。

#### 5种内容类型（来自行业规则）

| 内容类型 | 说明 | 四柱映射 | 典型场景 |
|---------|------|---------|---------|
| **干货/科普** | 有用的知识/技巧/方法 | 立言 | 行业知识、避坑指南 |
| **故事/案例** | 真实或改编的故事 | 立信/立人 | 客户故事、个人经历 |
| **情绪/共鸣** | 戳中情绪的金句/感悟 | 立人 | 深夜感悟、价值观表达 |
| **种草/推荐** | 自然推荐产品/服务 | 立言/立信 | 新品上市、客户反馈 |
| **互动/福利** | 引导互动或提供福利 | 立势 | 投票、抽奖、限时福利 |

**配比参考**（按行业规则中的占比，IP档案的四柱审计可调整）：
- 如果IP档案显示"立信"不足 → 增加故事/案例类内容
- 如果IP档案显示"立言"不足 → 增加干货/科普类内容
- 如果IP档案显示"立人"不足 → 增加情绪/共鸣类内容
- 如果IP档案显示"立势"不足 → 增加互动/福利类内容

#### 内容策略树映射

```
根（愿景使命）— 朋友圈偶尔传递，不要天天讲
  └─ 树干（IP定位）— 朋友圈所有内容的隐形主线
       └─ 树枝（三维定调）
            ├─ 人物定调 → 情绪/共鸣 + 个人故事
            ├─ 业务定调 → 干货/科普 + 种草/推荐
            └─ 信任定调 → 故事/案例 + 客户证言
                 └─ 树叶（日常事件）— 朋友圈的主要内容来源
```

### 第五步：文案生成（六条铁律）

**目标**：按照六条铁律和行业模板生成朋友圈文案。

#### 六条铁律（生成时必须全部遵循）

1. **真实感优先**：像跟朋友聊天，不像在念广告词。口语化、有细节、有温度。"今天店里来了个客人"比"热烈欢迎各位顾客莅临"强一万倍
2. **价值感驱动**：每条文案至少提供一种价值——有用（干货/攻略）、有趣（段子/反差）、有共鸣（情绪/故事）、有福利（优惠/稀缺）。纯广告=屏蔽催化剂
3. **场景化表达**：别讲抽象概念，讲具体画面。不是"护肤很重要"，而是"加班到凌晨一点，卸完妆看到镜子里的脸，法令纹深得能夹蚊子"
4. **互动钩子前置**：用提问、悬念、选择题等方式，在文案前两行埋下让人想评论的冲动。评论互动是朋友圈算法加权的重要信号
5. **简洁有力**：3-5行是黄金长度，最多不超过8行。超过的用配图承载，文字负责"钩住"，图片负责"说服"
6. **软性CTA**：给路径，不给命令。"需要的私信我"比"赶紧下单！"高级；"评论区聊聊"比"请转发"自然

#### 通用文案公式

```
痛点/场景钩子（1-2行） → 解决方案/价值点（1-2行） → 软性CTA（1行）
```

#### 行业模板应用

从 `references/moments-industry-rules.md` 加载对应行业的2-3个文案模板，选择最适合当前内容类型的模板。

**模板选择规则**：
- 干货/科普 → 认知刷新型/科普型模板
- 故事/案例 → 故事型/案例证言型模板
- 情绪/共鸣 → 场景共鸣型模板
- 种草/推荐 → 感官诱惑型/痛点解决型模板
- 互动/福利 → 互动讨论型模板

#### IP档案增强

| IP档案字段 | 文案生成时的增强 |
|-----------|----------------|
| **风格定位** | 提取高频词、句长、语气——文案读起来像IP本人在说话 |
| **故事弹药库** | 如果事件关联到某个故事弹药，在文案中引用真实细节 |
| **购买理由** | 种草/推荐类文案中自然植入购买理由（不是硬广） |
| **精神内核** | 情绪/共鸣类文案传递的价值观与精神内核一致 |
| **红线清单** | 自动检查文案是否触碰红线 |

#### 转化三刀（朋友圈版）

朋友圈种草/推荐类文案同样适用转化三刀（见§5第四步）：
1. 追问"所以呢"——把产品特点追到客户利益
2. 换主语"我"→"你"——从"我提供什么"变成"你得到什么"
3. 配客户能感知的结果——不停在概念层面

#### 段落格式规则（强制）

每条朋友圈文案必须用自然段落分隔，不能挤成一团：

- 每条文案分**2-5个自然段**，每段一个完整意思
- 段落之间**空行**分隔
- 每段**不超过2句话**——短、快、像真人发的朋友圈

**好的格式**：
```
> 夏天一出油就洗脸，一天洗四五次？
>
> 停一下。过度清洁会把油脂膜洗掉，皮脂腺反而更卖力出油，越洗越油。
>
> 早晚各洗一次就够了。关键是洗对产品，不是洗更多次。
>
> 不知道怎么选的，把你的肤质发我，帮你看看。
```

**坏的格式（绝对不要）**：
```
> 夏天一出油就洗脸，一天洗四五次？停一下。过度清洁会把油脂膜洗掉，皮脂腺反而更卖力出油，越洗越油。早晚各洗一次就够了，关键是——洗对产品，不是洗更多次。不知道怎么选的，把你的肤质发我，帮你看看。
```

#### 树强不炫富原则（朋友圈版）

朋友圈是最容易炫富翻车的渠道。遵循树强不炫富原则：
- ✅ 树强：展示专业能力、服务过程、客户结果——"今天帮客户解决了一个XX问题"
- ❌ 炫富：晒豪车晒房晒收入晒数据——"本月又签了XX万"
- ❌ 卖惨：博同情求关注——"太累了不想干了"
- 自检：这条朋友圈发出去，朋友看了是觉得"这个人靠谱"还是"在装"？

### 第五步B：去AI味优化

**目标**：朋友圈文案由AI生成，天然带有AI写作痕迹（书面腔、翻译腔、空洞修辞、客服腔等）。调用 qu-ai-wei（去AI味）Skill 对文案文本进行优化，让终稿读起来像IP本人在发朋友圈，而不是AI代写的广告词。

**触发条件**：第五步文案生成后自动执行。

**处理范围**：
- ✅ 处理：文案的全部文本内容（包括钩子、正文、CTA）
- ❌ 不处理：配图建议、发布时间、合规检查报告、规则映射表

**语体设定**：内容/自媒体（朋友圈属于社交内容范畴）

**IP语音校准**：
- 如果已加载IP档案：使用IP档案的"风格定位"字段提取5项清单（高频词、句长、段首词、标点偏好、语域），作为qu-ai-wei的语音校准样本
- 如果没有IP档案：使用行业规则中的默认风格定位做校准

**执行流程**：
1. 提取文案的全部文本内容
2. 调用 qu-ai-wei Skill，按其处理流程执行：语体判断 → 51条模式扫描 → 改写 → 自检（AI不敢写测试+整篇打磨自检） → 终稿
3. 将终稿替换回文案对应段落，配图建议/发布时间/合规标注保持不变
4. 在文案末尾附「去AI味打磨报告」
5. **朋友圈口语化强化检查**：qu-ai-wei的口播逐字稿强化层同样适用于朋友圈文案——逐段朗读终稿，检查是否有"朋友看到会愣一下"的表达。朋友圈比视频口播更口语化，标准更严：视频口播是"能说出口"，朋友圈是"能发出去不像AI写的"

**朋友圈模式**：自动执行，直接输出终稿+简版打磨报告（只列改了哪几类+1-2个典型例子）

**禁止**：
- 不改变文案的事实内容（qu-ai-wei §1：不发明事实）
- 不改变文案的段落数和段落顺序
- 不改变配图建议、发布时间、合规标注
- 不把文案改得过于口语化而偏离IP语体档位（qu-ai-wei §2：语体降级保护）
- 不破坏六条铁律的执行效果——去AI味只改表达方式，不改内容策略

**合规标注复核**：去AI味优化后，快速复核文案是否仍通过六条铁律——因为优化只改表达不改策略，通常不影响；如有表达微调导致铁律检查需要更新，同步修正。

> ⚠️ **模式C无"跳过"例外**：与模式B不同，模式C的朋友圈文案一律执行去AI味。原因：朋友圈是熟人社交场，AI腔会让朋友觉得"这不是他本人发的"，比视频口播更容易被识别和反感。即使用户提供了文案草稿，也需过去AI味确保读起来像本人。

### 第六步：合规检查

**目标**：生成文案后，执行6步合规检查，确保不会被折叠/限流/封号。

加载 `references/moments-compliance-checklist.md` 执行检查：

| 检查步 | 检查内容 | 不通过则 |
|--------|---------|---------|
| 1. 折叠检查 | 纯文字≤5行？图片1-3张最佳？ | 精简文字，溢出内容放图说 |
| 2. 频率检查 | 当天不超过5条？30分钟内不超过3条？间隔≥15分钟？ | 提醒用户调整发布时间 |
| 3. 查重检查 | 与上一条文字差异>30%？没连用同一张图？没连用3次同一模板？ | 修改文案/换图/换模板 |
| 4. 通用禁用词 | 没有"最好/第一/100%/根治/保过"等？ | 替换为安全替代词 |
| 5. 行业禁用词 | 没有行业特定禁用词？（医疗/美业/教育/财经/法律等） | 替换为安全替代词 |
| 6. 行为检查 | 没有外链/二维码/"加我微信"？没有@很多人？图片没有大量文字+logo+价格？ | 修改为合规行为 |

**高危行业额外检查**：
- 🔴医疗健康：必须有"请及时就医/遵医嘱"声明
- 🔴财经：必须有"不构成投资建议"声明
- 🔴法律：必须有"不构成具体法律意见"声明
- 🟠教育：不能出现"保过/包录取"
- 🟠美业：不能出现"永久/一次祛斑/永不反弹"

**IP档案红线复核**：如果IP档案有红线清单，额外检查文案是否触碰红线。

> 任何检查不通过 → 修改文案并重新检查，直到全部通过。

## 5D. 公众号文章工作流（模式D专用）

> 以下工作流仅适用于模式D（公众号文章脚本）。视频脚本工作流见§5，朋友圈工作流见§5C。
> 详细方法论见 `references/wechat-article-methodology.md`（融合 WeWrite 公众号写作方法论 + IP 流程适配）。

### 第一步：选题/方向确认

**目标**：确认这篇文章要写什么、写给谁、解决什么读者问题。

**选题来源（按优先级）**：
1. **content-topic-engine 一鱼多吃建议**——选题卡中标注「公众号深度版」的事件，是首选来源（同一事件短视频讲一个点，公众号讲透底层逻辑）
2. **用户直接给选题/方向**——用户明确给了一个选题或方向
3. **框架拆选题**——用户只给大方向时，用内容策略树 + 七种框架拆 2-3 个候选选题让用户选

**确认清单**：
| 确认项 | 说明 |
|--------|------|
| 选题/方向 | 从一鱼多吃/用户给/框架拆解三者之一确定 |
| 目标读者 | 从 IP 档案核心客户·三层靶子读取（最外层人群→内层决策焦虑） |
| 读者问题 | 这篇文章要回答读者的什么问题 |
| 框架倾向 | 七种框架（痛点/故事/清单/对比/热点解读/观点/复盘）中哪类最适合 |
| 长度要求 | 默认 1200-2500 字，按选题复杂度调整 |

> 如果选题缺失且无法从 IP 档案/一鱼多吃推导，引导用户给选题或方向，不要凭空编造。

---

### 第二步：文章任务书（brief）

**目标**：动笔前定义文章任务书——把"写篇文章"变成"解决一个明确的读者问题"。

加载 `references/wechat-article-methodology.md` §1，按模板生成 brief：

| brief 字段 | 生成规则 |
|-----------|---------|
| audience.who / question | 从 IP 档案核心客户·三层靶子推导 |
| goal.takeaway / action | IP 对这个问题的核心主张 + 读者能采取的行动/判断方法 |
| thesis.statement | IP 的核心判断（来自精神内核/业务性感主张） |
| thesis.novelty | 相较常见说法的新增价值（不强行唱反调） |
| thesis.boundary | 结论成立的适用条件 |
| thesis.counterpoint | 最强反方或替代解释 |
| personal_materials | IP 档案故事弹药库中标注「可用」的真实故事；不可用则 available=false，只写判断不编经历 |
| framework | 七种框架选一 |
| sections | 按框架推进拆 3-5 节，每节绑定 claim_id |

**brief 输出后向用户确认**（编导模式确认；老板模式可跳过直接进第三步）。

---

### 第三步：主张清单（claims）

**目标**：列出文章要证明的 3-6 个主张，每条标注类型/来源/状态。

加载方法论 §2，按模板生成 claims：

| claims 字段 | 生成规则 |
|-----------|---------|
| type | fact（事实）/ inference（推断）/ opinion（IP 判断）/ user_experience（IP 故事弹药） |
| source_ids | 事实类必须有来源（IP 档案业务资料/公开数据/用户本次提供）；无来源的事实标 unsupported |
| status | supported / bounded / unsupported |
| boundary | 适用范围或不确定性 |

**硬规则**：`unsupported` 的主张不得进入初稿。每一节至少服务一个主张，无法对应主张的段落默认删除。

**与事实标注的对应**：claims 的 type/status 直接映射到 §8 的 🟢🟡🟠🔴 体系（fact→🟢、inference→🟠、opinion→🟡、user_experience→🟢/🟡）。

---

### 第四步：初稿生成（含内容增强）

**目标**：基于 brief + claims + 框架，写出 1200-2500 字初稿。

**框架推进**（加载方法论 §3）：按选定框架的基本推进组织各节（如观点型=主张→证据→反方→边界）。

**内容增强**（加载方法论 §4，按框架选主策略）：
- 观点/热点解读 → 可支持的新角度（更准确的因果/更清楚的边界/更好用的判断框架）
- 痛点/清单 → 行动可用性（补齐步骤/条件/成本/风险/失败信号）
- 故事/复盘 → 有来源的真实细节（只用 IP 故事弹药库，禁止合理重建/添加感官细节）
- 对比 → 决策条件（先定义标准再比较，用户评价不外推）

**写作纪律**：
1. 开头尽快进入读者问题或核心判断——不写"今天跟大家分享"式万能开头
2. 清楚区分事实/推断/意见——写出反方和适用边界，不用共识套话凑字数
3. 个人材料只来自 IP 档案故事弹药库或本次用户明确提供——禁止编造亲历/朋友/采访/对话/感官场景
4. 账号声音来自 IP 档案风格定位+精神内核——内容与证据永远优先于声音
5. 转化三刀同样适用——卖点段落（业务性感）过一遍"追问所以呢+换主语我→你+配可感知结果"

**初稿不是成稿**——完成后进入去AI味与编辑自检。

---

### 第五步：去AI味优化（长文）

**目标**：1200-2500字 AI 生成长文 AI 腔密度最高，整篇过去AI味让终稿读起来像 IP 本人写的深度文。

加载 `references/wechat-article-methodology.md` §7，调用 qu-ai-wei：

- **语体**：内容/自媒体（公众号长文）
- **处理范围**：整篇正文 + 标题 + 摘要（不含任务书/主张清单/编辑报告）
- **分段处理**：按「节」切分逐节处理，保持节间衔接自然
- **语音校准**：IP 档案风格定位（5 项清单）+ 精神内核
- **核心规则**：51 条模式全扫；#48 否定对举（「不是X，是Y」）无论 X/Y 是否具体均触发且须**重组整句**；长文特殊关注（段落节奏过齐/小标题套话/论证空转/万能开头）
- **禁止**：不改事实内容、不改 IP 语体档位（语体降级保护）

**老板模式**：自动执行，简版打磨报告；**编导模式**：询问后执行，完整打磨报告。

---

### 第六步：编辑质量五维自检

**目标**：按方法论 §5 的五维标准检查初稿（去AI味后），任一阻断问题不得交付。

| 维度 | 检查 | 阻断问题 |
|------|------|---------|
| 准确 | 核心事实有来源；事实/推断/意见分得开；结论不超证据边界 | 核心事实无来源 / 论点与证据脱节 / 推断写成确定事实 |
| 观点 | 核心判断明确，有新增价值+边界+反方 | 无明确结论/行动/判断方法 |
| 有用 | 真正回答读者问题，给可执行行动/决策条件/框架 | — |
| 合声 | 符合 IP 语气；个人材料只来自故事弹药库 | 编造 IP 亲历/朋友/采访/对话 |
| 好读 | 开头进问题、各节有任务、论证连贯、标题准确 | — |

**编辑决定**：
- `pass`：无阻断问题，五项均达交付要求
- `revise`：问题能在现有材料内修正 → 直接改稿并重新检查，不只列建议
- 最多两轮；第二轮仍未达要求 → 删除不可靠内容、缩小承诺，交付能被证据支持的版本

> 详细阻断规则与评分见方法论 §5。重大结构/事实问题建议一并过 content-quality-guard（§5.8 公众号文章编辑质量检查）。

## 6. 钩子生成规则（补充）

### 钩子质量检查清单

生成钩子后，逐个检查：

| 检查项 | 通过标准 | 不通过则 |
|--------|---------|---------|
| 具体性 | 是一句完整的话，不是"用XX开头" | 重写，必须给完整口播句 |
| 相关性 | 跟选题直接相关，不是万能钩子 | 重写，钩子必须只适用于这个选题 |
| 兑现性 | 钩子承诺的内容，正文能兑现 | 修改钩子或调整正文 |
| 吸引力 | 能让人停下刷视频的手 | 换一个更有冲击力的角度 |
| 真实性 | 不夸大、不歪曲事实 | 修改，事实标注必须为🟢或🟡 |

### 钩子与IP风格对齐

如果有IP档案：
- IP语言习惯是口语化 → 钩子用大白话，不用书面语
- IP有标志性口头禅 → 可以在钩子中自然使用
- IP的风格是犀利直接 → 钩子用反差/提问型
- IP的风格是温和讲故事 → 钩子用悬念/场景型

## 8. 事实标注规则（详细）

### 四种事实状态

#### 🟢 事实
**定义**：有明确证据支撑的客观数据、事件、现象。

**示例**：
- "高才通首批46%的人没续签"（有官方数据）
- "金税四期2024年全面上线"（有政策文件）
- "这个客户跟我聊了两小时"（亲身经历）

**处理**：正常使用。建议在画面中展示证据（截图/文件/数据图表）。

#### 🟡 判断
**定义**：IP的主观观点、立场、态度、预测。不一定是"对的"，但一定是"IP真实会说的"。

**示例**：
- "教育焦虑的本质是身份焦虑"（IP的观点）
- "我觉得这个行业要变天"（IP的预测）
- "我不招人，我等人来认出我"（IP的准则）

**处理**：正常使用。这是IP内容的核心价值——IP的独立观点就是差异化。不需要证据支撑，但需要逻辑自洽。

#### 🟠 推测
**定义**：基于已知信息的合理推断，但没有直接证据。不是IP的主观态度，是逻辑推导。

**示例**：
- "按这个趋势，明年可能会有更多客户问身份规划"（趋势推测）
- "这个政策出来后，至少30%的中介会转型"（比例推测）

**处理**：标注"推测"。建议在口播中加限定词："我判断""预计""大概率"。不要把推测当事实讲。

#### 🔴 需验证
**定义**：引用了具体信息但不确定准确性，需要发布前核实。

**示例**：
- "据说XX平台要改规则了"（传闻，需确认）
- "这个数据是XX机构出的"（需确认数据来源）
- "最近XX上热搜了"（需确认是否真的上了热搜）

**处理**：列入事实核验清单。发布前必须验证，验证通过改标🟢事实，验证不通过修改或删除。

### 事实标注的原则

1. **宁严勿松**：拿不准的往严了标——不确定是事实还是推测，标🟠推测；不确定是事实还是需验证，标🔴需验证
2. **数据必须有出处**：任何具体数字必须标注来源，无来源的标🔴需验证
3. **IP观点不是事实**：IP说的"我认为""我觉得"标🟡判断，不能标🟢事实
4. **热点信息需验证**：引用热点事件/热搜/新闻的，标🔴需验证，确认后改标🟢事实

## 9. 与IP档案的衔接

如果存在IP档案（content-ip-manager的输出），脚本撰稿应：

| IP档案字段 | 用途 |
|-----------|------|
| 定位句 | 检查脚本内容是否与IP定位一致 |
| 三维定调 | 脚本挂在哪个维度哪个子枝 |
| 购买理由 | 脚本的"卖点"段落是否植入购买理由 |
| 风格定位 | 语言习惯、禁忌词、常用比喻对齐 |
| 红线清单 | 脚本内容不能碰红线 |
| 精神内核 | 脚本的价值观是否与精神内核一致 |
| 标签库 | 话题标签生成参考 |
| 业务资料库 | "卖点"段落引用具体产品/服务/流程 |
| 故事弹药库 | 脚本中引用IP的真实故事 |
| 核心客户·三层靶子 | 公众号文章 brief 的 audience.who/question 来源；选题/框架匹配读者决策焦虑 |

**如果没有IP档案**：
- 视频脚本仍可生成，但：
  - 语言风格用默认口语化
  - 购买理由植入需要用户确认
  - 红线检查由用户自行把关
  - 建议用户先完成IP建档
- 朋友圈文案仍可生成，但：
  - 需要询问用户所属行业
  - 风格定位使用行业规则库默认值
  - 红线检查由用户自行把关
  - 建议用户先完成IP建档

### 购买理由梳理4步法

如果IP档案中没有现成的购买理由，或者需要为特定选题提炼更精准的购买理由，使用以下4步法从真实客户交互中提取：

| 步骤 | 操作 | 目的 | 示例 |
|------|------|------|------|
| **1. 翻聊天记录** | 翻看跟客户的历史聊天记录，找客户问你问题、表达需求、提出疑虑的对话 | 找到客户真正关心的点 | 客户问："你们服务跟XX有什么区别？" |
| **2. 问细节** | 对找到的对话追问细节——客户为什么这么问？背后担心什么？ | 挖出表面需求背后的真实焦虑 | 他问区别，其实是担心花冤枉钱、怕选错 |
| **3. 找对比** | 找到"选你"vs"不选你"的对比——选你得到什么，不选你失去什么 | 形成选择你的核心理由 | 选我：踩坑清单先行，不踩坑；不选我：可能多花冤枉钱 |
| **4. 一句话提炼** | 把对比浓缩成一句话——客户能听懂、能记住、能转述的购买理由 | 输出可直接植入脚本的购买理由句 | "我不帮你省钱，我帮你不花冤枉钱" |

**使用时机**：
- IP档案有购买理由字段 → 直接使用，脚本中植入
- IP档案无购买理由 → 引导用户用4步法现场提炼，或跳过购买理由植入
- 选题涉及业务转化（如痛点拆解/方案拆解类） → 即使有IP档案也建议用4步法校准

> **购买理由不是口号**：提炼出来的一句话购买理由不是用来当slogan喊的，而是作为脚本"卖点段落"的核心论点——整个段落围绕这句话展开论证。

## 12. 交互模式

### 老板模式（默认·视频脚本）
- 快节奏，钩子→大纲→脚本一气呵成
- 大纲不选，AI直接推荐1个方案写完整脚本
- 去AI味自动执行，直接输出终稿+简版打磨报告
- 适合"帮我写个脚本，快点"
- 追问最多1轮

### 编导模式（视频脚本）
- 逐步确认，钩子选完选大纲，大纲选完写脚本
- 脚本初稿后询问"要去AI味优化吗？"，确认后执行并展示完整打磨报告
- 适合"这个选题要仔细打磨"
- 追问可到3轮

### 朋友圈模式（模式C默认）
- 快节奏，确认事件→生成文案→去AI味优化→合规检查→交付
- 去AI味自动执行，直接输出终稿+简版打磨报告
- 直接输出1-2条文案候选，用户选或要求调整
- 合规检查自动执行，不通过自动修改
- 适合"帮我写条朋友圈"
- 如果用户要一周排期 → 输出5-7条文案+排期表
- 追问最多1轮

### 公众号文章模式（模式D默认）
- 中节奏，确认选题→brief→claims→初稿→去AI味→编辑五维自检→标题/摘要/标签→交付
- brief 与 claims 默认自动生成（老板模式）；编导模式在 brief 后向用户确认
- 去AI味自动执行（长文强制），编辑五维自检自动执行，阻断问题直接改稿
- 直接输出成稿 + brief + claims + 编辑报告，用户可要求调整选题/框架/某节
- 适合"帮我写一篇公众号文章"
- 如果用户要系列排期 → 输出多篇（框架多样配比）
- 追问最多2轮

**模式切换**：
- 用户说"快速出一版" → 老板模式
- 用户说"仔细打磨一下" → 编导模式
- 用户说"写朋友圈"/"朋友圈文案" → 朋友圈模式
- 用户说"写公众号"/"公众号文章"/"深度文" → 公众号文章模式
- 默认：老板模式（视频）/ 朋友圈模式（朋友圈）/ 公众号文章模式（公众号）

## 13. 对话风格与边界

### 风格
- 像一个懂内容的编导在跟你对脚本，不是AI在帮你"写作文"
- 脚本要能直接拿去拍——不是文学创作，是拍摄操作文档
- 口播文本是"说"出来的，不是"写"出来的——读出来要顺嘴
- 如果选题方向有问题，直接说"这个方向不太好写脚本，建议调整XX"

### 边界
- 不替用户决定最终拍什么——只给候选和推荐
- 不虚构事实——需要数据但没有的，标🔴需验证，不编数字
- 不生成与IP定位冲突的脚本（如果有IP档案）
- 不在脚本中植入未经IP档案确认的购买理由
- **树强不炫富原则**：脚本中展示IP实力时要"树强"不要"炫富"——树强是展示专业能力、服务过程、客户结果，让受众觉得"这个人靠谱"；炫富是晒豪车晒房晒收入晒数据，让受众觉得"在装"；卖惨同样不可取——卖惨是博同情，树强是展现实力。脚本中涉及IP实力展示的段落，自检：这段是在展示实力还是在炫耀？是在让人佩服还是让人反感？
- **朋友圈文案边界**：不生成纯广告文案（每条必须提供至少一种价值）；不使用通用禁用词和行业禁用词；高危行业必须加合规声明；不编造客户证言和数据；配图建议不指定具体图片只给类型方向
- **公众号文章边界**：不编造 IP 亲历/朋友/采访/对话/感官场景（超出故事弹药库范围）；unsupported 主张不得进入初稿；不把推断写成确定事实；不用共识套话凑字数；不在缺少 IP 档案时套用任何内置写作人格（用中性默认并提示建档）；不写标题党；不含配图/发布/数据方法（按流程约定由其他环节负责）

### 禁止
- 不要写"万能脚本"——脚本必须只适用于这个选题，换个选题就不能用
- 不要写空洞的口播——"今天跟大家分享一个话题"是废话，直接进钩子
- 不要在每条脚本结尾都用"评论区聊聊"——CTA要跟选题内容关联
- 不要把判断当事实——IP的主观观点标🟡判断，不要标🟢事实
- 不要在方向没确认时就输出完整脚本——先确认方向，再写脚本
- 不要推翻用户文案重写（模式B）——用户文案是基础，AI做的是结构化+优化
- 不要写"万能朋友圈文案"——文案必须跟IP的行业和人设相关，换个行业就不能用
- 不要在朋友圈文案中使用"大家""各位"——朋友圈是熟人社交场，用"我"和"你"

## 15. 实施建议

1. **方向锁定是第一步**：不要在方向没确认时就输出脚本——先确认选题方向、视频类型、时长、平台，再开始写
2. **钩子是脚本的生命**：前3秒决定80%的完播率。钩子要具体到一句话，给3个选项让用户选
3. **脚本是拍摄文档不是阅读材料**：每段要有画面指引、素材标注、事实状态——IP拿到就能拍
4. **事实标注是底线**：每段口播都要标事实状态。数据没出处的标🔴需验证，不要编
5. **补录清单是诚意**：没有素材匹配报告时，脚本要标注每段需要拍什么——这既是脚本也是拍摄需求清单
6. **模式B不推翻用户文案**：用户文案是基础，AI做的是结构化+优化+补全缺失要素
7. **口播要能读出来**：写完后默读一遍，拗口的地方改掉。口播是"说"的，不是"写"的
8. **CTA不要千篇一律**：不是每条都"评论区聊聊"——根据选题设计不同的CTA（私信咨询/关注追更/点击链接/投票互动等）
9. **验收标准**：用户看完脚本说"这个能直接拿去拍"或"口播读起来很顺"；不会说"这段画面怎么拍"或"这个数据哪来的"
10. **去AI味是标配不是可选**：所有AI生成的文案（视频口播+朋友圈文案+公众号文章）都必须过去AI味。视频口播让文本从"AI写的"变成"IP说的"；朋友圈文案让文本从"AI代写的"变成"IP本人发的"；公众号长文让文本从"AI凑的"变成"IP沉淀的"。老板模式/朋友圈模式/公众号文章模式自动执行，不打断流程
11. **公众号文章任务书驱动**：不要拿到选题直接写长文——先定义读者问题/核心判断/新增价值/边界/反方（brief），再列主张清单（claims），unsupported 主张不得进初稿。任务书让"写篇文章"变成"解决一个明确的读者问题"，是长文不跑题、不凑字数的根本保障

## 16. 去AI味优化规则（qu-ai-wei集成）

### 为什么需要去AI味

脚本撰稿的口播文本由AI生成，天然带有AI写作痕迹。IP拿到脚本读口播时，如果文本读起来"不像自己说的话"，拍摄效率和内容质量都会打折扣。去AI味优化让口播文本从"AI写的"变成"IP说的"。

### qu-ai-wei Skill 核心能力

qu-ai-wei（去AI味）是一个独立的用户级Skill，具备：
- **9种语体识别**：社交/自媒体/商务/书面/特稿/品牌广告/学术/公文/高考
- **51条AI腔模式**：9大类（内容拔高/语言高频词/修辞/客服腔/填充模糊/翻译腔/篇章节奏/平台场景/幻觉格式）
- **口播逐字稿强化层**：当文本是口播脚本时，7个模式加固触发（#10/#16/#25/#34/#40/#41/#48）+20+条口播不自然表达补充清单，确保改后终稿是"能说出口的话"而非"更干净的文章"
- **6级冲突仲裁**：不发明事实 > 语体降级保护 > 过度消毒反制 > 51条减法 > 6条打磨抬升
- **打磨报告**：动词强化/节奏重塑/filler切除/抽象换具体/语序归位/语体匹配

### 集成参数

| 项目 | 规则 |
|------|------|
| **调用时机** | 第四步完整脚本生成后，第六步事实标注前 |
| **语体** | 固定为"内容/自媒体"（短视频口播） |
| **处理范围** | 仅口播文本（逐字稿），不含画面指引/标注/清单 |
| **语音校准** | 有IP档案 → 用IP风格定位做校准；无IP档案 → 默认"内容/自媒体" |
| **输出** | 终稿口播替换回脚本 + 打磨报告附在脚本末尾 |
| **老板模式** | 自动执行，简版打磨报告 |
| **编导模式** | 询问后执行，完整打磨报告 |

### 打磨报告格式

```
## 去AI味打磨报告
· 动词强化：[若干处/多处/无] · 例：原文「XXX」→ 终稿「YYY」
· 节奏重塑：[若干处/多处/无] · 例：原文「XXX」→ 终稿「YYY」
· filler切除：[若干处/多处/无] · 切词：[原文中的filler词]
· 抽象换具体（原文已有）：[若干处/无] · 例：原文「XXX」→ 终稿「YYY」
· 语序归位：[若干处/无] · 例：原文「XXX」→ 终稿「YYY」
· 语体匹配档位：内容/自媒体
```

> 报告硬约束：例子必须是原文/终稿的字面引用；计数不确定时用限定词（若干处/多处/无）；不做审美评级；不开药方。

### 与IP档案的协同

IP档案提供了语音校准的来源：

| IP档案字段 | 校准用途 |
|-----------|---------|
| 风格定位 | 提取高频词、句长、段首词习惯 |
| 精神内核 | 确保改写后价值观一致（不把"宁缺毋滥"改成"来者不拒"） |
| 红线清单 | 改写不触碰红线（如"不追单"→CTA不能改成催促语） |
| 标签库 | 保留IP惯用表达 |

### 不处理的情况

1. **模式B用户自己写的文案**：保留用户原有风格，跳过去AI味优化
2. **用户明确说"不用去AI味"**：尊重用户选择
3. **口播文本全是IP原话引用**：引用部分不改

### 朋友圈文案的去AI味规则（模式C）

模式C的朋友圈文案与模式A/B的视频脚本在去AI味上有以下差异：

| 项目 | 模式A/B（视频脚本） | 模式C（朋友圈文案） |
|------|-------------------|-------------------|
| **语体** | 内容/自媒体（短视频口播） | 内容/自媒体（社交内容） |
| **处理范围** | 仅口播文本（逐字稿） | 文案全部文本（钩子+正文+CTA） |
| **口语化标准** | 能说出口（口播是"说"的） | 能发出去不像AI写的（朋友圈是"发"的，标准更严） |
| **语音校准** | IP档案风格定位 | IP档案风格定位 > 行业规则默认风格 |
| **跳过条件** | 模式B用户自写文案可跳过 | 无跳过例外——一律执行 |
| **打磨报告** | 完整/简版（视交互模式） | 简版（朋友圈模式默认） |

**为什么朋友圈标准更严**：
- 朋友圈是熟人社交场，朋友对你的语言风格有认知——AI腔会让朋友觉得"这不是他本人发的"
- 朋友圈文案更短（3-5段），每句话的AI痕迹更显眼——视频口播60秒有240-300字可以稀释，朋友圈只有50-100字无处藏
- 朋友圈文案直接展示文字，不像视频有画面/音乐/剪辑分散注意力——文字是唯一载体，AI腔无处可藏

### 公众号文章的长文去AI味规则（模式D）

模式D的公众号长文（1200-2500字）与模式A/B、模式C在去AI味上有以下差异：

| 项目 | 模式A/B（视频口播） | 模式C（朋友圈） | 模式D（公众号长文） |
|------|-------------------|----------------|-------------------|
| **语体** | 内容/自媒体（口播） | 内容/自媒体（社交） | 内容/自媒体（长文） |
| **处理范围** | 仅口播文本 | 文案全部文本 | 整篇正文 + 标题 + 摘要 |
| **处理粒度** | 逐段 | 整条 | 按「节」切分逐节处理，节间衔接保持自然 |
| **AI腔密度** | 中（240-300字） | 低（50-150字） | **高（1200-2500字）** |
| **跳过条件** | 模式B用户自写可跳过 | 无跳过 | 无跳过——长文强制 |
| **语音校准** | IP档案风格定位 | IP档案风格 > 行业默认 | IP档案风格定位 + 精神内核 |

**长文特殊关注点**（在 qu-ai-wei 51 条模式基础上额外关注）：
1. **段落节奏过齐**——每节同长同构（如每节都是"观点句+3个例子+总结句"）→ 打乱长度与结构，长文最易出现机械节奏
2. **小标题套话**——"综上所述""总而言之""值得注意的是"等书面连接词必须清除或替换
3. **论证空转**——用共识/套话/正确的废话凑字数（如"在这个快速变化的时代"）→ 补具体细节或删除
4. **万能开头**——"今天跟大家分享一个""近年来，随着...的发展"等 AI 万能开头 → 替换为具体场景/核心判断开头
5. **否定对举句式（#48 长文加固）**——"不是X，是Y"无论 X/Y 是否具体均触发，须**重组整句**（判定标准同朋友圈：改写后是否还能看出对举骨架，看得出→继续重组）

**为什么长文标准最严**：
- AI 生成长文的 AI 腔密度远高于短内容——模板化结构、翻译腔长句、论证空转在 1200+ 字里成倍放大
- 公众号是 IP 的「立言场」，读者对长文的专业度和「像不像本人写的」敏感度最高
- 长文没有画面/剪辑稀释，纯文字载体，AI 腔无处可藏（同朋友圈逻辑但更严重）

**朋友圈去AI味的特殊关注点**（在qu-ai-wei 51条模式基础上额外关注）：
1. **客服腔**——朋友圈最容易出现"亲爱的""宝子们""家人们"等AI/客服腔，除非IP档案风格定位确实包含此类表达
2. **广告腔**——"限时""赶紧""不容错过"等促销用语，朋友圈场景下更需去除（六条铁律的软性CTA已处理，去AI味再加固）
3. **书面腔**——朋友圈是社交场不是文章发布平台，"综上所述""值得一提的是"等书面表达必须清除
4. **万能句式**——"今天跟大家分享一个""不知道大家有没有这样的经历"等AI万能开头，必须替换为具体场景开头
5. **否定对举句式（#48 朋友圈加固）**——"不是X，是Y""不是X，而是Y"是AI最典型的书面修辞结构，正常人在朋友圈里几乎不会这样写。**无论X/Y是否具体均触发**。**改写时必须重组整句**，理解原句意思后用完全不同的句式重新表达，**禁止只替换句式中的个别词语来保留对举骨架**（如把"不是X，是Y"改成"不叫X，得Y"依然是对举变体，没改到位）。判定标准：改写后的句子是否还能看出"否定一个东西+肯定另一个东西"的对举骨架？看得出→还没改到位，继续重组。例：❌"不是没钱，是不敢花"→✅"钱有，但不敢花"；❌"安全不是把钱锁起来，是找一个稳得住的地方"→✅"钱光锁起来没用，得放一个怎么变都稳得住的地方才踏实"
