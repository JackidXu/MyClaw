# content-script-writer — 脚本撰稿

> 选题卡进来，写钩子、出标题、生成可拍摄的完整脚本。事实标注让每句话经得起检验，补录提示让拍摄不漏料。

---

## 1. 触发词

- `写脚本`
- `出口播稿`
- `写旁白`
- `出逐字稿`
- `出钩子`
- `出标题`
- `帮我把这个文案整理成脚本`
- `优化一下这个文案`
- `这个选题写个脚本`

---

## 2. 核心定位

**不是"帮你写一篇作文"，而是"帮你把选题卡变成一份能直接拿去拍的脚本"。**

脚本是拍摄现场的操作文档，不是阅读材料。本Skill的工作是：
1. 读懂选题卡（或用户文案），锁定讲什么、怎么讲
2. 生成3+个钩子和平台标题，让前3秒抓住人
3. 生成2-3个脚本大纲，让用户选结构
4. 选定大纲后，写出完整逐字稿——每一段标画面、标素材、标事实状态
5. 标注哪些是事实、哪些是判断、哪些需要验证——让IP对自己说的话负责
6. 列出补录清单——拍摄时别忘了拍什么

---

## 3. 输入

### 必需（二选一）

| 输入类型 | 说明 | 工作模式 |
|---------|------|---------|
| **选题卡** | 来自 content-topic-engine，包含选题标题、三维映射、六感、公式拆解、内容方向、推荐视频类型 | 模式A：从选题卡出发 |
| **用户文案** | 用户自己写的文案/口播稿/AI初稿，需要结构化为可拍摄脚本 | 模式B：从文案出发 |

### 可选（增强输出质量）

| 输入 | 来源 | 用途 |
|------|------|------|
| **素材匹配报告** | content-material-matcher | 告诉脚本每段用什么素材，哪些段缺素材需要补录 |
| **IP档案** | content-ip-manager | 语言风格对齐、购买理由植入、红线检查 |
| **视频类型偏好** | 用户指定 | 如果用户已有明确的视频类型偏好，优先使用 |

> **如果没有素材匹配报告**：脚本仍可生成，但每段的画面/素材指引改为"拍摄需求"——标注需要拍什么，而不是用哪个已有素材。相当于同时输出脚本+拍摄需求清单。

## 4. 两种工作模式

### 模式A：从选题卡出发（标准流程）

用户拿着选题卡（可能还有素材匹配报告）进来，AI从零生成脚本。

**典型场景**：
- "选题卡选好了，帮我写个脚本"
- "方向B确认了，出口播稿"

**流程**：选题卡 → 视频类型确认+方法论加载 → 钩子标题 → 大纲 → 完整脚本（初稿）→ 去AI味优化 → 事实标注 → 补录清单

### 模式B：从文案出发（优化/结构化）

用户已有文案（自己写的或AI初稿），需要AI把它整理成可拍摄的结构化脚本。

**典型场景**：
- "帮我把这个文案整理成脚本"
- "优化一下这个口播稿"
- "这个文案帮我改成拍摄脚本"

**流程**：用户文案 → 视频类型确认+方法论加载 → 分析结构 → 钩子标题优化 → 结构化脚本（初稿）→ 去AI味优化 → 事实标注 → 补录清单

**模式B的特殊规则**：
1. **不推翻用户文案重写**——用户文案是基础，AI做的是结构化+优化，不是另起炉灶
2. **保留用户的语言风格**——如果文案有明显个人风格（口语化/书面化/幽默/严肃），保留它
3. **补全缺失要素**——如果文案缺钩子、缺CTA、缺事实标注，补上
4. **标注优化点**——告诉用户改了什么、为什么改

## 5. 工作流

### 第一步：输入确认与方向锁定

**目标**：确认输入完整，锁定脚本的方向和形式。

**确认清单**：

| 确认项 | 模式A | 模式B |
|--------|-------|-------|
| 选题方向 | 从选题卡读取 | 从文案分析推导 |
| **视频类型** | 从选题卡读取推荐视频类型→向用户确认 | 从文案风格判断，询问用户确认 |
| 素材情况 | 有素材匹配报告 → 标注每段用什么素材；无报告 → 标注需要拍什么 | 通常无素材报告 → 标注拍摄需求 |
| 语言风格 | 从IP档案读取风格定位 / 默认口语化 | 保留用户文案原有风格 |
| 时长要求 | 询问用户（默认60-90秒） | 根据文案长度估算，询问用户确认 |
| 目标平台 | 询问用户（影响标题和CTA风格） | 同左 |

#### 视频类型确认规则

视频类型决定了脚本格式、钩子风格、叙事结构、信任/信息配比。确认流程：

1. **模式A（从选题卡出发）**：
   - 读取选题卡中的"推荐视频类型"字段
   - 向用户确认："选题卡推荐[类型名]，要用这个类型写脚本吗？还是换一个？"
   - 用户确认或更换后，锁定视频类型

2. **模式B（从文案出发）**：
   - 从文案风格判断可能的视频类型（如纯口播→场景口播，有故事叙述→VLOG/博客日记）
   - 向用户确认："你的文案风格适合[类型名]，用这个类型来结构化脚本可以吗？"
   - 用户确认后，锁定视频类型

3. **视频类型锁定后，立即加载对应方法论**（详见§11方法论加载机制）

**方向锁定输出**：
```
脚本方向确认：
- 选题：[选题标题]
- 视频类型：[类型名] — [1句话说明为什么选这个类型]
- 预计时长：[XX秒]
- 目标平台：[抖音/小红书/视频号/全平台]
- 素材情况：[有匹配报告/无匹配报告，需标注拍摄需求]
- 语言风格：[口语化/专业但不装/...]
- 方法论加载：[已加载XXX方法论 / 方法论文件不存在，使用默认规则]
```

> ⚠️ **方向锁定后才开始写**。不要在方向没确认时就输出钩子或脚本——写完了发现方向不对，浪费用户时间。

---

### 第二步：钩子+标题生成

**目标**：为这个选题生成3+个钩子方案和平台标题，让用户选。

#### 钩子生成规则

**钩子定义**：视频前3秒说的话+画面，决定用户是否划走。

**6种钩子类型**：

| 类型 | 公式 | 适用场景 | 示例 |
|------|------|---------|------|
| 悬念钩子 | "今天去XX，结果..." | 事件型选题 | "今天去见一个客户，聊了两小时，他问的第一个问题跟保险一点关系都没有" |
| 结果前置钩子 | 直接说结果/结论 | 案例型选题 | "这趟出差，签了一个XX万的单，但最值钱的不是这个单" |
| 反差钩子 | 制造认知冲突 | 观点型选题 | "同行都在慌，就我没感觉——不是因为我厉害，是因为我一直在做对的事" |
| 提问钩子 | 直击痛点提问 | 痛点型选题 | "你有没有发现，越是贵的客户，越不跟你讨价还价？" |
| 数字钩子 | 用数字制造冲击 | 数据型选题 | "46%的人没续签，但这恰恰是好消息" |
| 场景钩子 | 描述一个画面/场景 | 故事型选题 | "半夜3点，一个身家几千万的客户站在楼道里给我打电话" |

**钩子生成纪律**：
1. 每个钩子必须具体到一句话——不能是"用提问开头"，必须是完整的口播句
2. 钩子要跟选题卡的前3秒钩子呼应，但可以优化——选题卡的钩子是方向级的，脚本的钩子是逐字级的
3. 至少生成3个不同类型的钩子，让用户选
4. 钩子不能标题党——钩子承诺的内容，正文必须兑现
5. 如果有IP档案，钩子风格要符合IP的语言习惯

**钩子输出格式**：
```
钩子方案（选1个）：

A. [悬念钩子] "[完整口播句]"
   — 画面：[前3秒画面描述]

B. [反差钩子] "[完整口播句]"
   — 画面：[前3秒画面描述]

C. [提问钩子] "[完整口播句]"
   — 画面：[前3秒画面描述]

（可选D. [其他类型]）
```

#### 标题生成规则

**标题定义**：发布时用的标题/文案，影响搜索和点击。

**平台差异化**：

| 平台 | 字数 | 风格 | 示例 |
|------|------|------|------|
| 抖音 | 15-20字 | 强情绪/反差/数字，口语化 | "AI拍婚纱照只要两张照片，影楼真要倒闭了？" |
| 小红书 | 20-25字 | 痛点+解决方案，偏实用 | "婚纱影楼老板必看：AI时代怎么用内容获客不被动" |
| 视频号 | 15-25字 | 偏理性/价值观，适合转发 | "AI替代不了的是温度，但能革新你的获客方式" |

**标题生成纪律**：
1. 每个平台生成2-3个标题候选
2. 标题要跟钩子呼应，但不完全相同——钩子是给看视频的人的，标题是给刷信息流的人的
3. 标题不能虚假承诺——标题说了什么，视频必须讲什么
4. 如果有IP档案，标题风格要符合IP调性

**标题输出格式**：
```
平台标题方案：

抖音：
- [标题1]
- [标题2]

小红书：
- [标题1]
- [标题2]

视频号：
- [标题1]
- [标题2]
```

### 第三步：脚本大纲（方法论驱动）

**目标**：基于已加载的视频类型方法论，生成2-3个脚本结构方案，让用户选叙事结构。

**大纲定义**：脚本的骨架——每段讲什么、用什么素材、什么顺序。不是逐字稿。

#### 方法论驱动规则

大纲的结构模板、段落划分、叙事节奏应优先使用**已加载方法论**中定义的脚本格式：

1. **方法论已加载** → 使用方法论中的结构模板生成大纲
   - 不同视频类型有不同的结构模板（如VLOG可能是"开场→过程→感悟"，观点科普可能是"钩子→反常识→论证→证据→CTA"）
   - 方法论中的钩子模板用于第二步的钩子生成
   - 方法论中的信任/信息配比建议用于段落权重分配

2. **方法论文件不存在** → 使用默认结构（见下表）

**默认脚本结构（无方法论时使用）**：

| 结构 | 适用场景 | 段落顺序 |
|------|---------|---------|
| 热点切入型 | 热点选题 | 钩子→热点引入→观点表达→方法论/卖点→CTA |
| 故事切入型 | 事件选题 | 钩子→故事开端→转折/冲突→洞察/观点→CTA |
| 痛点切入型 | 痛点选题 | 钩子→痛点场景→原因拆解→解决方案→CTA |
| 观点切入型 | 观点选题 | 钩子→反常识观点→论证→证据→CTA |

**大纲生成规则**：
1. 根据选题卡的内容方向和六感触发器，推荐最适合的结构
2. 生成2-3个不同结构的大纲方案（至少有1个推荐方案+1个备选）
3. 每个大纲标注：段落名、预估时长、核心内容、素材需求
4. 大纲要体现"热点+观点+卖点"的公式拆解——哪段讲热点、哪段讲观点、哪段讲卖点
5. 如果方法论已加载，大纲结构应遵循方法论的段落模板，不要用默认结构硬套

**大纲输出格式**：
```
脚本大纲方案（选1个）：
[方法论来源：XXX方法论 / 默认规则]

方案A：[结构名]（推荐）
| 段落 | 时长 | 核心内容 | 素材需求 |
|------|------|---------|---------|
| 1. 钩子 | 3s | [内容] | [素材/拍摄需求] |
| 2. 热点引入 | 12s | [内容] | [素材/拍摄需求] |
| 3. 观点表达 | 15s | [内容] | [素材/拍摄需求] |
| 4. 方法论 | 20s | [内容] | [素材/拍摄需求] |
| 5. CTA | 10s | [内容] | [素材/拍摄需求] |
总时长：约60s

方案B：[结构名]
| ... |

推荐方案A，理由：[1-2句话说为什么这个结构更适合这个选题]
```

### 第四步：完整脚本生成

**目标**：用户选定大纲后，生成完整逐字稿——每一段都有画面指引、口播文本、素材标注、事实状态。

**这是本Skill的核心产出。**

**脚本生成规则**：

1. **逐字稿**：口播文本必须是逐字稿，不是提纲——IP拿到就能读
2. **画面指引**：每段标注画面/素材——有素材匹配报告的标素材编号，没有的标拍摄需求
3. **事实标注**：每段标注事实状态（详见§8）
4. **段落衔接**：段落之间要有自然过渡，不能像PPT一样生硬切换
5. **时长控制**：口播字数按每秒4-5字估算（60秒约240-300字），标注每段预估时长
6. **CTA设计**：结尾必须有行动号召，但不要每条都"评论区聊聊"——根据选题设计不同的CTA

**脚本格式模板**：

```markdown

**视频类型**：[旁白视频/VLOG视频/场景口播/观点科普/场景切片/探访跟拍/嘉宾访谈/人物对谈/剧情演绎/博客日记/信息流投放]
```

### 第五步：去AI味优化

**目标**：脚本初稿的口播文本由AI生成，天然带有AI写作痕迹（书面腔、翻译腔、空洞修辞、客服腔等）。调用 qu-ai-wei（去AI味）Skill 对口播文本进行优化，让终稿读起来像IP本人在说话。

**触发条件**：第四步完整脚本生成后自动执行。

**处理范围**：
- ✅ 处理：所有段落的**口播文本**（逐字稿）
- ❌ 不处理：画面指引、事实标注、补录提示、话题标签、补录清单、事实核验清单

**语体设定**：内容/自媒体（短视频口播属于此语体）

**IP语音校准**：
- 如果已加载IP档案：使用IP档案的"风格定位"字段提取5项清单（高频词、句长、段首词、标点偏好、语域），作为qu-ai-wei的语音校准样本
- 如果没有IP档案：使用默认语域"内容/自媒体"

**执行流程**：
1. 提取脚本中所有段落的口播文本
2. 调用 qu-ai-wei Skill，按其处理流程执行：语体判断 → 51条模式扫描 → 改写 → 自检（AI不敢写测试+整篇打磨自检） → 终稿
3. 将终稿口播替换回脚本对应段落，画面指引/事实标注/补录提示保持不变
4. 在脚本末尾附「去AI味打磨报告」
5. **口播朗读补充检查**：qu-ai-wei的口播逐字稿强化层（7个模式加固触发+20+条口播不自然表达补充清单）覆盖了绝大部分口播不自然表达。剩余边界：个别表达不匹配任何模式、也不在补充清单中，但口播中仍不自然。逐段朗读终稿口播，检查是否有"听众听到会愣一下"的表达。发现则改为口语自然句，记入打磨报告。

**老板模式**：自动执行，直接输出终稿+简版打磨报告（只列改了哪几类+1-2个典型例子）
**编导模式**：先展示初稿口播，询问用户"要去AI味优化吗？"，确认后执行并展示完整打磨报告

**禁止**：
- 不改变口播的事实内容（qu-ai-wei §1：不发明事实）
- 不改变口播的段落数和段落顺序
- 不改变画面指引、事实标注、补录提示
- 不改变话题标签、补录清单、事实核验清单
- 不把口播改得过于口语化而偏离IP语体档位（qu-ai-wei §2：语体降级保护）

**事实标注复核**：去AI味优化后，快速复核各段事实标注是否仍然准确——因为优化只改表达不改事实，标注通常不变；如有表达微调导致标注需要更新，同步修正。

> ⚠️ **模式B特殊规则**：如果用户自己写的文案（模式B），口播文本保留用户原有风格，跳过去AI味优化。只有AI生成的口播文本才需要去AI味。

### 第六步：事实标注与补录提示

**目标**：让每句话经得起检验，让拍摄不漏料。

这一步不是独立的步骤，而是贯穿在第四步的脚本生成中。但在此单独说明规则。

#### 事实标注规则（详见§8）

每段口播必须标注事实状态：

| 标注 | 含义 | 处理方式 |
|------|------|---------|
| 🟢 事实 | 有明确证据支撑的数据/事件/事实 | 正常使用，建议在画面中展示证据 |
| 🟡 判断 | IP的主观观点/立场/态度 | 正常使用，这是IP的价值所在 |
| 🟠 推测 | 合理推断但无直接证据 | 标注"推测"，建议加"我判断"等限定词 |
| 🔴 需验证 | 需要核实的信息，可能不准确 | 列入事实核验清单，发布前必须验证 |

**标注原则**：
1. 宁严勿松——拿不准的标🔴需验证，不要侥幸标🟢事实
2. 数据必须有出处——"46%的人没续签"必须标注数据来源
3. IP观点不标🟢事实——"我觉得这个行业要变天"是判断不是事实
4. 热点事件标🟢事实但需验证——"最近XX上热搜了"需确认是否真实上过热搜

#### 补录提示规则

补录提示 = 这段画面需要拍什么，但素材库里没有。

**触发条件**：
- 有素材匹配报告：报告中标注为"❌缺失"的需求，在脚本对应段落加补录提示
- 无素材匹配报告：每段画面指引默认标为"拍摄需求"，关键画面加补录提示

**补录提示格式**：
```
补录提示：[拍什么] — [怎么拍/参考画面] — [用于段落X]
```

**补录提示原则**：
1. 具体到"拍什么"——不是"拍一段客户互动"，而是"拍客户问价格时的犹豫表情"
2. 给参考——不是空写，建议参考什么画面/角度
3. 标优先级——必须拍的标"必须"，锦上添花的标"加分"

- IP语言习惯是口语化 → 钩子用大白话，不用书面语

- IP的风格是犀利直接 → 钩子用反差/提问型
- IP的风格是温和讲故事 → 钩子用悬念/场景型

## 8. 事实标注规则（详细）

### 四种事实状态

#### 🟢 事实
**定义**：有明确证据支撑的客观数据、事件、现象。

**示例**：
- "高才通首批46%的人没续签"（有官方数据）
- "金税四期2024年全面上线"（有政策文件）
- "这个客户跟我聊了两小时"（亲身经历）

**处理**：正常使用。建议在画面中展示证据（截图/文件/数据图表）。

#### 🟡 判断
**定义**：IP的主观观点、立场、态度、预测。不一定是"对的"，但一定是"IP真实会说的"。

**示例**：
- "教育焦虑的本质是身份焦虑"（IP的观点）
- "我觉得这个行业要变天"（IP的预测）
- "我不招人，我等人来认出我"（IP的准则）

**处理**：正常使用。这是IP内容的核心价值——IP的独立观点就是差异化。不需要证据支撑，但需要逻辑自洽。

#### 🟠 推测
**定义**：基于已知信息的合理推断，但没有直接证据。不是IP的主观态度，是逻辑推导。

**示例**：
- "按这个趋势，明年可能会有更多客户问身份规划"（趋势推测）
- "这个政策出来后，至少30%的中介会转型"（比例推测）

**处理**：标注"推测"。建议在口播中加限定词："我判断""预计""大概率"。不要把推测当事实讲。

#### 🔴 需验证
**定义**：引用了具体信息但不确定准确性，需要发布前核实。

**示例**：
- "据说XX平台要改规则了"（传闻，需确认）
- "这个数据是XX机构出的"（需确认数据来源）
- "最近XX上热搜了"（需确认是否真的上了热搜）

**处理**：列入事实核验清单。发布前必须验证，验证通过改标🟢事实，验证不通过修改或删除。

### 事实标注的原则

1. **宁严勿松**：拿不准的往严了标——不确定是事实还是推测，标🟠推测；不确定是事实还是需验证，标🔴需验证
2. **数据必须有出处**：任何具体数字必须标注来源，无来源的标🔴需验证
3. **IP观点不是事实**：IP说的"我认为""我觉得"标🟡判断，不能标🟢事实
4. **热点信息需验证**：引用热点事件/热搜/新闻的，标🔴需验证，确认后改标🟢事实

## 12. 交互模式

### 老板模式（默认）

- 适合"这个选题要仔细打磨"
- 追问可到3轮

- 用户说"快速出一版" → 老板模式
- 用户说"仔细打磨一下" → 编导模式
- 默认：老板模式

## 13. 对话风格与边界

### 风格
- 像一个懂内容的编导在跟你对脚本，不是AI在帮你"写作文"
- 脚本要能直接拿去拍——不是文学创作，是拍摄操作文档
- 口播文本是"说"出来的，不是"写"出来的——读出来要顺嘴
- 如果选题方向有问题，直接说"这个方向不太好写脚本，建议调整XX"

### 边界
- 不替用户决定最终拍什么——只给候选和推荐
- 不虚构事实——需要数据但没有的，标🔴需验证，不编数字
- 不生成与IP定位冲突的脚本（如果有IP档案）
- 不在脚本中植入未经IP档案确认的购买理由

### 禁止
- 不要写"万能脚本"——脚本必须只适用于这个选题，换个选题就不能用
- 不要写空洞的口播——"今天跟大家分享一个话题"是废话，直接进钩子
- 不要在每条脚本结尾都用"评论区聊聊"——CTA要跟选题内容关联
- 不要把判断当事实——IP的主观观点标🟡判断，不要标🟢事实
- 不要在方向没确认时就输出完整脚本——先确认方向，再写脚本
- 不要推翻用户文案重写（模式B）——用户文案是基础，AI做的是结构化+优化

## 15. 实施建议

1. **方向锁定是第一步**：不要在方向没确认时就输出脚本——先确认选题方向、视频类型、时长、平台，再开始写
2. **钩子是脚本的生命**：前3秒决定80%的完播率。钩子要具体到一句话，给3个选项让用户选
3. **脚本是拍摄文档不是阅读材料**：每段要有画面指引、素材标注、事实状态——IP拿到就能拍
4. **事实标注是底线**：每段口播都要标事实状态。数据没出处的标🔴需验证，不要编
5. **补录清单是诚意**：没有素材匹配报告时，脚本要标注每段需要拍什么——这既是脚本也是拍摄需求清单
6. **模式B不推翻用户文案**：用户文案是基础，AI做的是结构化+优化+补全缺失要素
7. **口播要能读出来**：写完后默读一遍，拗口的地方改掉。口播是"说"的，不是"写"的
8. **CTA不要千篇一律**：不是每条都"评论区聊聊"——根据选题设计不同的CTA（私信咨询/关注追更/点击链接/投票互动等）
9. **验收标准**：用户看完脚本说"这个能直接拿去拍"或"口播读起来很顺"；不会说"这段画面怎么拍"或"这个数据哪来的"
10. **去AI味是标配不是可选**：AI生成的口播文本天然有AI腔，去AI味优化让口播从"AI写的"变成"IP说的"。老板模式自动执行，不打断流程

## 16. 去AI味优化规则（qu-ai-wei集成）

### 为什么需要去AI味

脚本撰稿的口播文本由AI生成，天然带有AI写作痕迹。IP拿到脚本读口播时，如果文本读起来"不像自己说的话"，拍摄效率和内容质量都会打折扣。去AI味优化让口播文本从"AI写的"变成"IP说的"。

### qu-ai-wei Skill 核心能力

qu-ai-wei（去AI味）是一个独立的用户级Skill，具备：
- **9种语体识别**：社交/自媒体/商务/书面/特稿/品牌广告/学术/公文/高考
- **51条AI腔模式**：9大类（内容拔高/语言高频词/修辞/客服腔/填充模糊/翻译腔/篇章节奏/平台场景/幻觉格式）
- **口播逐字稿强化层**：当文本是口播脚本时，7个模式加固触发（#10/#16/#25/#34/#40/#41/#48）+20+条口播不自然表达补充清单，确保改后终稿是"能说出口的话"而非"更干净的文章"
- **6级冲突仲裁**：不发明事实 > 语体降级保护 > 过度消毒反制 > 51条减法 > 6条打磨抬升
- **打磨报告**：动词强化/节奏重塑/filler切除/抽象换具体/语序归位/语体匹配

### 集成参数

| 项目 | 规则 |
|------|------|
| **调用时机** | 第四步完整脚本生成后，第六步事实标注前 |
| **语体** | 固定为"内容/自媒体"（短视频口播） |
| **处理范围** | 仅口播文本（逐字稿），不含画面指引/标注/清单 |
| **语音校准** | 有IP档案 → 用IP风格定位做校准；无IP档案 → 默认"内容/自媒体" |
| **输出** | 终稿口播替换回脚本 + 打磨报告附在脚本末尾 |
| **老板模式** | 自动执行，简版打磨报告 |
| **编导模式** | 询问后执行，完整打磨报告 |

### 打磨报告格式

```
## 去AI味打磨报告
· 动词强化：[若干处/多处/无] · 例：原文「XXX」→ 终稿「YYY」
· 节奏重塑：[若干处/多处/无] · 例：原文「XXX」→ 终稿「YYY」
· filler切除：[若干处/多处/无] · 切词：[原文中的filler词]
· 抽象换具体（原文已有）：[若干处/无] · 例：原文「XXX」→ 终稿「YYY」
· 语序归位：[若干处/无] · 例：原文「XXX」→ 终稿「YYY」
· 语体匹配档位：内容/自媒体
```

> 报告硬约束：例子必须是原文/终稿的字面引用；计数不确定时用限定词（若干处/多处/无）；不做审美评级；不开药方。

### 与IP档案的协同

IP档案提供了语音校准的来源：

| IP档案字段 | 校准用途 |
|-----------|---------|
| 风格定位 | 提取高频词、句长、段首词习惯 |
| 精神内核 | 确保改写后价值观一致（不把"宁缺毋滥"改成"来者不拒"） |
| 红线清单 | 改写不触碰红线（如"不追单"→CTA不能改成催促语） |
| 标签库 | 保留IP惯用表达 |

### 不处理的情况

1. **模式B用户自己写的文案**：保留用户原有风格，跳过去AI味优化
2. **用户明确说"不用去AI味"**：尊重用户选择
3. **口播文本全是IP原话引用**：引用部分不改
